# deploy/ —— 部署与配置清单

这个目录是**控制台与仓库之间的接口**。控制台 EXE 不写死任何配置项，它部署完成后读取
`console-config.json`，按里面的声明生成界面；改这个文件就能增减配置项，**不用重新打包 EXE**。

## 文件

| 文件 | 作用 | 是否入库 |
|---|---|---|
| `console-config.json` | 配置项清单（控制台界面由它生成） | 是 |
| `robot.env.example` | 运行配置模板，部署时复制成 `robot.env` | 是 |
| `robot.env` | 真实运行配置（可能含密钥） | **否**，已被 `.gitignore` 忽略 |

## 配置项字段

```json
{
  "key": "DSH_WEB_MOD",            // 环境变量名，必须是大写字母/数字/下划线
  "label": "出口审核",              // 界面上显示的名字
  "group": "联网与审核",            // 分组标题，同名自动归到一栏
  "type": "bool",                  // bool / int / float / str / enum
  "min": 3, "max": 60, "step": 1,  // 数值范围，越界直接报错，不做静默钳制
  "options": ["a", "b"],           // 仅 enum 使用
  "default": "1",                  // 服务器上没设时界面显示的值
  "secret": false,                 // true＝界面只显示「已设置/未设置」，永不回显真实值
  "restart_required": true,        // true＝改完需要重建容器
  "hint": "先审后发，防止违规内容发到群里"
}
```

规则：

- `type` 认不出的配置项会被**跳过而不是报错**，所以以后加新控件不会让旧 EXE 崩。
- `bool` 写入时统一写成 `1`/`0`。很多插件用 `!= "0"` 判断，写 `false` 会被当成「开」。
- 数值必须给 `min`/`max`：填了非数字会让插件 import 失败，等于整个插件加载不了。
- 标了 `secret: true` 的项（如搜索接口密钥）真实值只留在服务器，控制台永远读不到。
- 配置写回是**行级编辑**：保留注释、空行和顺序，只动改动的那一行。

## 怎么加一个配置项

1. 在插件代码里用 `os.environ.get("DSH_XXX", "默认值")` 读取。
2. 在 `console-config.json` 的 `knobs` 里加一条声明。
3. 在 `robot.env.example` 里补上同名默认值（保持模板和清单一致）。
4. 提交后，控制台点「刷新配置」就能看到新项，不需要重新发布 EXE。

## 不要放进去的东西

- 真实服务器地址、域名、IP、群号、QQ 号
- 密码、Token、API Key、私钥、证书
- 任何生产环境的完整路径

模板里一律用占位符，真实值由使用者在自己的服务器上填写。
