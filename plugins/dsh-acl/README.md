# 群权限目录 · 第 10 版（2026-09-14）

dsh-acl 2.0.0。指令按 **QQ 号**（不是昵称）分三档：`owner` / `admin` / `所有人`。

本版核心变化：**目录不再靠人工登记，改成启动时扫描实际装了什么**。

---

## 一、这一版改了什么

### 1.1 老问题：手工表会漏登记

1.1.0 的目录是两张写死的手工表（`OWNER_CMDS` / `ADMIN_CMDS`），加一条新指令就得记着回来补一行。
实际上没补上过——用户报「权限指令不是最新的」就是这个：

```
装了新插件 → 指令能用了，但 /权限 列不出来
→ 群主看不到自己有什么，群友也不知道边界在哪
```

2026-09-10 补登记过一批（`关系状态` `关系标签` `欲望状态` `自主状态` `利益状态` `利益模式`
`利益账本` `自我认知状态` `我和鱼` `社交退出`），但补登记这个动作本身还是会再漏。

### 1.2 新做法：AST 扫描 + 手工表只管分档

启动时扫 `/AstrBot/data/plugins` 和 `/AstrBot/astrbot/builtin_stars` 下所有 `.py`，
用 AST 找 `@filter.command("xxx")` 装饰器，取出指令名。

```python
_scan_installed_commands()   # AST 扫描，得到实际装了什么
INSTALLED_CMDS -= {"name", "provider", "dashboard_update"}
KNOWN_CMDS = INSTALLED_CMDS or (OWNER_CMDS | ADMIN_CMDS | PUBLIC_CMDS)
```

职责就此分开：

| 谁 | 管什么 |
|---|---|
| AST 扫描 | **有哪些指令**（自动，新装插件即出现） |
| 手工表 | **每条属于哪一档**（人来判，因为「后果由谁承担」机器判不了） |

没被手工表登记的指令，默认落到「所有人」档 —— 与 1.1.0 的语义一致，不改变任何已有权限。

扫描失败（路径不对、语法错误）时退回静态表，**绝不让 `/权限` 变成空目录**。

### 1.3 三条 WebUI 指令被剔除

`name` / `provider` / `dashboard_update` 是 AstrBot 原生 WebUI 的管理员指令，
受 WebUI 账号体系限制，**QQ 群身份无论如何都过不了**。留在目录里等于骗群主「你能用」，
所以显式剔除。

**`/忘记我` 刻意不设限**：这是群友对自己数据的退出权。锁成 owner 等于「你的资料只有群主能删」，
比不设限更糟。`/我的档案` `/记住` `/记住我` 同理，作用域都只有自己。

**`/画图` `/说话` `/搜` `/看网页` `/b站` 也给所有人**：这五条都有**自然语言路径**
（直接说「画个猫」「用语音说」走 LLM 工具和 `on_llm_response` 兜底钩子，不经过指令系统），
锁指令挡不住任何东西，只会制造「明路关了、暗路还开着」的假象。

### 2.4 清单外的 10 条

这 10 条实际装在机器上、但没被手工表登记，按默认语义落进「所有人」档：

```

```

它们都是**只读观测**，且作用域是机器人自己的内在状态，给所有人看不构成越权 —— 保持默认即可。
本版把清单写出来，是为了让「默认」是一个**被确认过的决定**，而不是「忘了登记」。

## 三、分档原则

只有一条：**这条指令的后果由谁承担**。

| 后果落在 | 档 |
|---|---|
| 全群（共享会话、全群记忆、整群策略、花钱） | owner |
| 只有运维信息（暴露地址/模型/配额） | admin |
| 只有自己 | 所有人 |

---

## 四、指令级 ACL 挡不住什么（务必知道）

`/画图` `/说话` `/做视频` `/搜` `/看网页` `/b站` 六条都有自然语言路径：

```
群友：「画个猫娘」「用语音说」「做个动画」
→ 走 LLM 函数工具 或 各插件的 on_llm_response 兜底钩子
→ 完全不经过指令系统，门卫看不见
```

所以把它们设成 owner **只是关掉了明路，省不了钱**。真要限制花钱的能力，
得在 `dsh-imagegen` / `dsh-voice` / `dsh-video` 内部按 `sender_id` 再判一次。
默认策略据此把这几条留给所有人 —— 半拉子限制比不限制更让人困惑。

同理，跨群的 `/画图` `/b站` 等指令 ACL 本来就管不了太多，真正的边界在插件内部。

## 五、匹配规则必须和框架逐字一致

框架 `CommandFilter` 的判定（`command.py:199-204`）：

```python
message_str = re.sub(r"\s+", " ", event.get_message_str().strip())
命中 = message_str == cmd 或 message_str.startswith(cmd + " ")
```

两个关键点：

1. `message_str` 在 `waking_check` 里**已经剥掉了前缀 `/`**，也剥掉了第一个 @机器人。
   所以 `/记忆状态` 和 `@机器人 记忆状态` 到门卫手里都是 `记忆状态`，一套规则覆盖两种发法。
2. **那个空格是刚需**：靠它区分 `记住我`（指令 记住我）和 `记住 我喜欢篮球`（指令 记住 + 参数）。
   少了空格约束，`记住我` 会被 `记住` 抢走。

还必须检查 `is_at_or_wake_command`，否则群友闲聊里说一句「我的档案」（没带斜杠、没 @），
本来根本不触发指令，却会被门卫拦下回一句「这条只有群主能用」—— 凭空制造噪音。

## 六、配置

`imagegen.env`（或对应插件的 env 文件）：

```
DSH_ACL=1                     # 总开关
DSH_ACL_OWNER=2774000001      # 群主 QQ，可逗号分隔多个
DSH_ACL_SCOPE=both            # group / private / both
DSH_ACL_QUIET=0               # 1 = 拦下时不出声
DSH_ACL_COOLDOWN=30           # 同一人拒绝提示的冷却秒数
```

追加旋钮（改分档不用改代码）：

```
DSH_ACL_OWNER_CMDS=xxx,yyy    # 追加 owner 级
DSH_ACL_ADMIN_CMDS=xxx        # 追加 admin 级
DSH_ACL_ALL_CMDS=记忆状态      # 降级为所有人可用（优先级最高）
```

改 env 后必须 `docker compose up -d astrbot`（`restart` 不重读 `env_file`）；
只改插件代码用 `docker restart astrbot`。

## 八、失败模式

判定过程整段包在 `try` 里，异常时 **fail-open**：不停事件，指令照常执行。

把人锁在门外比放进来更糟。日志里会有 `[acl] 判定失败，本次放行`。

目录扫描是另一套兜底：扫描异常时退回静态表，保证 `/权限` 永远不为空。
