# 大肥鱼人格驱动核心第一阶段

## 目标

把现有 agency、proactive、followup、memory、selfaware 和 dynamics 的信号统一成一个可回放的决策层。第一阶段不直接发送 QQ 消息，默认作为影子协调器使用，先观察“为什么应该说/为什么应该沉默”。

## 新模块

`plugins/dsh-persona-core/persona_logic.py` 提供无 AstrBot 依赖的纯函数：

- `TurnContext`：统一一轮消息的身份、指向、任务、安全、兴趣、情绪、关系和上下文信号。
- `PersonaState`：心情、精力、好奇、烦躁、孤独、自信，带半衰期自然衰减。
- `RelationState`：熟悉度、信任、亲近、玩笑容忍度，变化幅度受限并随时间衰减。
- `motives()`：帮助、续聊、社交、兴趣、关系维护、观察、退场动机排序。
- `choose_action()`：每轮只选择一个行为候选。
- `should_wake()`：可选主动行为的最终门控；明确任务和安全问题绕过可选阈值。

## 联动约定

适配器应把现有插件结果填入 `TurnContext`，由核心返回一个 `Action`。插件不得各自直接抢发同一轮消息。建议优先级为：安全/权限与明确任务、被@回复、续聊、关系维护、兴趣插话、主动开场。

第一阶段 `dsh-persona-core` 不修改生产配置，不接管现有消息出口，不影响多模态 provider。接入生产前应先用真实日志回放至少观察一轮，并验证主动行为冷却、社交少打扰边界、消息去重和 TurnClaim。

## 硬边界

- 情绪、关系和逆反不能阻断明确能力任务。
- 安全、权限和事实路径不能被人格偏好改写。
- 对无关且未点名的新话题默认不抢话。
- 关系只影响语气、主动性和信任，不影响安全结论。
- 状态输入损坏时回退到基线，不能让插件异常阻断正常回复。

## 行动层（v3，已接入生产）

第一阶段核心只产出候选，真正“开不开口”由行动层记账，避免同一个人被反复追问，也避免刚被要求少打扰还继续探头。

- `plugins/dsh_action.py`（`ActionStore`，SQLite `/AstrBot/data/dsh_action.db`）按群保存窗口、队列与开话次数：
  - `consider()` 决定是否给出候选，拒绝原因有 `duplicate | boundary | pending | no_opportunity | insufficient_context | density | cooldown | withdraw | burst | quota`。
  - `sent()` 只在消息真的发出去后计数；`release()` 用于发送失败或本轮被打断。
  - `revoke(gid, uid)` 撤销某用户的待发候选与追踪窗口。
  - 判定“被无视”要求窗口期内群里**有新活动**（≥3 条新流量）；单纯冷场不算拒绝。
- `plugins/dsh-persona-core/action_logic.py`：`MicroMotive`、`Participation`、`add_motive`、`open_participation`、`participation_allows`、`record_outcome`、`wake_score`、`should_withdraw`。
- `plugins/dsh-proactive/main.py`：接上 `ActionStore`，并在 `social_allows_proactive()` 为假时调用 `revoke()`，保证“撤回/少打扰”后不再对被撤回的人探头。

行动层只影响“说不说、跟谁说”，不改事实、安全和权限路径。

## 测试

在支持 Python 3.10+ 的环境运行：

```text
python3 plugins/dsh-persona-core/test_persona_logic.py
python3 plugins/dsh-proactive/test_proactive.py
python3 plugins/test_action.py
```

当前模块只使用标准库，可在 AstrBot 容器的 Python 3.12 中直接回放。
