# 2026-09-10 整体体检与隐藏 Bug 修复

## 结论

本轮对生产部署的容器、AstrBot 日志、插件管道、视觉调用、数据库、临时目录和 QQ 出口链做了完整检查。已部署并验证的改动如下。

1. 修复 `/表情包` 的结果链类型错误：`event.chain_result()` 必须接收组件 `list`，不能传 `MessageChain`。错误会让 `dsh-mention`、`dsh-sticker` 和框架结果装饰阶段连续崩溃，最终图片不发送。
2. `dsh-mention` 与 `dsh-sticker` 增加嵌套 `MessageChain` 拆平保护。即使将来其他插件再次误用，也不会拖垮整条发送管道。
3. `dsh-vischain` 将智谱 `1210`（图片格式/解析）和 `1301/contentFilter` 判为图片级永久错误：不在同一档白等重试，直接换档，但不拉黑整个 provider。
4. 禁止视觉链条的嵌套重试放大。框架 provider 单次请求默认还会重试 5 次，外层链条再重试会放大到最多 10 次/档；现在底层固定一次，由链条统一控制重试。
5. 修复 AstrBot 内置主动回复的 `GeneratorExit` 假错误。下游 `stop_event()` 关闭异步生成器属于正常控制流，原版 `except BaseException` 会把它记成空的“主动回复失败”。补丁对 `GeneratorExit` 立即重新抛出，真实异常仍按原逻辑记录。
6. 图片上下文总预算从 15 秒提高到 24 秒，覆盖 10 秒视觉请求的一次链条重试及取图/缩图余量；未改视觉 provider、模型、链条或默认图片描述 provider。
7. 清理超过 6 小时的 AstrBot 临时文件，目录由约 200 MB 降到 33 MB。

## 持久化补丁

`patches/builtin_astrbot_main.py` 是 AstrBot v4.27.4 内置 star 的完整文件副本，只在主动回复的 `yield event.request_llm(...)` 后增加：

```python
except GeneratorExit:
    raise
```

生产 Compose 通过只读 bind mount 覆盖：

```yaml
- ./patches/builtin_astrbot_main.py:/AstrBot/astrbot/builtin_stars/astrbot/main.py:ro
```

这样容器重建后补丁仍在。升级 AstrBot 镜像时，应先与新版本原文件比较；如果上游已修复，应移除此覆盖，而不是继续挂旧文件。

## QQ 出口代理现状

广州反向 SOCKS 当前没有监听 `127.0.0.1:11080`，宿主也没有对应的持续 SSH 会话；历史连接留下过 `CLOSE-WAIT`。因此不是本机 redsocks 或 iptables 配置错误，而是广州对端没有保持 `ssh -R` 反向转发。守卫已正确 fail-open：透明代理规则未启用，容器暂时从美国直连出口访问。

恢复方式是让广州对端重新建立并持续保活反向 SOCKS；守卫连续两次探活通过且出口确认为广州 IP 后，会自动重新挂代理规则。对端离线时不应强行开启本地规则，否则 NapCat 与 AstrBot 出网会黑洞。
