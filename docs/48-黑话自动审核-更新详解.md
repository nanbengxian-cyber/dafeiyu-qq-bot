# 黑话自动审核 —— 更新详解（2026-09-07）

对应插件 `dsh-slang` v1.1.0（上一版 v1.0.0 已于当日凌晨上线，本次在其上新增自动审核并修复隐患）。

## 新增了什么

- **自动审核**：不再依赖群主逐条确认候选。插件内置定时循环，每 8 小时把「创建超过 1 小时」的候选打包给 LLM 审：`通过 / 拒绝 / 再等等`。
  - 通过：必须是真网络用语/群内梗，且审核必须同时给出释义，否则按再等等处理（空释义不注入）；
  - 拒绝：泛词、人名、命令词、敏感内容；
  - 再等等：证据不足；连续 3 次再等等自动转拒绝，避免无限重审。
- **正式注入**：影子模式关闭（`DSH_SLANG_SHADOW=0`），确认词条在 `on_llm_request` 注入 `<group_slang>` 块帮模型听懂。
- **新命令**（群主）：`/黑话学习状态` 现显示上次审核时间与最近自动决策记录。
- 配置旋钮：`DSH_SLANG_AUTO` / `AUTO_INTERVAL`(8h) / `AUTO_MIN_AGE`(1h) / `AUTO_MAX_DEFER`(3) / `AUTO_BATCH`(20)。

## 修复了什么

1. **重启冲库**：重启后词库未加载就先提取，会把历史词库整体覆写清空 —— 现在提取/审核前强制加载状态文件。
2. **命令词污染语料**：AstrBot 的唤醒检查会剥掉 `/` 前缀，`startswith("/")` 拦不住命令，管理命令被学成黑话（词库里真出现过「黑话学习状态」）—— 改为按命令词本身拦截。
3. **幻觉候选入库**：提取模型可能输出语料里根本不存在的词 —— 候选必须能在取样语料中找到原文，否则硬拦截。
4. **审核循环静默死掉**：`ensure_future` 的任务对象被丢弃后被 GC 回收，循环无声停止 —— 持有全局强引用 + 启动打日志。
5. **`__init__` 隐藏 bug**：模块级函数被写成 `self.xxx` 调用，插件曾 Failed to load（测试绕过构造函数没暴露）—— 新增走真构造函数的回归测试。

## 优化了什么

- **注入预算**：`BUDGET=300`，超预算先退化成只给释义、再裁低次数词条、单条超长则截断，保证不挤爆上下文。
- **同轮候选去重**：LLM 一次输出里的重复词不重复计数。
- **落盘收紧**：状态文件权限 0600（含群聊原文）。
- **定时循环先检查再睡**：重启后若已到点立即补审，不用干等一个周期。

## 实测

16 项纯函数单测全过（本地 + 容器内）；线上首批真实审核：审 5 条 → 通过 1（半个省略号）/ 拒绝 2（好可爱、坏蛋）/ 再等等 2（柔柔、小小柔）。
