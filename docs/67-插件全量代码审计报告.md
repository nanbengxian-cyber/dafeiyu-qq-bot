# AstrBot 插件全量代码审计报告

## 1. 结论与范围

本轮检查 `/home/ubuntu/workspace/dafeiyu-qq-bot-audit` 中约 55 个 AstrBot 插件、约 4.3 万行 Python，并与生产最近 20,000 行日志交叉核对。结论：未发现高置信 P0；确认 13 项 P1、24 项 P2，另有若干工程性 P3。当前已在镜像修复 5 个插件族中的高价值问题，但没有部署、重启或推送。

生产日志基线：6 个 traceback、13 个 `TimeoutError`、4 个 `ModuleNotFoundError`。`dsh-poke/poke_logic.py` 当前存在，历史导入失败更符合非原子部署或热重载窗口；vischain 历史“平均浪费 16.4 秒”为解析误差，修正约 5.9 秒，但 timeout/429 重试放大确实存在。

## 2. P1 问题

1. **dsh-pay 错误确认到账** — `plugins/dsh-pay/pay_logic.py:42-46,80-83,151-170`，接线 `plugins/dsh-pay/main.py:203-206,239-257`。待确认时群主说“还没到账、到账了吗、到账失败、讨论到账逻辑”会因“到账”子串推进状态并公开误报。最小修复：肯定式短句 fullmatch，并排除否定、疑问、条件及元讨论。测试：所有反例不改状态，明确“钱到账了/已收到赞助”才成立。**本轮已修复。**
2. **dsh-merge 绕过统一出口安全链** — `plugins/dsh-merge/main.py:191-198,207-221`。艾特风暴 flush 独立生成后直接 `send_message()`，标准 `on_llm_response/on_decorating_result` URL、泄漏和行为闸不可见。修复：回到标准 result 管线或调用唯一强制出口审核 API；测试敏感 URL、人格泄漏、挑衅输出和审核超时 fail-closed。
3. **dsh-video 无界下载及失败残留** — `plugins/dsh-video/main.py:1035-1054,1343-1359`。超大、慢速、断流或错误响应可写满磁盘，后续整文件/base64 可 OOM。修复：流式硬上限、媒体类型校验、临时文件、成功原子改名、失败统一 unlink；测试伪长度、chunked 超限、中断、非 200、小文件和边界 MP4。
4. **dsh-video 热重载遗留生成任务** — `plugins/dsh-video/main.py:457-458,1137-1141,1267-1269,1477-1479,1501-1503`。3–5 分钟生成期间卸载后旧实例继续轮询、计费和发送。修复：实例任务集，`terminate()` cancel+gather，清理在途状态；测试提交、轮询、下载、发送各阶段卸载。
5. **dsh-homophone 干净部署静默失效** — `plugins/dsh-homophone/main.py:40,43-54,83-88,113-131`。依赖的 `homophone_data.json` 未跟踪，异常被吞后空词库仍显示加载成功。修复：提交有效词库，启用时对缺失、损坏和 schema 错误 fail-fast；测试干净 checkout 和坏词库。

7. **dsh-armor 动态破甲状态跨群污染** — `plugins/dsh-armor/main.py:111-128`、`plugins/dsh-armor/armor_logic.py:102-155`。修复：按 `(gid, phrase)` 分区并贯穿观察、降级、清理和查询；测试跨群及重载隔离。

## 3. P2 问题

- **任务生命周期/取消**：`dsh-merge:395-429` 卸载不取消且吞取消；`dsh-listen:336-385` 热重载遗留转写；`dsh-fwd:841-849` ffmpeg 超时不 terminate/kill/wait；`dsh-initiate` 取消不 await 且 `BaseException` 吞取消；`dsh-poke` 热部署窗口可出现旧新任务并存。统一修复为实例任务集、`terminate()` cancel+gather、`CancelledError` 传播、子进程最终回收。
- **无界资源**：`dsh-merge:71-80,371-423` 窗口可无限续期且 O(n²) 去重；`dsh-voice:880-915` TTS body 整块无上限；`dsh-voice:956-1077` 合成文件发送后不立即删除。应加条数/字节/硬截止、流式上限、owned path finally 清理。
- **跨群/跨用户污染**：`dsh-slang:99,161-164,429-460,658-664,907-935,1021-1034` 多群共用词库证据；`dsh-interest:216-229,287-352` 热度跨群/私聊；`dsh-selfworth` recent evidence 仅按群；`dsh-desire` 全局 freshness/state；`dsh-proactive` 去重键不含完整群维度。状态键必须含 gid，涉及个人证据再含 uid。
- **并发 TOCTOU**：`dsh-scene:330-373` 冷缓存击穿；`dsh-slang:689-779,1036-1096` 在途自动审核覆盖后到人工决定；`dsh-proactive`、`dsh-poke` 冷却/配额并发突破；`dsh-clarify` 同一消息并发分类。采用 per-key lock/singleflight、锁内二次检查、revision CAS。
- **白名单/退出 fail-open**：`dsh-noise:156-185` 私聊也变换；`dsh-slang:71-74,641-664,855-874` 空组收集全部群；`dsh-social:278-308,406-418` owner 标签撤销用户 opt-out；`dsh-selfaware` owner 为空时命令 fail-open。应严格限定消息类型/群集合，并让退出只能由本人显式撤销。
- **安全与隐私**：`dsh-sticker:140-151,368-387,447-462` 标签目录穿越/symlink；`dsh-effect:149-150,348-352,431-438` SQLite/WAL/SHM 默认 0644；`dsh-fatigue:73-76,187-214` 状态文件 0644；`dsh-selfaware` 非可信自由文本进入高优先级自事实 prompt；`dsh-selfworth` 原文可闭合 prompt 标签。采用 realpath/commonpath、0600、结构化转义/边界。
- **解析与内容安全**：`dsh-decide:470-475,835-885` 字符串 `"false"` 被 `bool()` 转真；`dsh-leakguard:121-135,327-343` 重复 strong 标题只删第一个；`dsh-aiflavour:63-77,195-235` WEAK 可动态升级后被剥除；`dsh-imagegen:961-1015,1138-1158` 确定发送失败仍占完成标志/冷却。均需严格 schema、循环清除后复扫、WEAK 优先、明确发送结果回滚。
- **持久化正确性**：`dsh-slang:695-779` 全部本地硬拒时不落盘；`dsh-joinguard:60,131-175` 拒绝缓存仅从最近 12 条日志恢复；`dsh-joinguard:147,173-175,239-243,336-338` 拒绝键未含 gid；`dsh-interest:132-193,316-339` 同 message_id 可重复计热；`dsh-followup` 缺消息 ID 去重；`dsh-desire` SelfAware cursor 在 durable processing 前确认导致崩溃丢遥测。
- **异步阻塞**：`dsh-listen:94-122,190-202` 同步 ffmpeg 可卡事件循环 120 秒；memory/desire/agency/selfaware/emotion/selfworth 等多处 async hook 内同步 SQLite/文件 I/O。应迁移 async subprocess、`to_thread` 或后台批处理，并明确数据库连接所有权。
- **dsh-memory**：已确认 opt-out 后已认领抽取仍可复活事实、to_thread 取消/close 竞态、`_put_fact()` 提前返回导致半事务泄漏。该文件已有其他工作流改动，本轮未触碰，后续需独立事务化修复。
- **dsh-selfguard**：final-only hook 无法阻止已发出的 streaming token，替换后后续 decorator 仍可修改，async hook 同步 SQLite。需要前移到统一发送前闸或禁用流式直发。

## 4. P3 / 工程问题

- 七个连字符插件 metadata 名称可能不通过 AstrBot 标准安装器的 `isidentifier()` 检查，尽管当前手工目录能加载；应统一标识符并保留显示名。
- `dsh-followup` 测试在相对导入失败后可跳过整段仍打印 `ALL PASS`；应将 skip 变为失败或明确 skip 计数。
- 多插件仍捕获 `BaseException`，会吞 `CancelledError`；规则应统一为单独传播取消、业务异常仅捕获 `Exception`。
- 部署应采用临时目录完整同步、依赖/语法验证后原子切换，避免 `dsh-poke` 类 `ModuleNotFoundError` 热窗口。

## 5. 本轮镜像修复

- `dsh-guard`：修复第三人称辱骂误罚、mention 目标识别、ASCII 边界误判；严格 bool schema；身份未知不处罚；同群配额加锁预留；明确失败回滚，超时/取消保守保留，取消传播。
- `dsh-vischain`：永久失败只按独立逻辑请求累计；timeout、429、1210/1301/contentfilter 不永久拉黑；昂贵失败立即换 provider；图片归一化补试也受单次 timeout 约束。
- `dsh-web`：恢复 TLS 验证；短链/页面逐跳手动重定向复验；仅 `ip.is_global` 放行；连接器实际解析结果再次校验并固定到已验证 IP，关闭 DNS 缓存，保留原 Host/SNI/证书校验；严格审核 JSON；完整内容 SHA-256 缓存键；完整待发送文本送审；所有 B 站出口改为模型 fail-closed；取消传播。
- `dsh-pay`：到账确认改为明确短句 fullmatch，否定、疑问、条件、元讨论、裸“确认/已确认”不推进状态机。
- `dsh-ctxclean`：截断时保留持久 system/developer 前缀，从 user 边界保留最近 N 轮且不造孤儿 tool。
