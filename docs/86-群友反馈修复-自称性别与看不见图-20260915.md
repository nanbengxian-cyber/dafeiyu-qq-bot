## 二、修复 1：自称与性别一致性（dsh-factguard）

### 根因

不是「模型不听话」，是**它手里根本没有自身事实卡**。

`dsh-factguard` 只在 `_TRIGGER_RE` 命中时注入事实卡，而那个正则要求
「自称词 + 10 字内出现自身属性词」。当天真实出现的这些句子一条都没命中：

```
妈妈              （@ 之后只剩下正文「妈妈」）
小鱼弟
你是GG还是MM啊
咋肥鱼把自己当男的了   （@ 的是群主，不是机器人）
```

于是 19:10–19:45 整段「自称漂移」期间，日志里**一次 `[factguard]` 都没有**
（只有 persona-core / agency 的行）。模型在没有事实卡的情况下自由发挥，才说出
「叫我鱼哥就行」「叫爸爸也没用」「我本来就没性别」。

还有一条助推：旧 `aliases` 写的是「鱼哥/肥鱼**可以应**」——这句话被读成
「我是鱼哥」。

### 改法

`plugins/dsh-factguard/main.py`：

1. `_DEFAULT_FACTS` 新增 `self_address`，`aliases` 改写成「那是群友的叫法，
   **不是自称**」，去掉「可以应」。
2. `build_inject()` 新增两行硬规则：
   - `自称：…不要自称「鱼哥」「鱼弟」「哥」「小弟」「爸」，也不要说自己「没性别」`
   - `性别口径：自己是女的。被叫「哥」「弟」「小鱼弟」「兄弟」「男鱼」…就用一句
     短话平静纠正（例如「我是女的啊」），不吵架、不反复强调；**绝不说「我没有
     性别」**。群友喊「妈妈」「老婆」是玩梗，不承认也不翻脸，更不要用「叫爸爸也
     没用」「妈什么妈」这类话顶回去 —— 那句本身就是把它说成男的。`
3. 新增 `_ROLE_RE` / `_NAME_RE` / `_addressed()` / `_triggered()`：**被点名**
   （`event.is_at_or_wake_command`）或**被叫名字**时，句子里出现亲属/性别称呼就
   注入事实卡。

`_ROLE_RE` 刻意**不收裸「妈」「爸」「哥」「弟」**：实测「别让外国人以为我们吃
不起**老干妈**」会被裸「妈」误命中（14:54:57 那条就是这么中招的）。群友真要喊
亲属称呼时都写双字「妈妈」「爸爸」，收双字足够。

### 触发面实测（用当天 600 条真实群友消息回放）

```
旧触发 7 条 / 新触发 38 条（1.2% → 6.3%），净增样本全部是「妈妈」「臭妈妈坏妈妈」
「你是GG还是MM啊」这类真·该注入的句子，没有一条误伤。
```

事实卡长度 863 字。

### 生产事实表同步

`/AstrBot/data/plugins/dsh-factguard/self-facts.json` 会**覆盖**默认值，所以
`aliases` 必须同步改，否则改了代码也没用。已改，并保留群主原来的
`note: 被问年龄：报生日（2023-11-02）让人自己算，不编具体数字`。
备份：`/opt/qqbot/backups/dsh-group-feedback-20260915-122222/self-facts.json`。

## 三、修复 2：问了图却说看不见（dsh-imgctx）

### 根因

`LOOKBACK = 4`，太小。

时间线：群友 **11:57:32 发图** → **12:00:24 才 @ 它问「图片里面的内容是什么
意思」**，中间隔了 6 条消息。`_pick_images()` 只看 `messages[-4:]`，够不着那
张图 → 没有 caption → 日志里连一行 `[imgctx]` 都没有 → 下游 `dsh-clarify` 只
能看到「图片内容未知」，于是反问「图片里是什么意思？」，机器人再把这句话发给
群友 —— 群友问的本来就是这件事。

图并没过期：`MAX_AGE = 300s`，11:57:32 那张在 12:00:24 时是 172 秒。

### 改法（`plugins/dsh-imgctx/main.py`）

1. 新增 `ASK_LOOKBACK`（默认 12，env `DSH_IMGCTX_ASK_LOOKBACK`）。
   `_turn_asks_about_image(req)` 为真时，取历史条数与 `_pick_images` 的
   回看条数都放宽到 `max(LOOKBACK, ASK_LOOKBACK)`；不说图时**行为完全不变**。
2. `_pick_images()` 新增 `lookback` 参数（默认 `None` → 用 `LOOKBACK`，保持旧行为）。
3. 新增兜底：**在说图但回看到底也没捞到**（图太老/rkey 过期/被撤）时，注入
   「就按现有信息正常接话…**不要说自己看不见图／没有看图能力，也不要解释图片
   是怎么到你这儿的**」。直接掐掉「真看不见 图没递到我这边」这类内部机制自述。
4. `/图片上下文` 的状态行补上放宽值。

## 四、部署方式上的一个坑（重要）

**生产 imgctx 比镜像旧。** 镜像 HEAD 里有一份已经提交、但**从未上线**的 SSRF
加固重构（`_is_public_ip` / `_PublicResolver` / `MAX_REDIRECTS` /
`_INFLIGHT_OWNERS`，线上文件里 0 处出现）。直接 `cp` 整个 `main.py` 会顺手把
那份重构推上线，那不是这次要改的东西。

所以这次用的是**按字面锚点打补丁**：
`patches/patch_prod_imgctx.py <线上版> <输出>` → 7 处补丁 → 只改本次要改的行，
线上其余代码原样不动。打完与镜像 diff，残余差异**全是**那份 SSRF 重构。

> 待办（不在本次范围）：镜像与生产对 imgctx 已经分叉，要么把 SSRF 重构补上线，
> 要么从镜像撤回。现在这种状态下次容易踩。

## 七、部署当晚的掉线事件（不要误认成这次改动引起的）

20:31 部署完第二次重启后，NapCat 停在扫码页。查清了，**和这次改动无关**：

```
20:31:12 [napcat] 大肥鱼2号 | [KickedOffLine] 你的账号当前登录已失效，请重新登录
20:31:19 [watchdog] online -> offline（探针 get_status online=false）
20:31:32 [watchdog] 二维码过期，重启 napcat 重新出码
20:31:48 [napcat] 正在快速登录 100000003 -> 快速登录错误：登录态已失效
```

QQ **先**在 20:31:12 把账号踢了，守护脚本 7 秒后才探到、30 秒后才重启 napcat。
而且同样的 `探针 get_status online=false` 掉线，今天在**没有任何人操作**的
08:32、09:30、10:33 各发生过一次 —— 这正是 `qq_watchdog.sh` 开头写明的那件事：
「账号 100000003 被 QQ 风控盯得很紧，每 20~60 分钟就掉线一次」。

作为对照：12:22 那次重启 astrbot 只让守护脚本报了 21 秒的
`degraded（探针 online，但 astrbot 未接上 OneBot WS）`，12:23:06 就自己回到
online，**没有**重启 napcat。所以「重启 astrbot」本身不会踢 QQ。

### 操作上要记住的两条

1. **重启 astrbot 后顺手确认 napcat 没被踢**：
   `sudo docker logs napcat --since 5m | grep -iE "KickedOffLine|离线|扫码"`。
   astrbot 重启会让 OneBot WS 断一下，守护脚本会短暂报 degraded，那是正常的、
   会自愈；但如果同时赶上 QQ 风控踢人，就会退化成要扫码。
2. 真要扫码时，用守护脚本维护的页面（会一直换新鲜码，QQ 码只活约 2 分钟，
   别用日志里那条已经过期的 URL）：`:8088`（`qqbot-qrweb.service`），
   容器内路径 `/app/napcat/cache/qrcode.png` 同步到 `/opt/qqbot/public/qrcode.png`。
