## 一、当前架构

### 1.1 总体部署

```
┌─────────────────────────────────────┐
│  阿里云 ECS (Ubuntu 22.04)           │
│  ├── Docker ─── NapCat (QQ 协议端)   │
│  │      └── AstrBot                  │
│  │             ├── 45 个 dsh-* 插件  │
│  │             │   (优先管线)        │
│  │             └── 多模型 LLM 通道   │
│  └── Android 管理 APK (可选手持)     │
└─────────────────────────────────────┘
```

- **服务器**：阿里云 ECS, Ubuntu 22.04, 2 核 4G, 40G SSD。
- **QQ 协议**：NapCat (NTQQ 协议), Docker 容器内运行。
- **Bot 框架**：AstrBot (Python), Docker 容器内运行, `imagegen.env` 管理环境变量。
- **插件体系**：45 个 `dsh-*` 插件,按优先级编排为**断点管线**(
  分组 `armor`/`merge`/`decide` 优先 2000 → 注入组 → 输出组 priority 100)。
- **模型通道**：DeepSeek / Claude / 智谱等多模型,支持视觉(TTS/文生图/视频)专用 API。

### 1.2 插件管线架构

插件按优先级分三层,不全部串行:

```
输入侧 (priority=2000)       注入组 (priority=1000)       输出侧 (priority=100)
┌──────────┐                ┌────────────────┐          ┌──────────────┐
│dsh-armor │ → 拦截破甲话术  │dsh-memory      │ → 记忆   │dsh-effect    │ → 效果观察
│dsh-merge │ → 被 @ 聚合     │dsh-ctxclean    │ → 去陈   │dsh-emotion   │ → 情绪注入
│dsh-decide│ → 判断该不该回  │dsh-fwd         │ → 历史   │dsh-style     │ → 句长样本
└──────────┘                │dsh-glossary    │ → 黑话   │dsh-human     │ → 分段发送
                            │dsh-slang       │ → 学习   │dsh-aiflavour │ → 去 AI 味
                            │dsh-imgctx      │ → 视觉   │dsh-humanizer │ → 人味改写
                            │dsh-vischain    │ → 降级链 │dsh-typo      │ → 错别字
                            │dsh-...         │ (共45种) │dsh-noise     │ → 噪点
                            └────────────────┘          │dsh-quote     │ → 引用重写
                                                        │dsh-...       │ (共18个输出插件)
                                                        └──────────────┘
```

关键设计原则:

1. **拦截先于注入** — 先判断「要不要回」再决定「怎么说」,防止攻击输入触达主模型。
2. **说话质量管线** — 输出侧从语气/风格/分段→去AI味→错别字→噪点是**可断链**:
   关掉任意一环后面的照常走,不会崩。
3. **影子模式全闭合** — 所有插件的判定/动作均已从 shadow 切换为 live 模式,
   线上无静默判断环节。日志可证实每个插件都在真实生效。

### 1.4 风险与应对现状

| 原定风险 | 当前状态 | 应对 |
|---------|---------|------|
| QQ 账号风控/封禁 | 大号已封,换用「大肥鱼2号」运行 | 小号运行+消息规律模拟真人 |
| API 费用暴涨 | DeepSeek + Claude 混合,月费可控 | 设 Token 上限+效果通过 `dsh-effect` 闭环观察 |
| 记忆数据库膨胀 | SQLite 运行良好 | 240 条缓冲+LLM 摘要,约 98 MB `data/` |
| 服务器被攻击 | 密钥登录,仅开放必要端口 | Docker 网络隔离+端口限制 |
| 语音/图片格式 | NapCat 自动处理 | silk 转换由 `dsh-voice` 内建 |

## 二、后续方向

### 2.1 短期(1~2 周)

| 方向 | 优先级 | 说明 |
|------|--------|------|
| 知识库冷归档 | 高 | 比例预期逻辑提案已通过但未实施;长期重复话题((nnn)含 / 群友A/B/C）需要定期存档机制 |
| 多群隔离 | 中 | 当前硬编群号 100000001;插件级别需适配多群路由 |
| 容器资源限制 | 中 | 当前容器无 CPU/内存限制,极端话题可能打满 4G |
| 第三方插件兼容 | 低 | dsh-merge/armor 等插件接管了框架默认行为,与其他 AstrBot 插件共存需验证 |

### 2.2 中期(2~4 周)

| 方向 | 说明 |
|------|------|
| **多模态召回闭环** | 当前`dsh-imagegen`/`dsh-video`只有生成,缺少从群聊学图/视频的能力 |
| **群友画像精细化** | 目前仅 LLM 抽取+注入;引入长期用户偏好分类(信源可信度/话题韧性) |
| **滑动窗口优先级** | 240 条缓冲在活跃群聊 1~2 天即填满;压缩策略可优化为按人+时间衰减 |
| **「科研模式」API 成本透明** | 通过 `dsh-effect` 的数据,生成各功能模块的 token 消耗报表 |

### 2.3 长期(1~3 月)

| 方向 | 说明 |
|------|------|
| **插件市场** | 将 45 个插件抽成独立可安装包,支持社区提交新的 dsh-* 插件 |
| **Web 管理后台** | 替代安卓 App 作为主要管理入口,可视化调节插件参数 |
| **多机器人协作** | 多个 QQ 号组成群内「AI 摆龙门阵」场景 |
| **语义搜索引擎** | 群聊历史全文检索,按时间/发送者/话题维度搜索 |

## 三、技术债务与已知问题

| 问题 | 影响 | 计划 |
|------|------|------|
| 45 个插件 cache 注册名硬编码 | 框架升级可能破 | 随 AstrBot 新版接口迁移重构 |
| 所有配置走单一 env_file | 45 插件的 100+ 变量集中同一文件,可读性差 | 拆分多 env_file 按功能域加载 |
| 无 CI/CD | 改插件手动 scp + restart | 引入 GitHub Actions 自动部署 |
| 群聊活跃时段硬编码(8:00~2:00) | 未考虑假期/考试季作息变化 | 改为从群聊活跃度数据动态检测 |
| 语音转写只支持 AssemblyAI | 另一个供应商出问题时整条链路不可用 | 加入 Whisper 本地转写作为 fallback |

---

## 四、总结

从 2026-08-30 的「双端挂机」原型到今日的 45 插件云端管线,机器人已从
「能跑」(实验中) → 「能说」(28 插件) → 「像真人一样沟通」(45 插件全 live)
三个阶段。当前系统在阿里云 ECS 上稳定运行,影子模式已全部闭合,
45 个插件构成一条可断链运行的说话质量管线。

**下一步的核心矛盾**从「搭建基础设施」转变为**「运营精细化」**:
不再缺能力,而是需要让每个能力在真实群聊中持续积累数据并自我优化。
