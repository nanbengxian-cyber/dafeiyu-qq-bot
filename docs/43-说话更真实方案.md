# 下一版方案：说话更真实 + 多步思考（先想清楚再开口）

时间：2026-09-02 · 状态：**已全部实施，见 `说话更真实与多步思考实施记录.md`** · 配套：`空头承诺根因与修复记录.md`、`答非所问与主动回复频率调优记录.md`

> 实施后有两处结论被实测推翻，以实施记录为准：
> ① 决策步不能让模型直接输出「沉默/回话」结论（提示词一改判沉默率就在 0%~62% 乱跳），改成「模型只输出感知布尔量 + 代码做 veto-only 判定 + 温度 0」；
> ② `possibility_reply` 定 **0.28** 而非 0.38 —— 实测判沉默率是 11% 不是估计的 34%。

## 一、结论先行

1. **拟人三板斧的顺序**：先修 bug（工具前「垫话」把 `[贴纸:x]` 原样漏进群）、再立硬约束（句长翻倍、9 成回复带贴纸/图全是软规则没执行）、最后上多步思考（小模型先判断「在聊什么、该不该说、用什么动作」）。
2. **成品插件一个都不能直接装**：拟人类插件要么覆写人格/记忆数据（`self_learning` 等，与我们手工调的 3644 字人格 + dsh-memory 冲突），要么和已装的 dsh-ctxclean / dsh-memory / dsh-mention 抢钩子；唯一能白捡的是**框架自带的分段回复开关**。正确姿势是抄它们的「小模型判定接话」「错字模拟」等机制自研。
3. **深度学习/微调现在做不了**：不是技术问题，是数据只有 65 条真人原话（958 字，差 2 个数量级）+ 服务器 2 核 1.6G 无 GPU + 渠道无 `/fine_tuning` 接口无 embedding。现在能落地的替代是**从 dsh-memory 已存的真人原话里抽 4~6 条当 few-shot 样本注入上下文**——实测平均句长 16.5 → 9.5 字，逼近真人中位 8 字，零成本。

## 三、真 bug：中间步贴纸标记泄漏（P0，必修）

**现象**：napcat 收到的群消息里 7 条带 `[贴纸:嘲笑]` 原文；同轮最终回复的贴纸却正常剥掉了。

**证据链**（astrbot 日志逐秒对齐）：
```
14:01:11.663 [mention] at=False 不用@(工具=无 …)        ← on_decorating_result 在中间步跑了
14:01:11.667 Prepare to send … 得嘞，这就把群主画飞[贴纸:嘲笑]   ← 中间步文字发出
14:01:12.201 Agent 使用工具: ['generate_image']         ← 工具在这之后才执行
14:01:26.123 [贴纸] 发送 1 张, tags=['嘲笑'], cleaned_text='画好了…' ← 最终回复才被剥
```

**根因**（代码）：
- `on_llm_response` 只在 `MainAgentHooks.on_agent_done`（astr_agent_hooks.py）触发，**一轮只触发一次**。
- 工具循环里每步的 assistant 文字在 `run_agent` 里 `astr_event.set_result(...) + yield`，调度器洋葱模型逐段跑完 decorate → respond，**根本不经过 on_llm_response**。
- 所以 dsh-sticker 的剥离逻辑对中间步 100% 不生效。6 小时窗口：12 次工具中间步里 7 次泄漏。
- 同类坑 dsh-welcome 已踩过一次（`llm_generate` 不走管道），教训是「凡绕过管道直接出消息处都要自带剥离」；中间步这条漏网路径当时没覆盖。

**修复（推荐 B+C 一起做）**：
- **A** `buffer_intermediate_messages=True`：中间步合并成最终一条。缺点：丢掉「先应一声再干活」的拟人感，且全局生效。
- **B** dsh-sticker 加 `on_decorating_result` 钩子统一兜底剥离（与 dsh-mention 同钩子同时机，已实证会跑到中间步）。出口处总是清理——两条独立防线不能塌成一条。
- **C** 人格/工具指令删掉「提前说『这就X』」样板：模型要么直接动手（工具调用允许不说话），要么说有意义的话。收敛中间步，泄漏面自动变小。

**验收**：真群跑 30 分钟，napcat 侧抓 `[贴纸` 为 0。

## 四、说话更真实：三板斧（按性价比）

### 4.1 真人样本 few-shot 注入（最大单点收益，零成本）
- 实测：同样 3644 字人格 + deepseek-v4-flash，注入 4~6 条该群真人短句（提示「学长度和语气，别学内容」）后，4 个场景平均句长 **16.5 → 9.5 字**；对照组「硬性字数上限指令」平均 8.5 字但更僵。
- 语料现成：`dsh_memory.db` 的 `buffer` 表已存每群滚动 240 条原话（真群满 240 条）。做「最近 N 条真人短句」动态注入，说话风格会自动跟着群内真人漂移。
- 实现：on_llm_request 里读 buffer 表，抽 4~6 条（优先 20 字内），包成 `<style_samples>` 块注入 `extra_user_content_parts`；ctxclean 的 `^<小写标签>` 结构判断会自动清旧块，天然免疫「注入块污染历史」问题。
- 注意：样本只给「长度/语感」，不能学内容（脏话、具体梗）。

### 4.2 贴纸/图片配额（硬杠杆）
- 人格是软约束（实测 91% 都发）。改结构约束：dsh-sticker 在 on_decorating_result 做**概率闸门**（如连续 2 条带贴纸后，第 3 条强制纯文字）；dsh-imagegen 工具路径出图后，同轮文字不再追加贴纸。
- 目标：贴纸出现率 91% → ~30%，且集中在「真有情绪」时。

### 4.3 分段回复（框架自带，开启 + 改配置）
- 现状 disabled。开启后要改两个东西：
  - `words_count_threshold=150` 语义是**「超过就全文发送，不超过才分段」**，中位 20 字的回复全会进分段逻辑，无需改。
  - 现行默认正则 `.*?[。？！~…]+|.+$` + DOTALL 会把模型自己打的换行吞掉 → 换行分段完全失效（实测 10 条真实回复仅 2 条真被切）。换 `[^\n。？！~…]*[。？！~…]+|[^\n]+`：**尊重模型换行 + 句末标点，逗号不切**（避免把一句话剁碎），实测 10 条里 5~7 条自然分 2~3 段。注意单字段（「哼，」后无内容）不分，只在内容 >4 字时才切。
  - 间隔用现有 random（1.5~3.5s）或 log 模式按字数，发出去就是「一条一条蹦」的打字感。
- 配合 4.1 的短句样本：模型按「一条一行」自然分行，分段才有料可分。

## 五、多步思考：先想清楚「在聊什么、该不该说、要做什么」

### 5.1 现在缺什么
- 主动插话 = 掷骰子，没有「值不值得接」的判断。
- 主模型一次到位，没有「先判话题 → 再定动作」的显式环节。
- 工具前先发「行，这就X」样板过渡——正是「不知道该不该说」的表现。

### 5.2 方案：on_llm_request 前加一道小模型「决策步」（新插件 dsh-decide）
- 位置：`OnLLMRequestEvent` 在 agent 正式跑之前触发（internal.py:269），`event.stop_event()` 返回 True 可**直接截停主模型**，一分钱主模型 token 都不花。
- 流程：
  1. 只对**主动插话**路径做完整决策；被@ / 有明确指令时跳过或只做轻量判断（别让用户白等 4 秒）。
  2. 读最近 N 条群消息（直接读 dsh-memory 的 buffer 表，不依赖 req.contexts 顺序）+ 自己上一轮说的话，问小模型输出紧凑 JSON：`{act: 沉默|回话|工具, topic, tone, avoid}`。
  3. `act=沉默` → `stop_event()`；`回话/工具` → 把决策包成 `<judgement>` 块注入请求，主模型照着意图说（块里**只给意图不给成句台词**，防止模型照着念丢人设）。
- 实测（8 组场景，deepseek-v4-flash-0731）：
  - 判断准确 6/8；两个错例恰好都是「该不该插话」的边界（把催婚私聊误判为可接、把泛群闲聊误判为沉默）——所以它只能当**闸门+参考**，不能当绝对否决。
  - 延迟 1.7~5.0s（中位 3.6s）；输入 ~176 tokens、输出 ~32 tokens。主调用中位 input 9390 / output 118 → **决策步成本 ≈ 主调用的 2%**。
  - 成本翻盘点：每判「沉默」一次 = 省一整次主调用（9390 tokens）。25% 插话率 × 40% 判沉默 ⇒ 每 10 条插话省 4 次主调用、花 10 次决策步，**多步思考反而省钱**。
  - 坑：glm-5.3-flash / qwen3.7-flash 会默认把正文放 `reasoning_content`、`content` 为空，JSON 解析直接失败 → 决策模型**固定 deepseek-v4-flash-0731**，并在插件里兜底 content 空 / 开头是 ``` 的情况。
- 替代方案对比：
  - 单次调用内自评（让主模型输出 `#判断` + `#正文`）：实测判断行会原样漏进正文（2/4 漏），还要多剥壳一次，不如两段式干净。
  - 换更强主模型（deepseek-v4-pro 2.9s / kimi-k2.6 26s 不可用 / minimax-m2.7 5.0s）：没有「该不该说」的显式判断，延迟还加在每条上，不如决策步划算。

## 六、成品插件 vs 自研 vs 深度学习

### 6.1 市场插件盘点（官方市场 1940 个里挑相关的）
**抄机制不安装**：
| 插件 | ★ | 值得抄的机制 |
|---|---|---|
| astrbot_plugin_self_learning | 399 | 学对话风格、群黑话、人格自适应演化——但它直接改写人格/记忆数据，与手工人设和 dsh-memory 冲突；**借鉴「人格随对话演化」思路，不装** |
| astrbot_plugin_outputpro | 75 | 错字模拟（写成再改）、智能引用——低成本拟人小技巧 |
| astrbot_plugin_self_initiated_reply | 7 | 由判断模型决定是否自然接话 = 5.2 的思路，社区已有验证 |
| astrbot_plugin_regex_trigger_pro_max | 6 | 正则唤醒 + 小模型二次判定唤醒，同思路 |

**明确不装**：livingmemory(334) / private_companion(326) / proactive_chat(382) / angel_memory(183) / memorix(51)——与已验证的 dsh-memory 功能重叠，且依赖向量库（服务器跑不动、渠道无 embedding），大多面向私聊陪伴场景，群聊拟人要做的是「少说、短说、看场合」，恰恰是它们不擅长的。

**结论：一个都不直接装**；抄 2~3 个具体机制（小模型判定、错字模拟、分段），按自家插件风格自研，可控可回滚。

### 6.2 深度学习/微调：现状不可行，但要留种子
| 卡点 | 实测 |
|---|---|
| 数据量 | napcat `get_group_msg_history` 只能翻 200 条（翻页返回空）；真人纯文本 65 条 / 958 字。LoRA 需几千上万条对话，差 2 个数量级 |
| 硬件 | 2 vCPU / 1.6G RAM / 无 GPU，本地别说训练，7B 推理都悬 |
| 渠道 | relay-a 无 `/fine_tuning/jobs`（404）；embedding 各模型全 400 |

**未来条件**：攒到 ~1 万条真人原话 + 有 GPU 训练环境，再评估 LoRA 一个 7B 小模型的群聊风格。现在最便宜的准备动作：**dsh-memory 加一张不裁剪的 archive 表，只 append 真人短句，从今天开始攒语料**——零成本、可逆，真要训时不用补历史。

## 七、落地顺序（四步走）

1. **P0 修 bug**：中间步贴纸泄漏（B 兜底剥离 + C 收敛样板话）。验收：真群 30 分钟 `[贴纸` 泄漏 0。
2. **立竿见影**：few-shot 真人句注入（4.1）+ 贴纸配额（4.2）+ 分段回复配置（4.3）。验收：机器人中位句长 ≤12 字、贴纸率 ≤40%。
3. **多步思考**：dsh-decide 插件（5.2）。验收：插话中 `act=沉默` 占比落在 30~50%；被@路径延迟增量 <1s（决策步只记录不拦截）；真群 1 小时零泄漏。
4. **语料种子**：buffer archive 表开始攒，1 万条后再谈微调。

## 八、不做什么 / 风险

- 不装市场大插件（6.1）；不做本地模型（服务器扛不动）；暂不换更强主模型（kimi 不可用，多步思考已在补「聪明」）。
- 风险 A：`<judgement>` 块写太具体 → 模型照着念、丢掉傲娇人设。对策：只给意图（act/topic/avoid），不给成句。
- 风险 B：分段开启后单字段（「哼，」）单独成条。对策：内容 ≤4 字不分段，上线前用真句式跑一遍。
- 风险 C（新发现，需跟进）：astrbot 容器今天被 recreate 过（14:25、14:41，docker logs 被清空），watchdog 只 restart napcat、cron 无相关项，原因未明。**容器重生会清 docker logs**——关键统计要落到监控/表，不能只靠 docker logs 排查。
