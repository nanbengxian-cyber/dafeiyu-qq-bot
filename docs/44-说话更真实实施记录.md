## 四、四次失败换来的一条方法论

决策步的提示词改了五版。前四版全在同一个坑里：**让模型直接输出「沉默/回话」这个结论**。

| 版本 | 提示词形状 | 12 个标注场景 | 真实随机窗口判沉默率 |
|---|---|---|---|
| v1 | 结论式，沉默条件写在前面 | 5/7 | 纯玩梗也判沉默 |
| v2 | 加一句「拿不准就选回话」 | 6/10 | **0%**（诉苦、谈正事都要插嘴） |
| v3 | 两步优先级（先看硬信号再看能不能接） | 7/11 | **62%**（玩梗/话头/吐槽全判哑） |
| v4 | 模型只输出布尔事实，代码判定 | 9/12 | 30% |
| v5 | 同 v4，但判定改 **veto-only** | **11/12** | 11% |

同一个模型、同一批场景，只改措辞就在 0% 和 62% 之间乱跳 —— 说明「结论」这个输出形状本身不稳，继续调措辞是白费功夫。

但**感知**是稳的：四版里「有人在诉苦」「有人说了别插话」「这句只是应答」「两人在对具体安排一来一回」都判得准，翻来覆去错的只有「所以到底该不该说」。

于是 v4 让模型只回答 7 个布尔量 + 4 个短描述，阈值和组合逻辑写成一个纯函数：

```python
def verdict(f):
    if f["stop"]:    return "沉默", "有人叫别插话"
    if f["venting"]: return "沉默", "有人在诉苦"
    if f["arrange"] and not f["banter"]: return "沉默", "两人在谈具体安排"
    if f["ack"] and not f["open"]:       return "沉默", "只是一句应答"
    return "回话", ...     # veto-only：没有否决信号就放行
```

v4 → v5 只改了最后一行。v4 要求「必须感知到 banter/open/about_bot 才放行」，错的三个全是旗标一片空白的单行短消息（`你们都几点睡`、`这鱼今天怎么这么安静`）—— 模型对只有一行的输入设不出正面旗标。改成「只有否决信号才拦」就 11/12。

这和 `dsh-imagegen` 那次的教训完全同形：**主证据是群里发生了什么，模型的意见只用来否决**。

### 温度必须是 0

`verify_realgroup.py` 第一次跑，同一个窗口连问 3 次得到「回话/沉默/回话」。在下结论「判断不稳」之前先分清了两件事：模型对**清晰信号**摇不摇摆（那是真问题），还是对**本来就模糊**的窗口给不同答案（那是窗口的问题）。

专门写了个探针，每个窗口问 5 次，跑两个温度：

| 窗口 | temp=0.2 | temp=0.0 |
|---|---|---|
| 清晰-诉苦 | 稳（5/5 沉默） | 稳 |
| 清晰-玩梗 | 稳（5/5 回话） | 稳 |
| 清晰-叫别插话 | 稳（5/5 沉默） | 稳 |
| **模糊-真群最近窗口** | **摇摆（4 回话 + 1 沉默）** | **稳（5/5）** |

判断是事实抽取不是创作，随机性只带来摇摆。`llm_generate` 现在显式传 `temperature=0`。

## 五、代码之外的三个硬事实（都是踩出来的）

### 1. 改配置不重启 = 白改

`need_active_reply` 每次都调 `cfg(event) → context.get_config(umo)`，看着像现读，但它返回的是**内存里的 `AstrBotConfig` 对象**（`core/star/context.py:609-612`），而 `AstrBotConfig` 全类只有 `save_config`，没有 `reload`/`watch`/`mtime` 任何重新读盘的入口。

后果：为了让插话必然发生而把 `possibility_reply` 改成 1.0，跑了两轮测试都「一次没触发」，误以为是 `dsh-decide` 拦掉了 —— 其实量到的是 0.28 的骰子。

推论：幂等脚本**不能只比文件 md5 决定要不要重启**。上一轮可能上传成功但重启失败，于是文件是新的、容器跑的是旧代码，而 md5 一致让本轮判定「无改动」。`runner.sh` 现在的权威判据是：

```bash
docker inspect -f '{{.State.StartedAt}}' astrbot   # 容器启动时间
find $PDIR/dsh-* -name '*.py' -newermt "$started"  # 有更新的就必须重启
```

### 2. `updated_at` 写成整数会让整个 bot 起不来

改人格时把 `updated_at` 写了 `int(time.time())`。SQLite 弱类型照收，但列类型是 `DATETIME`，SQLAlchemy 读它走 `datetime.fromisoformat`，于是 AstrBot 一启动就在 `persona_mgr.initialize → get_all_personas` 崩掉：

```
TypeError: fromisoformat: argument must be str
```

supervisor 反复重启，机器人下线约 90 秒。**SQLite 不校验类型不等于上层不校验**：往 ORM 管的表里写值要照 ORM 的类型写。`patch_persona.py` 现在写 ISO 字符串、写完自检 `typeof()=='text'`、自检失败就地从备份回滚，并且每次运行都会顺手把被写坏的类型修回来。

### 3. 分段正则要「尊重换行」但不能切出孤立标点

原默认正则 `.*?[。？！~…]+|.+$` 在 DOTALL 下用 `.+$` 兜底，会把模型自己打的换行整段吞掉 —— 模型分行了也白分。拿 19 条真实回复 + 边界用例实测三个候选：

| 候选 | 正则 | 多段率 | 孤立标点段 |
|---|---|---|---|
| A 现行 | `.*?[。？！~…]+|.+$` | 7/18 | 2 |
| B 尊重换行 | `[^\n。？！~…]*[。？！~…]+|[^\n]+` | 10/18 | 2 |
| **C 采用** | `[^\n。？！~…]+[。？！~…]*|[^\n]+` | 9/18 | 1 |

A/B 都会把 `？我哪天不乖了` 切成孤零零一个 `？` + 正文；C 的第一分支要求「至少一个非标点实字」，只有整条消息就是 `！！！` 时才出现纯标点段（合理）。三者都不丢内容。配 `content_cleanup_rule = [，、]+$` 去掉段尾逗号，避免「哼，」单独成条。

## 六、测试自己把自己测坏，四次

端到端测试的做法是：伪造一个 napcat，连上容器内 `ws://127.0.0.1:6199/ws`，发 OneBot 事件，收 action 帧。协议是明文 JSON，全程不碰真实 QQ。但这条路上有四个坑：

| # | 症状 | 真相 |
|---|---|---|
| 1 | 401 拒绝连接 | 适配器配了 `ws_reverse_token`，要带 `Authorization: Bearer`。token 从配置现读、不写死不打印 |
| 2 | 所有用例共用一个群号，判断结果乱 | `dsh-memory` 把每条测试消息写进 buffer，`decide` 又从 buffer 读最近 8 条 —— 第 5 条看到的窗口里还躺着第 2、3 条的「心累」「别插话」。日志旗标 `[.VS.B..]` 就是证据：**判沉默完全正确，错的是测试**。改成每个用例独立群号 |
| 3 | 该沉默的用例被判回话 | 所有用例共用一份「玩梗」seed，`decide` 读最近 8 条就读到了「群主又跑了/懒猪一个」。测试必须控制模型看到的**全部** 8 条，于是每个用例自带上下文 |
| 4 | 8 条全无回复 | 插话路径硬要求该会话**已存在 conversation**（`builtin_stars/astrbot/main.py:241-245`），全新测试群没有。改成先 @ 一句建会话，再发插话消息 |

另外两个纯技术坑：`websockets` 默认 `max_size=1MiB`，而出图时 action 帧里的 base64 图片实测 4.63 MB，超限时**我们这一侧**会回 1009 并断连，后面所有用例全废（报错文本 `sent 1009 ... frame with 4633778 bytes` 看着像对方发错了）；还有 `except BaseException` 包住 `sys.exit` 会把 `SystemExit` 也捕获，明明 `MEASURE OK` 却先刷一串假 Traceback。

还有一次是断言本身写错了 —— 测试只调了 `_ASK_RE` 一道正则，而被测代码是 `_ASK_RE and not _NOT_ASK_RE` 两道，于是报了个假失败。**测试必须复刻被测代码的完整判定链，抄一半比不抄更坏**：它会让人去改本来是对的代码。

同样，`archive == buffer` 这个断言一开始写成 `n_arc >= n_buf`，也是错的：archive 有 `UNIQUE(group_id,user_id,text)`，是去重表，天然比 buffer 少。正确的不变量是 `archive 条数 == buffer 里三元组去重后的条数`。

## 七、断线自愈的落地脚本

用户的要求是「渠道有时候会中断，你可以自启动自己继续任务」。做法不是让脚本猜任务，而是把每一步写成**幂等收敛**动作：无论从哪一步断掉，重跑一次状态都会收敛。

```
bash <runner-dir>/runner.sh          # 收敛一次
bash <runner-dir>/runner.sh --watch  # 每 5 分钟收敛，直到全绿
bash <runner-dir>/runner.sh --status # 只看状态
bash <runner-dir>/run_interject.sh   # 插话路径端到端（会改概率+重启+自动恢复）
```

幂等靠四件事保证：上传前比 md5、只有真换过文件才重启（外加上面说的 StartedAt 判据）、配置改动走 `utf-8-sig` 且改前自动备份、每步都 `py_compile` + 跑自测，失败就停在该步不污染后面。

`run_interject.sh` 还有一个安全设计：临时把插话概率提到 1.0 的同时，把 `active_reply.whitelist` 设成只含测试群号 —— 测试窗口内真群**一次都不会**被插话，比平时的 0.28 更安静。恢复动作挂在 `trap EXIT INT TERM` 上，脚本被 Ctrl-C 或超时杀掉也会执行，恢复后还会复核值确实回到 0.28、白名单确实清空。

## 九、参数与推导

| 参数 | 值 | 怎么定的 |
|---|---|---|
| `possibility_reply` | **0.28** | 18 个真实随机窗口实测判沉默率 11%，`0.25 / (1-0.11) = 0.28`。先前写 0.38 是按估计值 34% 倒推的，实测后改正 |
| `DSH_STICKER_WINDOW` | 2 | 命中率 = `1/(WINDOW+1)`（授予的那次自己也占一个窗口槽），WINDOW=2 → 33%，满足 ≤40% |
| `DSH_DECIDE_MIN_GAP` | 60s | 「刚说完又自己接一句」代码百分百知道，不该问模型。压发言占比最直接且零成本 |
| `DSH_DECIDE_TIMEOUT` | 8s | 实测中位 2.2s，8s 兜长尾；超时 fail-open |
| `DSH_DECIDE_MAX_SILENCE_STREAK` | 6 | 连续判沉默 6 次后强制放行一次，防判断退化把机器人变哑巴 |
| `DSH_STYLE_MIN_LEN` | 1 | 单字样本（`草`、`困`）恰恰是最有价值的长度示范。但单字必须是中文（拦掉 `a`、`6`） |
| 决策步温度 | 0 | 见上文实测 |

成本账：主调用 ≈ 9390 input / 118 output，判断步 ≈ 381 in / 61 out（约 4%）。判沉默率只要超过 4%，这套多步思考就是**净省钱**的；实测 11% + MIN_GAP 拦掉的部分，是明显省。

## 附：一句话经验

1. 把「结论」交给模型不稳，把「感知」交给模型、「决策」写进代码才稳；判定用 veto-only 而不是「必须先感知到正面信号」。
2. 事实抽取类调用温度设 0，摇摆不是模型笨是采样在赌。
3. AstrBot 的配置是**内存快照**，改文件必须重启；幂等脚本要拿容器 `StartedAt` 对比文件 mtime，不能只比 md5。
4. 往 ORM 管的表写值要照 ORM 的类型写，SQLite 的宽容不代表上层宽容。
5. 测试要复刻被测代码的**完整**判定链；抄一半会让人去改本来正确的代码。
6. 端到端测试的隔离粒度要盖住「被测组件读什么」—— `decide` 读最近 8 条，测试就必须控制那 8 条。
7. 用户明确点名要的能力，任何路由都不许否决。
