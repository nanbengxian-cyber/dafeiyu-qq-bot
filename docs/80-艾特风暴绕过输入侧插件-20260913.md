# 80 · 艾特风暴（dsh-merge）绕过全部输入侧插件

2026-09-13 · 主群 100000001

## 一、怎么发现的

排查「不知道谁艾特他」和「防占便宜失效」时，翻 13:20 那轮日志，发现群友 @ 它说的
「**你看看你吃多少token了?！**」「**吃白饭的肥鱼**」正是 selfworth 1.1.0 刚补的目标话术，
却**一条都没触发**，同时刻也没有任何 `[selfworth]` 日志。管道日志给出答案：

```
13:20:48 [merge] gid=100000001 触发艾特风暴，开窗收集
13:20:48 [Core] dsh-merge - collect stopped event propagation.   ← 吞掉
13:20:56 [Core] dsh-merge - collect stopped event propagation.   ← 吞掉
13:20:58 [Core] dsh-merge - collect stopped event propagation.   ← 吞掉
13:20:59 [merge] 生成期间收到新艾特，丢弃旧草稿并继续等待
13:21:00 [Core] dsh-merge - collect stopped event propagation.   ← 吞掉
13:21:07 [Core] dsh-merge - collect stopped event propagation.   ← 吞掉
13:21:23 [merge] 停歇后重扫并发送：上下文24条／其中艾特7条
```

7 条艾特全被吞，然后走**整合回复**发出去。整轮 selfworth 没参与。

## 二、根因：整合回复不经过插件钩子链

`dsh-merge` 的两个动作决定了这件事：

1. **逐条拦截**（`plugins/dsh-merge/main.py:336`，`priority=2000`）：
   窗口内每条艾特都 `event.stop_event()`，同批后续 `on_llm_request` handler 全部跳过
   —— 这正是它的设计意图（不让机器人在被喊时一边说"先等喊完"一边随机插话）。

2. **整合发送**（`_flush()`，`main.py:128`）：直接
   `await star_ctx.llm_generate(chat_provider_id=pid, prompt=..., system_prompt=persona)`
   —— **绕开 AstrBot 的插件管道，自己调模型**。

所以整条 `on_llm_request` 链（selfworth / clarify / agency / spine / social / scene …
以及出口侧 `on_decorating_result`）在风暴轮里**全部失效**。这不是某个插件的 bug，
是合并机制与钩子架构的固有冲突。

## 三、影响面（2026-09-13 当天实测）

| 指标 | 次数 |
| --- | --- |
| merge 开窗（艾特风暴） | **25 次** |
| merge 吞掉逐条回复 | **62 次** |
| merge 发出整合回复 | 25 次 |
| selfworth 输入侧命中（全天） | 2 次（均为 00:01 前，部署后 0） |

即当天约 **25 轮对话完全绕过了全部输入侧插件**。群主感知到的
「防占便宜失效」「不知道谁艾特他」里有相当一部分落在这个盲区——
**不是判据不够，是根本没走到判据**。

## 四、本次的处理

风暴路径的改造涉及 dsh-merge 的核心机制（合成事件要重建完整插件管道，
改动面和风险都大），**本次不动它**，只做两件事：

1. **补齐仍遗漏的判据**（selfworth，已部署）：风暴里那些原话本身也要认得，
   这样等将来修好管道、或风暴没触发时能正常工作。
   - `DEAL` 新增：`(?:吃|烧|费|用)[了掉]?\s*(?:多少|好多|超多|巨多|太多)\s*token`
     —— 「你看看你吃多少token了?！」（原来只认具体数字如「几万token」）
   - `DEAL` 新增：`(?:吃|喝|啃)白(?:饭|食|嫖)`、`白(?:吃|喝|嫖|蹭).{0,4}(?:鱼|你|机器人)`
     —— 「吃白饭的肥鱼」
   - `_LABEL_WORDS` 新增「吃白饭 / 白吃饭 / 白嫖货」，让「行行行 吃白饭就吃白饭」
     这种跟着认账的形状也能被认出来。
2. **记录待办**：dsh-merge 整合路径的插件化改造留作后续独立任务
   （思路：flush 时不直接 `llm_generate`，而是构造合成事件走完整管道；
   或在 flush 前手动调用需要的关键判据）。

回归：`SELFWORTH_TEST_OK`；3776 条真话 sweep 仍为 32 条命中、无新增误伤；
「白嫖党永不为奴」等嘴硬仍原样放行。

## 五、后续建议（未实施）

1. 先量一段时间：统计「风暴轮里出现过 selfworth 目标话术」的比例，
   决定值不值得改 dsh-merge。
2. 若改：优先方案是在 `_flush()` 里**复用同一套判据做一次输入/出口检查**，
   而不是重造整个管道——代价小、回滚容易。
3. 无论改不改，都应在 `/整合回复状态` 里暴露「本轮回合绕过了 N 个输入侧钩子」，
   让这类静默失效可见（当前是完全无感的）。
