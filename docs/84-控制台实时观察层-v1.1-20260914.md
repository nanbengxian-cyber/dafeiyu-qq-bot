# 84-控制台实时观察层 v1.1 —— 2026-09-14

## 一句话

大肥鱼控制台（手机 App）从「只看状态 + 改配置」扩成「实时看机器人在干啥」。
新增 4 个端点，App 加 3 个页签：**实时 / 心智 / 日志**。

## 为什么做

用户要求：实时看到每个插件是否在运行、最近运行日志、确保能看到大肥鱼所有配置、
群的动向、对话详细日志、总体上思维链与动向。

## 架构

```
手机 App (versionCode=2)
   │  GET /api/console/{live,mind,log,rawconfig,status}
   ▼
8088 qrweb（root 身份，现有鉴权/cookie/锁定逻辑不动）
   │  console_api.handle()
   ▼
console/server/feed_sources.py  ← 只读聚合
   │
   ├─ astrbot.log      增量扫描（插件活性 / 日志尾巴）
   ├─ dsh_memory.db   buffer 表 → 群友消息流
   ├─ dsh_effect.db   reply 表 → 机器人发言 + 群里反应判词
   ├─ dsh_mind.db     observe / observe_block → 内在状态块
   ├─ dsh_selfaware.db self_revision / sense_event → 能力变化
   ├─ dynamics.json   群体记分卡 P1~P7
   └─ cmd_config.json + imagegen.env → 全量配置（脱敏）
```

**只读**。feed_sources 绝不写任何生产文件；出错一律回空/降级，
不让观察层把控制台搞挂 —— 观察是附加能力，不是生命线（和 patch_qrweb 的哲学一致）。

## 端点

| 端点 | 用途 | 关键参数 |
|---|---|---|
| `GET /live` | 群聊合并流（群友 + 机器人发言） | `group`, `limit`, `before`（翻页锚点） |
| `GET /mind` | 内在状态 + 效应判词 + 能力变化 + 记分卡 + 插件画像 | — |
| `GET /log` | 日志尾巴 | `level`(all/err/warn/info), `name`, `minutes`, `limit` |
| `GET /rawconfig` | 全量配置（密钥掩码） | — |
| `GET /status` | 旧接口，新增 `live_plugins` 字段 | — |

`/live` / `/mind` / `/log` / `/rawconfig` **只支持 GET**，POST 回 404（和 8088 的
「写操作走 /api/console/{config,model,mode,plugin,action}」分工一致）。
`level` 只认 4 个值，坏值抛 `ApiError(400)`。

## 两个必须写在前面的坑

1. **日志时区**。astrbot.log 的时间戳是 UTC+8 挂钟（实测 host UTC 02:39 时
   日志打 10:39），而 buffer.ts / docker StartedAt 是绝对 epoch。要可比，
   日志墙钟必须按 +8 折算：`epoch = timegm(墙钟) - 8h`。不做这一步，
   日志事件会比 buffer.ts「晚 8 小时出现」，所有新鲜度判断全错。
2. **增量扫描**。日志 11~20MB 且一直在长；手机 15 秒一轮询，每次全量重读
   会把这台 2 核小机拖住。日志只增不改（轮转是换文件名），所以按
   `(inode, byte offset)` 缓存，只解析新追加的字节。换文件/被截 → 整个重来。

## 插件活性口径（status / mind 页）

dashboard 的「启用了」只代表插件加载了，不代表它在干活；日志的「有活动」
只能证明进程活着。两个证据放在一起才回答得了「这个插件在运行吗」：

| 状态 | 判据 |
|---|---|
| running | dashboard 启用 + 本次容器启动后有日志 |
| crashed | 有错误日志（最高优先级，压过其他判断） |
| idle | 启用但启动后无日志（安静插件是正常的，不算病） |
| disabled | dashboard 明确关了 |
| unknown | dashboard 问不到（后端故障时回这个，不硬猜） |

日志标签里的历史脏名（`aw`/`dsh-sh-check` 这类一次性测试脚本留下的日志）
天然被 dashboard 清单过滤掉 —— 只有真实存在的插件才会出现在结果里。

## 「思维链」的诚实标注

主模型的原始 `reasoning_content` **不落盘**（agentrouter 的请求转储验证完已置 false）。
`/mind` 给的是 dsh-mind 每轮注入的**内在状态块**（islands/notes）和
dsh-effect 的**观察判词**（strategy/stance/why），这是「它在想什么」最接近的
已落盘证据。界面上必须如实标注这一点，不能把 islands 说成思维链原文。
（`mind_feed()` 里有 `honesty_note` 字段，App 心智页固定显示。）

## 配置脱敏（两层）

8088 是明文 HTTP —— 明文里能出现什么，按「会被邻居路由器看到」来定。
所以宁可多掩一层：键名沾 password/secret/token/key 的都不出服务器。

1. **键名层**：`password|passwd|secret|token|api_?key|apikey|authorization|credential|key$`
2. **值形状层**：`sk-...` / `ghp_...` / `github_pat_...` / `xox...` / `AIza...` /
   `eyJ...`（JWT）/ 32+ 位纯 hex

值形状层是兜底 —— 实测就从这里漏出去六个真 sk- 密钥：
`provider_sources[].key` 是一个列表，里面装的就是 API key，键名就叫 `key`，
键名层挡不住。列表里的字符串值也要走值形状防线，漏掉这一步就是把 sk- 直接吐出去。

纯数字长串（QQ 号、时间戳、ID）不是密钥，别误掩。
