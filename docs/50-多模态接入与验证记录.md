## 二、触发机制

四种触发形状，优先级从上到下。**关键设计：高频场景不依赖模型自觉调工具。**

### 1. 自动钩子（`on_llm_request`）——不需要模型配合

| 触发条件 | 插件 | 行为 |
|---|---|---|
| 消息里出现 `http(s)://` 或 `www.`/`b23.tv` 裸链接 | `dsh-web` | 抓正文 → 注入 `<webpage_context>` |
| 消息里出现 B 站链接 / 裸 `BV号` / `av号` | `dsh-web` | 查 wbi/view → 注入结构化信息 |
| **消息里出现「搜一下 / 查一下 / 百度一下 / 联网搜」** | `dsh-web` | **先搜好 → 注入 `<search_context>`** |
| 消息带视频（框架留下 `[Video Attachment: path …]`） | `dsh-video` | 抽帧识别 → 删掉路径标记，注入 `<video_context>` |
| 消息带图片 / 最近 4 条里有图 | `dsh-imgctx` | 转述 → 注入 `<recent_image_context>` |

为什么用钩子而不是只给工具：`deepseek-v4-flash-0731` 在「完整人格 + 20 条群聊历史」的上下文里经常不调工具，只嘴上答应——`dsh-imagegen` 在生图上踩了三轮才修好。而「群友发个链接问这是什么」是最高频场景，链接就在消息里，插件自己抓完注入，命中率 100 %。

搜索这条是端到端实测补上的：「搜一下今天有什么新闻」模型只回了「等下，我搜搜看[贴纸:思考]」就没了，工具压根没调。搜索**只能**走 `on_llm_request`——结果必须进模型上下文才能被组织成人话，事后贴一段干巴巴的结果列表反而更怪，所以 `dsh-web` 刻意**没有** `on_llm_response` 兜底搜索。

自动搜索的边界刻意收窄：只认显式动词（搜/查/百度/谷歌/联网搜），不认「X 是什么梗」这类泛问句——泛问句模型自己答得挺好（「哈基米」实测答对），每句都去搜纯粹浪费配额和 1–2 s。另加负向后视 `(?<![检调审侦排稽普抽复核盘])`，否则「检查一下代码」「调查报告写完了吗」会被当成要联网搜。

### 2. LLM 函数工具——模型主动调用

六个工具，全部写进人格 `tools` 白名单（`personas.tools`，非 None 时只放行列表内的名字）：

| 工具 | 触发语义 | 参数 |
|---|---|---|
| `generate_image` | 画画/生成图片/出图/壁纸/表情包 | `prompt` |
| `send_voice` | 「用语音说」「发个语音」「念一句」「想听你声音」 | `text` ≤ 60 字 |
| `web_search` | 时事/新出的东西/不确定的事实 | `query` |
| `read_webpage` | 主动想看某个网址 | `url` |
| `bilibili_video` | 主动想查某个视频 | `video` |
| `generate_video` | 做视频/做动画/生成短片 | `prompt` |

### 3. 兜底钩子（`on_llm_response`）——模型答应了却没做

| 判据 | 插件 | 行为 |
|---|---|---|
| 用户要图 + 模型没拒绝没反问 | `dsh-imagegen` | 自己出图 |
| 用户要语音 + 模型没拒绝没反问 | `dsh-voice` | 自己念出来 |
| 用户要视频 + 模型没拒绝没反问 | `dsh-video` | 自己出片 |
| **模型把 `send_voice(text="…")` 这类调用当文本吐出来** | 四个插件全部 | 清掉标记；抠出参数当作真实意图（比意图正则更硬的铁证） |

最后一条是这次端到端实测抓到的真实故障，详见第五节。

判据的形状是固定的：**用户请求是主证据，模型回复只用来否决**（明确拒绝、或在反问要画/念/做什么）。绝不靠「模型答应了」这类关键词、也绝不掐字数——上一轮 imagegen 在这两条上各栽过一次。

### 3.1 跨插件互斥（镜像让路）

三个生成类插件的兜底钩子会互相误触发，用两张镜像表互斥：

| 场景 | 谁让路 | 判据 |
|---|---|---|
| 「给我做个视频封面」「画个动画风格的壁纸」 | `dsh-video` 让路 | 句中出现明确图片名词 `IMG_NOUN_RE` |
| 「用语音说」「做个视频」但没有图片名词 | `dsh-imagegen` 让路 | `OTHER_MEDIA_RE` 命中且 `EXPLICIT_IMG_RE` 没命中 |

`IMG_NOUN_RE` 刻意**不收**光秃秃的「画」和「画面」——「动画」里就带一个「画」，正是它引发了误判。

**让路 ≠ 对面接得住。** 这两张表还有一个更隐蔽的失效方式：imagegen 让路了，但 voice/video 的意图正则不认这个说法，**结果谁都不接，用户什么都拿不到，而且没有一条日志报错**（每个插件各自的行为都符合自己的规则）。实测踩过三次（「来点声音」「用你的声音夸夸我」等），最后靠 `test_gap.py` 的笛卡尔积断言收干净，详见第五节。改任一侧的意图正则后必须重跑它。

### 3.2 泄漏清理接力

模型偶尔把函数调用当文本吐出来，四个插件都要清。但 `call_event_hook`（`/AstrBot/astrbot/core/pipeline/context_utils.py:78`）就是拿 registry 顺序 for 循环、**没有优先级**——`dsh-video` 最先加载，它一清完，后面的 `imagegen`/`voice` 从 `completion_text` 里再也读不到原文，只能自己重新推 prompt（日志里能看到 `[video] 已清理…` 之后 `[imagegen] 兜底出图` 用的是自己推的词）。

修法是接力：第一个动手的插件把**原文**存进 `event.set_extra("dsh_leak_raw")`，后面的从这儿取原文抠自己那个工具的参数。清理本身幂等，谁跑几次都一样；每个插件只抠自己的参数，但**清理全部六个工具名**。

清理还有一条收尾规则：如果模型整条回复就是一个泄漏标记，清完会变成空串，群里只剩一个光秃秃的 @。所以 `_leak_relay` 在这种情形下回落一句短话（「这就来 / 等着 / 来了」）。放在 `_leak_relay` 而不是纯函数 `_strip_all_leaks` 里，是因为后者还被用来抠 TTS 文本，不该凭空造词。

## 三、人格提示词改动

`data_v4.db` → `personas.qun-by-and-ai`，2296 → **3644** 字。改动只在【工具规则】段和末尾追加的三条硬规则，人设、去 AI 味铁律、AI 味黑名单、贴纸段、语言段全部原样保留（每次改完逐条断言验证，10~16 项自检全过）。

`tools` 白名单：`["generate_image","send_voice","web_search","read_webpage","bilibili_video","generate_video"]`。这个字段在 sqlite 里、不在 `cmd_config.json` 里，且非 None 时**只**放行列表内的名字（`/AstrBot/astrbot/core/astr_main_agent.py` 601-617），新工具不加进去等于没接。

新增的三条硬规则：

```
【不许编】凡是插件给你的东西——图片转述、视频转述、网页正文、搜索结果、B站信息——只能照着说。
如果插件明确告诉你"打不开""读不到""没查到""看不了图""看不了视频"，你就直接说读不了/看不了，一个字都别编。这条比人设优先。

【时政不聊】政治人物、政府会议、国家领导人、涉台涉港涉疆这类话题，一律不聊——不是傲娇，是真的不能聊。
有人问就用你自己的语气推掉（"这个我不聊""换个话题呗"），别复述、别评论、别装作没看见硬答。

【别自己写标记】要调工具就真的调，绝对不许把调用写成文字。下面这些形状一个都不许出现在你的回复里：
- send_voice(text=...)、generate_image(prompt=...) 这种函数写法，加不加引号、加不加反引号都不行；
- <send_voice>要念的话</send_voice> 这种尖括号标签；
- [send_voice:要念的话]、[generate_image:画什么] 这种方括号写法；
- [语音]、[图片]、[视频] 这种自己造的提示标记。
写出来不会变成真的语音或图片，只会以一串乱码一样的文字发到群里，群友只会觉得你出 bug 了。
你能用的方括号标记只有 [贴纸:名称] 这一个，别的方括号一律别写。
```

第三条是本轮实测七种泄漏形态之后补的，详见第五节。它和插件的出口清理是**两道独立防线**：人格让模型少写，清理保证写了也不进群。

工具规则里针对每个工具都写了「什么时候用」和「用完说什么」，例如语音那条明确写「语音会自动发出去，你只用再说一句很短的话，别把语音里的内容再重复一遍」「没人要语音就别发——你平时是打字的，突然开口很怪」；搜索那条补了「有人明说搜一下时插件已经先搜好了，结果在 `<search_context>` 里，别再调一次工具白等」。

## 五、过程中修掉的真实故障

**模型把函数调用当文本吐出来。** 端到端第一次测语音，机器人回的是：

```
喏，听好了哦。

send_voice(text="哼，既然你这么想听，我就勉为其难说一句吧——在的在的，找我干嘛呀？")
```

`tools_call_name` 是空的，语音倒是被兜底钩子发出去了，但**那行 `send_voice(...)` 会原样进群**，而且念出来的是「喏，听好了哦」而不是模型真正想说的那句。

修法与 `dsh-imagegen` 当初处理 XML 泄漏同构，识别三种形态（`send_voice(text=…)` 单双引号、`<invoke name="send_voice">` XML、` ```json {"name":"send_voice"…} ``` `），做两件事：① 无条件把标记从 `completion_text` 里清掉（在所有 `return` 之前，就算不发语音文字也得干净）；② 把抠出来的 `text` 当作真正要念的内容。泄漏的调用本身也被当作「模型想发语音」的铁证，比意图正则更硬。

修后重测，日志变成：
```
[voice] 已清理模型泄漏的伪工具调用标记
[voice] 兜底发语音（抠自泄漏调用）：真是的，这么爱听我说话呀——好啦，小鲸鱼在此，有什么吩咐？
```
进群文字只剩「又来？行吧，听着。」。

后来又抓到第四种形态：`generate_image(prompt=蓝白配色的小鲸鱼，…无复杂背景`——**没有引号、也没有右括号**，正则一个都不认，于是原样进了群。同一次还出现 `web_search(query="…")` 泄漏且搜索压根没跑。所以把清理逻辑抽成一个通用块注入四个插件：`_LEAK_A` 配平括号、`_LEAK_B` 全角右括号、`_LEAK_C` 不闭合（读到空行停）、`_LEAK_D` XML、`_LEAK_E` ```json 块、`_LEAK_FRAG` 残片，`_strip_all_leaks()` 清全部六个工具名，`_extract_arg()` 支持带引号／XML／JSON／裸值四种取值形态。

**清理干净了，但反引号剩下了。** 本轮收尾时的冒烟测试五条里中了两条，群里看到的是：

```
这就来
``
```
```
`` 晚安～
```

模型写的是 `` `generate_image(prompt=…)` ``——用**反引号**把伪调用包起来，`_LEAK_A` 把括号里那段整段清掉，两个反引号就留在了原地。这是「清理逻辑本身有缺口」，比模型泄漏更隐蔽：日志里明明写着「已清理模型泄漏的伪工具调用标记」，看着像修好了。

修法分三层，关键是**不能误伤群友正常发的代码**：① 把可选反引号外壳并进 A/B/C 三个形态，行内 `` `call` `` 和 ` ```call``` ` 一起吃掉，右侧加 `(?![A-Za-z])` 免得吃掉真代码块的开栏 ` ```python `；② 「恰好两个连续反引号」是空的行内代码段、任何正常文本里都不该出现，无条件清——这条同时兜住「前一个插件清完、残渣接力到后一个插件」的情形；③ 单独成行的反引号、以及落单的奇数个反引号，**只在真的清掉过泄漏时**才处理。

当时新建的 `test_fence.py` 有 35 条断言，四个插件各跑一遍（后来随着新形态不断增补，最终 **92 条**）。里面专门有一批反向断言守着不许误伤：`你跑 \`pip install httpx\` 就行`、` ```python\nprint(1)\n``` `、以及「同一条消息里既有群友的正常代码又有泄漏，正常那段必须保住」。改前 8 passed / 10 failed，改后全过，线上复测两条泄漏用例都干净了（「行，画我自己是吧，等着」「晚安啦⭐」），而「pip install httpx 这命令对吗」照样正常回答。

**模型自造伪媒体标记 `[语音]`，进群还被念了出来。** 扩大 e2e 覆盖面（六条更口语的说法）又抓到两条：

```
[语音] 行吧念给你听——某个群友说了，今天谁也别想叫我起床，饭放门口就行。
[语音] 早……才不是特意给你录的，就是刚好闲着。今天也要好好摸鱼啊。
```

两处都脏：**进群的文字**带着 `[语音]`，`[voice] 兜底发语音（念回复原文）` 的日志说明**念出来的内容也带着**。根因是人格教了它一个方括号标记 `[贴纸:名称]`，模型顺手泛化出 `[语音]`/`[图片]`/`[视频]` 当舞台提示写——而这类标记不会变成任何真东西（真语音是插件发的），只会原样进群。

这类「教会一个标记，模型自造一批同形标记」是提示词工程的固有代价，只能在出口清理。`_MEDIA_TAG_RE` 三重收窄防误伤：① 只认**行首**（实测就长在行首）；② 方括号里必须**只**有那个词，`[语音条挺长的]` 这种正常话不动；③ **带冒号的一律不碰**——`[贴纸:嘲笑]` 有自己的处理链、`[At:123]` 是框架的。断言里 8 条正向 + 7 条反向守着，其中「行首的 `[贴纸:装萌]` 也不许碰」是最容易写错的那条。

**第六种泄漏形态：把工具名当标签名。** 再扩大一轮 e2e（六条更口语的说法），「用语音念一段绕口令」出了这个：

```
好嘞，听好了

<send_voice>
四是四，十是十，十四是十四，四十是四十，别把十四说四十，也别把四十说十四。
</send_voice>

怎么样，舌头打结没
```

已有的 `_LEAK_D` 只认 `<function_calls>` 和 `<invoke name="send_voice">`，**裸标签** `<send_voice>` 没人管。这条比其他形态更值钱：标签里包着的就是模型真正想念的话，不抠出来兜底就会去念「好嘞，听好了」——念错内容比不念更糟。所以除了加 `_LEAK_X` 清理，还给 `_extract_arg` 加了「裸标签取内容」的分支（放最后，前面几种形态更精确）。

三轮加起来这么找出四种新形态，说明一件事：**泄漏形态是穷举不完的，只能靠不断换说法实测**。每次扩大 e2e 的说法覆盖面就冒出一种新的。所以 `test_fence.py` 的价值不在于覆盖全，而在于把每次真实抓到的语料原样钉住，改坏了立刻能看出来。

**第七种：`[工具名:参数]`——直接照抄贴纸标记的形状。** 修完裸标签再测一轮，模型换了个更刁的写法：

```
[send_voice:四是四，十是十，十四是十四，四十是四十，…]
[generate_image: 一只可爱的Q版小猫，圆圆的脑袋，…]来了来了。
```

这是 `[语音]` 那条的更深一层：人格教了 `[贴纸:名称]`，模型不只泛化出 `[语音]`，还把**函数调用整个套进这个形状**。上一轮那条「带冒号的一律不碰」正好把它放过了——修一个洞开一个洞的典型。

判据只能是**方括号里的名字是否属于六个工具名**：`[贴纸:嘲笑]` 留、`[At:123]` 留、`[send_voice:…]` 清。名字白名单化之后不存在歧义，也不随模型换说法失效。断言里 5 条反向守着不许误伤，包括 `[备注:明天开会]` 和 `[12:30]`。

**根治那一半：人格里补【别自己写标记】。** 出口清理是补漏，形态一个接一个说明模型偏爱把调用写成人格里已有的形状。原来【工具规则】只写了「不要提到函数名」，模型没把「写成标记」理解成「提到函数名」。所以把四种形状逐条列出来明令禁止，并且给出因果——「写出来不会变成真的语音或图片，只会以一串乱码一样的文字发到群里，群友只会觉得你出 bug 了」，比单纯禁止有效得多。同时说清唯一合法的方括号标记是 `[贴纸:名称]`，免得它以为方括号一律不能用。人格 3293 → **3644** 字，16 项自检全过（含 `tools` 白名单未动）。

**清理与人格是两道独立防线，都得留着。** 人格让模型少写，清理保证写了也不进群——只留一道都不够：清理漏形态时人格能顶一半，模型不听话时清理能兜住。

**第八种，跟前七种不是一类：模型编了个图片网址用 markdown 贴出来。** 第五轮 e2e（八条全新说法），「整个表情包」出了这个：

```
![Image](https://image.pollinations.ai/prompt/cute%20blue%20whale%20girl%20chibi%20sticker%20style%20simple%20line%20art%20flat%20color?width=512&height=512&nologo=true)

小鲸鱼卖萌版表情包，拿去用吧哼。
```

它不是在写函数名，而是**绕过工具自己「生成」图片**——编一个 pollinations.ai 免费图床地址，指望 markdown 渲染出来。三个问题叠着：QQ 不渲染 markdown，这一定是一坨字符进群；那个地址是现编的，插件实际走 Agnes 从没用过 pollinations；而同一条日志里 imagegen 兜底出图**已经成功了**，这坨 markdown 纯属画蛇添足。

所以 `_MD_IMG_RE` 整段删 `![alt](url)`（alt 文字对群友没用），`_MD_LINK_RE` 把 `[文字](https://…)` 降级成纯文字。限定 `http(s)` 开头是为了不误伤别的方括号写法，而 `[贴纸:名称]` 后面没有 `(...)`，正则天然不命中。裸网址故意不清——人格里已经写了「别贴网址」，清理不该越界替它管风格。

**一个不是 bug 的观察。** 同一轮里出现过一条空的 `Prepare to send - 群友B/100000002: `——查 napcat 日志确认那个时刻**没有任何消息发往真群**，是框架内置 `active_reply`（10 % 主动插话）抽中后决定不说话的正常路径，`after_message_sent stopped event propagation` 就是它自己收尾。历史上只出现过这一次，不是回归。

**跨插件空洞：「来点声音」两边都不接。** 第六轮 e2e 抓到一个和泄漏无关、但后果更直接的问题——用户说「来点声音」，机器人只回了句「这就来」，**语音根本没发**。日志给了半个答案：

```
[imagegen] 让路：用户要的是视频/语音而不是图 | 用户=来点声音
```

imagegen 认为这该语音管、让路了；而 `dsh-voice` 的 `VOICE_INTENT_RE` 不认「来点声音」（它只认「来个语音」「念一句」这些）。**于是没人接**，用户什么都没拿到，而且没有任何一条日志说「我不接」——两个插件各自的行为都符合自己的规则。

根因是两张镜像表判据不对称：imagegen 的 `OTHER_MEDIA_RE` 认「声音|音频」这两个裸名词，voice 的意图正则却要求「语音」二字或明确的听觉动词结构。枚举出来共 6 个空洞：来点声音 / 整点声音 / 发点声音 / 给点声音 / 来段声音 / 发个音频。

修 voice 而不是收窄 imagegen——「来点声音」确实是在要语音，让路是对的，错的是 voice 没接住。当时补了两条要求明确给予动词的分支：`(发|来|整|搞|给|弄|放)(点|些|段|个|条|句)?(声音|音频|嗓音)` 和 `录(个|段|一)?音(?![笔机棚室频])`。**这个修法后来证明是错的**（见下），但当时六个空洞确实都堵住了，「这视频没声音」「调大点声音」「录音笔坏了」也都不误触发。

这类洞**单看任一插件的测试都发现不了**，所以新建了一条形状不同的测试 `test_gap.py`：同时加载三个插件，断言镜像表的对称性——「imagegen 让路的每一种说法，voice 或 video 必须有人接住」。

**然后这个洞又复发了两次，才找到正确的修法。** 第十轮 e2e 抓到「用你的声音夸夸我」——同一个洞，只因为上一轮补动词表时想到了「发/来/整/搞/给/弄/放」，漏了「用」。于是把 `test_gap.py` 从手写说法列表改成**笛卡尔积**：动词 × 量词 × 名词 × 后缀全铺开。一跑出来 **1188 个组合谁都不接**。

补「用/拿/使用」之后剩 1104 个，补量词后剩 736 个，补「音频」后剩 384 个——每补一次露出下一批。到这里问题的形状才清楚：那不是几个独立的 bug，而是**三条近似重复的分支各带略有差异的动词表 / 量词表 / 名词表**：

```
(发|来|整|搞|给)       (个|条|段|句)?        语音               ← 缺 弄放用拿、缺「一」
(发|来|整|搞|给|弄|放)  (点|些|段|个|条|句)?  (声音|音频|嗓音)    ← 缺 用拿使用、缺 语音
(用|拿|使用)           (一|两)?(个|段|…)?    (声音|音频|语音|…)  ← 缺 发来整搞给弄放
```

交叉组合必然漏。合并成一条结构化判据（动词表覆盖「给予」和「使用」两类，名词组与 imagegen 的 `OTHER_MEDIA_RE` 对齐）之后 **1892 条全过**。

反向保护靠否定前视 `(?<![别不少没])`：「别用语音」「不用语音」「少用语音」「没声音」都不算在要语音，而「这视频没声音」「调大点声音」的动词（没/调）本来就不在表里。另外「录…音」那条踩了个小坑：量词写成可选，名词「录音」就命中了——「这段录音不错」误触发。改成数词可选、**量词必需**（`录(一|两)?(个|段|条)音`），名词形态全部排除，动词短语一个不漏。

`test_gap.py` 最终 **1892 条断言**，是全部测试里最大的一条，也是唯一一条能不靠 e2e 持续守住跨插件不变式的。教训很直接：**镜像表之间的对称性必须机器验证，手写说法列表一定漏。**

**第九种泄漏形态：把工具名翻译成中文再套方括号。** 第七轮 e2e，「帮我画个头像」出了这个：

```
来了来了

[生成图片: 一个可爱的二次元Q版少女头像，蓝色长发，蓝白配色，闭眼微笑，…]
```

`_LEAK_Y` 只认六个英文工具名，中文译名没人管。`_LEAK_Z` 的判据用**动词开头**而不是枚举译名——方括号里以「生成/发送/调用/播放/合成/搜索/联网/读取/查看/获取/制作/画」开头且带冒号的就是伪调用。这样模型换个说法（「制作视频」「合成语音」）照样命中，而 `[贴纸:嘲笑]`（贴 不在动词表）、`[At:123]`、`[备注:明天开会]`、`[12:30]` 全都安全。同时给 `_extract_arg` 加了中文译名映射表，抠出来的 prompt/text 能直接用。

**「帮我画个头像」的主体被剥成一个「像」字。** 同一轮日志里的另一个问题，跟泄漏无关：

```
[imagegen] 兜底出图（用户要图（模型答应））: 像
```

追 `_derive_prompt`：`帮我画个头像` → 剥掉「帮我/画/个」得到「头像」→ 再剥开头量词 `^(只|条|头|位|…)` → 变成「像」→ `BARE_PIC_RE` 认不出「像」，于是拿一个「像」字去生图。生出来的图凑巧还行（模型答应时会自己补细节进 prompt），但这是运气。

根因是**剥开头量词那一步排在 BARE_PIC 判定之前**：「头像」整体表示「没指定画什么」（该画小鲸鱼自己），却被当成「头 + 像」的量词结构切开了。修法是调换顺序而不是给「头」加否定环视——加环视就得挨个补「条(?!纹)」「位(?!图)」，又是打地鼠。改成先判整句是否只剩图片类词，不是才去剥量词；剥完再判一次（防「画个头照」之类）。

验证覆盖两侧：「帮我画个头像/画个头像/来张头像/给我个头像」四种说法全部回到自画像，而「画只猫→猫」「画头牛→牛」「画位老师→老师」「画个大头娃娃→大头娃娃」「画个头戴帽子的猫→戴帽子的猫」这些真主体一个没吞。这 16 条钉进了 `test_imagegen_reg.py`（34 → **50** 条）。

**第十种，也是最后一种形态：不带参数的裸标记 `[tool_call]`。** 第九轮 e2e，「用你的声音夸夸我」出了这个（顺带把内心独白也说出来了）：

```
text 参数写什么好…… 用户让我夸 TA，那就写一句傲娇但真诚的夸奖，别超过 60 字。

[tool_call]
```

前面九种形态**全都要求有冒号或括号**，这种光秃秃的裸标记一个都没接住。`_BARE_CALL_RE` 收 `tool_call`/`tool_calls`/`function_call(s)`/`工具调用`/`函数调用`/`调用工具`，半角全角都认。

**清理后变成空串——群里只剩一个光秃秃的 @。** 同一轮里「生成个动图」触发了这个：

```
Prepare to send - 测试群友/111222333: [At:111222333]
```

模型整条回复就是一个泄漏标记，清完什么都不剩。图其实发出去了，但配文没了，看着更像 bug。修法是在 `_leak_relay` 里加回落：`raw` 非空而 `cleaned` 为空时随机取一句「这就来 / 等着 / 来了 / 行 / 好嘞」。放在 `_leak_relay` 而不是 `_strip_all_leaks`，因为后者是纯函数、别的地方（抠 TTS 文本）也在用，不该凭空造词。四个插件按加载顺序跑，第一个动手的换成短话，后面的看到 `cleaned == raw` 就不再动，所以不会叠加。

顺带修了「生成个动图」的主体识别——日志里 `兜底出图（用户要图）: 动图`，「动图」被当成画面主体了。它和「头像」一样属于「没指定画什么」，归进 `BARE_PIC_RE`；「画只动物→动物」验证过没被误伤。

**第十一种，不是伪调用而是旁白：模型把机制说出来了。** 第十二轮 e2e，「来张自拍」：

```
喏，刚拍的
（图片自动发给你）
```

图确实发了，这句旁白纯属多余，还暴露实现细节——和 `[语音]` 是同一类问题（模型在描述机制而不是说话）。全历史出现 2 次。

清括号比清标记危险得多，群友和机器人都会正常用括号讲话（「（这图真好看）」「（笑）」）。所以 `_STAGE_NOTE_RE` 三个条件同时满足才清：括号内容 ≤ 14 字 + 含媒体名词 + 含发送动作词（`自动发|已发|发给|发送|附上|见下|在下面|随后发|马上发`）。「（这图真好看）」缺动作词、「（我发链接给你）」缺媒体名词、「（这张图片我已经发到另一个群里给他们看了）」超长，全都留着。

**十一种形态的分布**（都是真实抓到的，不是设想的）：

| # | 形态 | 实测语料 |
|---|---|---|
| A/B/C | 裸函数调用 | `generate_image(prompt=一只猫)` |
| D | XML 风格 | `<invoke name="send_voice"><parameter name="text">…` |
| E | JSON 风格 | `{"name":"generate_image","arguments":{…}}` |
| 反引号 | 上面任意一种被 `` ` `` 包住 | `` `generate_image(prompt=…)` `` |
| 伪媒体标记 | 自造舞台提示 | `[语音] 行吧念给你听` |
| X | 工具名当标签名 | `<send_voice>四是四，十是十…</send_voice>` |
| Y | 工具名套方括号 | `[send_voice:四是四…]` |
| Z | 中文译名套方括号 | `[生成图片: 一个Q版少女头像…]` |
| markdown | 编个图床网址 | `![Image](https://image.pollinations.ai/…)` |
| W | 不带参数的裸标记 | `[tool_call]` |
| V | 旁白说出机制 | `（图片自动发给你）` |

十一种里有八种是**这一轮**才发现的，全靠不断换说法做 e2e。规律很清楚：模型倾向于把工具调用写成**它在提示词里见过的形状**——人格教了 `[贴纸:名称]`，就冒出 `[语音]`、`[send_voice:…]`、`[生成图片:…]` 三种方括号变体。所以每次给模型加新的标记语法，都要重跑一轮 e2e 看有没有新的同形变体。

**视频做出来了却没发出去。** 日志里只有一句空的 `[video] 后台出片异常：`——因为 aiocqhttp 抛的 `ActionFailed` 的 `str()` 是空串，什么线索都没有。挖下去发现 `AiocqhttpMessageEvent._from_segment_to_dict` 只对 `Image`/`Record` 转 base64，遇到 `Video` 是调 `await comp.to_dict()`，而 `Video.to_dict()` 在没配 `callback_api_base` 时原样把**容器内路径**塞进 OneBot 消息。napcat 是另一个容器、没有共享挂载，于是必然：

```
ENOENT: no such file or directory, open '/AstrBot/data/video/xxx.mp4'
```

框架自带的文件服务也走不通：`/api/file/<token>` 从 napcat 请求返回 **404**（那套 token 是给 WebUI 用的）。修法是自己转 base64——`Video(file=f"base64://{b64}")`，和框架处理 `Image`/`Record` 的做法一致。1.3 MB 视频约 1.8 MB base64，`send_private_msg` 正常返回 `message_id`。上限 `MAX_SEND_B64 = 24 MB`（`DSH_VID_MAX_SEND`）。

**「搜一下今天有什么新闻」把整条回复变成一行英文报错。** 群里收到的是：

```
LLM 响应错误: All chat models failed: Exception: API 返回的 completion 由于内容安全过滤被拒绝(非 AstrBot)。
```

探针确认搜索本身成功（5 条结果），问题是「今天有什么新闻」搜出来的全是时政新闻（领导人出访、政治局会议），注入 LLM 请求后上游渠道直接 `finish_reason='content_filter'` 拒绝**整个** completion。这是最糟的失败形状——不是「机器人傲娇地拒绝聊政治」（人设里本来就有这条），而是一行英文报错糊在群里，模型压根没机会说话。

修法是在注入前就摘掉：`SENSITIVE_RE` 逐条判断，还剩干净结果就只注入干净那些；全被摘掉就注入一句说明让模型用自己语气打哈哈；网页正文同样过一遍。四个入口全覆盖（自动搜索钩子、`web_search` 工具、`/搜` 指令、`/看网页` 指令）——后两个不经过 LLM、不会踩 `content_filter`，但机器人自己把时政新闻贴进 QQ 群，对一个已经被打标的号来说是纯风险。

关键词表刻意只收「几乎必然踩线」的那类，**不收**「经济」「疫情」这种正常词——这里的取舍和 imagegen 相反：宁可漏过几条，也不要把正常搜索全废掉。断言里验了 9 个正常话题（「上海房价走势」「新疆棉花产量」「台湾夜市小吃攻略」「疫情后的旅游业」）一个都不误杀。

**出片提交随机 503。** `{"code":"fail_to_fetch_task","message":"litellm.ServiceUnavailableError: … no available server"}`，紧接着手动直连同一接口就 200——上游偶发缺通道，不是参数问题也不是限流。不重试的后果特别难看：用户等几秒收到「视频没做出来，接口那边出问题了」，而再试一次就成了。出片本来就是 3–5 分钟的活，多花二十几秒重试完全值得。`_submit` 拆成 `_submit`（带退避重试）+ `_submit_once`，`_RETRYABLE_RE` 只认 5xx / `no available server` / 超时，4xx（参数/余额/鉴权）立刻放弃。

**其他修掉的**：
- `aiohttp` 的 `content.read(n)` 只返回当前缓冲区，gzip 大页面上只拿到第一块 26 KB，`<article>` 还没出现 → 「抓到了但没正文」。改成 `iter_chunked` 循环读满。
- 拦截页 HTTP 都是 200、正文也有几十字，光看长度分不出来。加特征识别，且**「验证码」这类词只在标题里判，正文里不判**——一篇正经讲验证码的文章不该被误杀。
- DNS 失败和「解析到内网」原来共用一句错误话术，排查时会把两件事搞混，拆成两条。
- 「做个视频封面」「画个动画风格的壁纸」触发了出片。加 `IMG_NOUN_RE` 镜像让路，`test_cross.py` 18/20 → 20/20。
- 「随便说句话」误触发语音——`(说|讲)…(句)…(话)` 这条正则太宽，收紧。
- 「检查一下代码」被当成要联网搜（「检查一下」里含「查一下」），加负向后视。
- **「来点声音」谁都不接**（第六轮 e2e）：imagegen 让路、voice 不认，用户什么都没拿到。共 6 种说法有这个洞，补 voice 意图正则并新建 `test_gap.py` 守住跨插件对称性。
- **「帮我画个头像」的 prompt 被剥成一个「像」字**（第七轮 e2e）：剥开头量词那步排在 BARE_PIC 判定之前，「头像」被当成「头 + 像」切开。调换顺序而非加否定环视。
- **sqlite 备份坑**：`shutil.copy2` 单独拷 `data_v4.db` 拿到的是**过期状态**（WAL 没 checkpoint）——两份这样的备份读回来都是 2810 字，而线上已经 3035/3047 了。改用 sqlite 的 `backup()` API。
- `docker compose restart astrbot` **不会**重读 `env_file`，新加环境变量必须 `docker compose up -d astrbot`。

## 六、安全

`dsh-web` 的 SSRF 防护是这次唯一新增的攻击面处理。群里任何人都能发链接，不设防等于让机器人替他读内网——本机 `172.18.0.2:6185` 就是 AstrBot WebUI。

强制四层：只允许 `http`/`https`；`getaddrinfo` 后要求**所有**解析结果都是公网 IP（私网/环回/链路本地/多播/保留/未指定全拒）；手动跟随重定向且**每一跳重新校验**（防 DNS rebinding 与跳转绕过）；响应体 3 MB 截断 + Content-Type 白名单。实测 `127.0.0.1:6185`、`172.18.0.2:6185`、`169.254.169.254/latest/meta-data/` 全部拦下，且返回内容不泄漏任何内部信息。

**另有一项存量风险需要你处理（本次只查证、未改动）**。实测公网监听如下：

| 端口 | 服务 | 鉴权现状 | 风险 |
|---|---|---|---|
| 6099 | NapCat WebUI | token 只有 **12 字符**，`accessControlMode=none`，`host=::` | 拿到 token 就能操作 QQ 账号：发消息、加好友、导出聊天记录 |
| 6185 | AstrBot WebUI | 账号密码 | 能改人格、改渠道、看全部 API key |
| 6186 | AstrBot 回调 | 无 | 次要 |
| 3001 | NapCat 正向服务 | 见 onebot 配置 | 未使用但开着 |
| 8088 | 扫码/状态页（宿主 python） | **完全无鉴权**，实测 `HTTP 200` | 二维码与账号号码公网可见，谁抢先扫谁就登进这个号 |
| 22 | SSH | 密钥 | 正常 |

其中 8088 最要紧：它就是掉线后用来扫码的页面，二维码直接暴露在公网上。6099 次之——12 字符 token 对公网服务来说太短。建议二选一：阿里云安全组只放行你自己的 IP，或把这几个端口改成只监听 `127.0.0.1` 再用 SSH 端口转发访问。这两项都不是这次接的多模态功能引入的，属于之前就存在的配置。

## 七、已知限制

- **语音识别（STT）做不了**：Fish `/v1/asr` HTTP 402 欠费；智谱 `glm-asr`/`glm-4-voice` HTTP 429「余额不足」，`glm-asr-flash`/`whisper-1` 不存在；`relay-a.example.com` 20 个模型里没有音频模型。群友发语音，机器人只能知道「有人发了条语音」。公告里已明说「听不懂语音，要说话请打字」。
- **生成视频 3–5 分钟**：官方限流 1 请求/分钟。已做成后台任务（工具立刻返回，做完单独发），否则 `session_lock_manager` 会锁住会话让整个群几分钟无响应。全局间隔 75 s + 同群冷却 300 s。提交侧会自动重试 5xx，但上游长时间缺通道时仍会如实报「接口那边出问题了」。
- **看视频是抽帧**，没有声音、可能漏掉快动作。提示词里明说了，让模型别把静态描述当完整剧情。整段传 base64 也能用（18.7 s / 17824 tokens），但抽 4 帧只要 3.5 s / 959 tokens 且描述质量一样。
- **部分中文站点抓不到正文**：微信公众号、掘金、36氪、百家号、微博、知乎、维基百科在香港直连都是验证码/403/前端渲染。这些情况会明确告诉模型「打不开」，并靠 `web_search` 的摘要兜底（智谱每条结果自带约 680 字）。
- **时政话题一律不聊**，且是插件层硬拦（不只靠人设）。原因是上游渠道对这类内容 `content_filter` 拒整条 completion，一行英文报错比不回答更难看。代价是少数正常话题可能被摘掉一两条搜索结果。
- `r.jina.ai` 对这台机器整体 403，不能当 reader 兜底。SOCKS 隧道只对 napcat 生效，astrbot 容器内连不上，不要指望。
- **视频/语音发送靠 base64 内联**，上限 24 MB（`DSH_VID_MAX_SEND`）。5 秒片子约 1.3–2.1 MB，够用；要发大文件得先解决 napcat 与 astrbot 之间的文件共享。
- **模型会自造标记，形态穷举不完**：教它 `[贴纸:名称]` 之后，它泛化出十种伪调用写法（`[语音]`、`<send_voice>…</send_voice>`、`[send_voice:…]`、`[生成图片:…]`、`[tool_call]`、编个 pollinations 图床网址用 markdown 贴……）。全部已在出口清理并钉进 `test_fence.py`，人格里也加了【别自己写标记】，但这类问题**只能靠实测发现**——十种里有七种是反复换说法做 e2e 才冒出来的。凡是给模型加了新的标记语法，都要重跑一轮 e2e。
- **跨插件让路必须机器验证对称性**：`dsh-imagegen` 判断「用户要的是语音/视频」时会让路，但让路不等于对面接得住。「来点声音」「用你的声音夸夸我」都曾出现两边都不接、用户什么都拿不到，且**没有任何一条日志报错**（每个插件各自的行为都符合自己的规则）。手写说法列表漏了两次，最后靠 `test_gap.py` 的笛卡尔积（1892 条）才收干净。以后改任一侧的意图正则，必须重跑 `test_gap.py`。

## 十一、识图模型换成 claude-opus-5（2026-09-02）

### 做了什么

识图（看图片、看视频抽帧）原来只有智谱 `GLM-4.6V-Flash` 一个模型。现在改成三档链条，前两档是朋友站（`relay-b.example.com`）的 `claude-opus-5` 和 `claude-opus-5-thinking`，智谱降为最后兜底：

```
claude-opus-5  →  claude-opus-5-thinking  →  GLM-4.6V-Flash
   主用                  备用                    兜底（异站）
```

三条识图入口全部覆盖，各自的改法不同，因为它们本来就不是同一套代码：

| 入口 | 什么时候用 | 怎么改的 |
|---|---|---|
| 框架转述当前消息自带的图 | 群友发图并 @ 机器人 | `cmd_config.json` 的 `default_image_caption_provider_id` 指向 `vision-opus5` |
| 框架转述被引用消息里的图 | 群友引用一条带图的消息 | 同上（同一个配置项） |
| `dsh-imgctx` 转述前几条消息里的图 | 群友先发图、隔几条才问 | 它的 `DSH_IMGCTX_PROVIDER` 未设 → 自动回落到上面那个配置项 |
| `dsh-video` 视频抽帧识别 | 群友发视频 | 不走 provider 系统（自建 aiohttp），单独改 `DSH_VID_VIS_*` |

### 为什么必须有备用链，而不是直接把配置项改成 opus-5

框架只给了**一个**格子。`default_image_caption_provider_id` 是字符串不是列表（schema `_special: select_provider`），没有「主用挂了换备用」这回事。而这条线路必须有备用：

朋友站在 Cloudflare 后面，带图请求会被边缘节点**偶发弹回 403**（`error code: 1010`）。实测：

| 模型 | 单打成功率 |
|---|---|
| `claude-opus-5` | 10/13、8/10、6/6、3/5 各批次不等，综合约 **77 %** |
| `claude-opus-5-thinking` | 7/10、4/5，约 **75 %** |

也就是说群友每发四五张图，就有一张会换来 `[Image Captioning Failed]`。而框架的 `_handle_api_error`（`openai_source.py:1071`）只对 429、上下文超长、`The model is not a VLM`、内容审核这四种情况做处理，**403 既不重试也不轮换 key，直接往上抛**。

所以新增插件 `dsh-vischain`（`/opt/qqbot/astrbot/data/plugins/dsh-vischain/`）。

### 三个关键设计决定

**① 顶替已有 id，而不是新建一个 id。**

直觉做法是新建 `vision-chain` 这个 provider id 再把配置指过去。但那样插件一旦没加载起来，配置就指向一个不存在的 provider——识图**整条腿断**（框架只打一行 `Provider ... was not found` 然后跳过转述）。

现在的做法是配置照旧指向真实存在的 `vision-opus5`，插件在 `on_astrbot_loaded` 之后把 `provider_manager.inst_map["vision-opus5"]` 换成链条包装器。插件没起来，拿到的就是原装 opus-5 单打独斗（77 %），坏也只坏成「没有备用」。**降级要往「少个功能」倒，不能往「整条断」倒。**

**② 每档先原地重试，再换下一档。**

因为 403 是**瞬时**返回的——实测失败耗时 min/中位/max 全是 0.0 s，边缘节点在收完请求体之前就拒了；而成功一次要 2.4~11 s。所以「主用秒挂 → 重试」几乎不花时间，代价约等于零。实测同模型立刻重试：8 次里 6 次一遍过、2 次重试救回、**0 次三连死**。

**③ 加了看护，因为顶替会被悄悄冲掉。**

WebUI 里改任何一个 provider 都会走 `provider_manager.reload()`：它 terminate 掉旧实例再 load 新的，把 `inst_map[id]` 换成裸实例——顶替就没了。更阴的是改**非第一档**时 `ALIAS` 那格没被碰，但链条手里攥着的是已 terminate 的死实例。这个失效不报错、不打日志，识图照样能用（只是没了备用），靠肉眼永远发现不了。

所以插件每 30 s 按 id 逐档核对身份，发现被换过就地重建，并把战绩接着数（重装清零统计会让 `/识图状态` 骗人）。

### dsh-video 单独改，而且顺手救了一个已经半死的功能

它不走 provider 系统，`dsh-vischain` 管不到；而且它**只有一个模型、零重试**，失败就直接告诉群友「看不了」。

探测时发现智谱免费池已经严重拥堵：`GLM-4.6V-Flash` 连打 8 次成功 3 次，间隔 4 s 打 6 次只成 1 次，全是 429 `code 1305`「该模型当前访问量过大」。也就是说**「看视频」这个功能此前大概率已经是坏的，只是坏得很安静**。

所以给它加了同形状的链条（`_vis_targets()` + `_caption_once()`），并把智谱保留为**异站**最后兜底——主站整片 403 时还有一条独立线路。可重试判定：403 / 408 / 429 / 5xx / 超时重试，400 / 401 / 402 / 404 不重试（参数、鉴权、余额错误重试一百次也是同样结果）。

顺带修了自己引进的一个漏洞：`_caption` 与钩子入口原本判 `if not VIS_KEY`，那样「只配了异站兜底」时会被直接关掉、兜底档形同不存在。改判 `_vis_targets()`。**两条防线不能靠同一个变量决定生死。**

### 验证

| 测试 | 断言/次数 | 结论 |
|---|---|---|
| `test_vischain.py` | **50**（链条 27 + 看护 18 + 配错 5） | 换档/重试/全废抛错/看护重建/配错不崩 |
| `test_vidchain.py` | **33** | 8 个状态码的可重试判定、三档接力、全废报错 |
| `e2e_vis.py`（真实网络） | 10 次 | 第一档单打 77 %（10 成 3 败）→ **链条对外 10/10** |
| `e2e_fallback.py`（真实网络） | 3 场景 | 强制第一档失败 → 第二档接住；前两档失败 → 智谱接住；三档全废 → 如期抛错 |
| `e2e_pipe.py`（整管道） | 7 次 | 假 NapCat 发「@机器人 + 红底白十字图」，回复全部说出画面内容 |
| `e2e_imgctx.py`（整管道） | 1 次 | 只 @机器人问「刚刚那张图是什么」，走 imgctx 回看路径也命中链条 |
| `rt_vidvis.py`（真实网络） | 4 次 | 真视频（红块左→右滑动）**4/4** 读出「从左向右匀速移动」 |

`e2e_fallback.py` 单独存在的理由：`e2e_vis.py` 那 10 次里第一档自己重试就救回了全部 3 次失败，**第二三档一次没被用到**——备用路径不测就等于没有。

`rt_vidvis.py` 踩过一个坑值得记：第一版用 `drawbox` 的 `x='t*90'` 画移动方块，结果四帧全白，模型如实回答「均为纯白空白」，看起来像是模型不行。实际是 `drawbox` 的 `t=fill` 参数和时间变量 `t` 撞了、方块根本没画上。**测试素材本身必须先自检**（现在会数红像素并算横向重心，确认 `[55, 115, 175, 237]` 真的在移动），否则「模型看不懂」和「素材是空的」分不清。

### 顺手量到的其它事实

- **朋友站有巨大的隐藏系统提示词**：trivial 请求的 `prompt_tokens` 就有 6934~7588。识图走它比走智谱贵得多，但这次没有为省钱牺牲效果。
- **浏览器 UA 不能消掉 403**：带 Chrome UA 3/5、不带 4/5，没有区别。之前「加 UA 就通」的结论只适用于裸 `urllib`（openai SDK 自己的默认 UA 本来就不被拦）。所以没配 `custom_headers`。
- **缩图仍然保留**：`dsh-imgctx` 缩到 768 px 原本是为智谱省时间（14.9 s → 1.9 s）。opus-5 的瓶颈在中转站排队而不是图大小（交替测试下 96 px 与 768 px 延迟无显著差异），但缩图仍省 token，无害。
- **`dsh-imgctx` 的 15 s 预算不用改**：它每轮最多 2 张、串行。实测 2 张串行墙钟中位 7.2 s、p90 8.8 s、max 8.8 s，8 轮里 0 轮会被砍。
- **主聊天模型没被影响**：`default_provider_id` 仍是 `bigfeiyu-glm`（`deepseek-v4-flash-0731`），`fallback_chat_models` 仍是 `[]`；新增的两个 provider 只被识图路径引用。发纯文字消息实测仍由 DeepSeek 回答。

### 遗留

- **403 只能靠重试掩盖，消不掉**。它来自 Cloudflare 边缘而不是我们的请求，UA 无效、key 正确。如果哪天成功率跌破 50 %，正确的动作是换站而不是继续加重试。
- **智谱兜底档本身也不健康**（免费池常年 429）。它现在的价值主要是「主站整片挂掉时还有一条独立线路」，别指望它挑大梁。
- `dsh-imgctx` 的转述缓存按 `file` id 存，换模型后旧缓存仍是智谱的描述，会自然过期，没有主动清。
