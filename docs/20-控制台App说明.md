# QQ 机器人控制台 APK

手机上装一个 App，看机器人在不在线、改它的说话频率、一键切换几种预设模式。
包名 `com.dafeiyu.console`，安装后叫「大肥鱼控制台」。

---

## 装

先在手机浏览器打开扫码页登录（就是平时看二维码那个页面）：

```
http://your-server.example.com:8088/
```

登录后，同一个浏览器里打开下载地址：

```
http://your-server.example.com:8088/console.apk
```

会下载 `dafeiyu-console.apk`（约 121 KB）。点开安装，安卓会提示「来自未知来源」——
允许一次即可。要求安卓 5.0 及以上。

> 必须先登录再下载。没登录的话这个地址会返回 401，不是坏了。

装完不用再输一次地址：App 里默认填的就是 `your-server.example.com:8088`，只要输密码 ——
和扫码页同一个密码。

## 三个页签

**状态**。打开就看最上面那条横幅，它只报最坏的一件事：

| 横幅说什么 | 意思 | 该干什么 |
|---|---|---|
| 一切正常 | 在线、工具能用、容器都在跑 | 不用管 |
| 机器人掉线了，二维码已就绪 | QQ 掉了，码生成好了 | 去扫码页扫码 |
| 状态不明 —— 看门狗没更新 | 看门狗本身挂了，下面的数据是旧的 | 看下面「看门狗」那节 |
| 工具能力异常 | 配置里 `tool_use` 丢了 | 见下面「嘴上答应却不发图」 |
| 内存快满了 | 服务器只有 1.9G | 重启机器人容器能回收一些 |

横幅下面按「越可能出事的排越前」列：QQ 状态 → 二维码（只在掉线时出现）→
两个容器 → 模型 → 工具能力 → 当前模式 → 插话设置 → 插件 → 代理 → 主机资源。

最下面三个按钮是操作：重启机器人、重载环境变量、重启 QQ 客户端。
**重启 QQ 客户端会掉线并换二维码，大概率要重新扫码**，点之前会问一次。

**配置**。整页**由服务器下发的 schema 动态生成** —— 滑块、开关、下拉、文本框、
逗号分隔列表都认。改完按「保存改动」，只提交你真改动过的项，
所以拖了滑块又拖回原位不会白写一次配置。

这一页现在有 104 个旋钮，分两类：

| 类别 | 存哪 | 什么时候生效 |
|---|---|---|
| 框架配置（插话概率、上下文轮数、限流…） | `cmd_config.json` | 保存即生效 |
| 插件开关（`env:DSH_*`，22 个插件） | `imagegen.env` | **要按一次「重载环境变量」** |

第二类会在界面上标「改完要重启才生效」。原因是 astrbot 容器的环境变量来自
docker compose 的 `env_file`，容器内的 `os.environ` 只在**容器重建**时才更新 ——
`docker restart` 不重读 `env_file`（这个坑踩过）。所以「重载环境变量」按钮跑的是
`docker compose up -d astrbot`。

写 env 有三条硬约束，都由服务端兜住，手机上不会碰到：

1. **布尔一律写 `1`/`0`。** 22 个插件对布尔有 4 种解析写法，其中 11 个变量用
   `!= "0"` 判定 —— 写 `false` 会被当成**开**。
2. **数值必须在范围内。** 除 `dsh-memory` 外，`int`/`float` 填非数字或留空会让插件
   在 import 时抛异常，**整个插件加载失败**（不是回落默认值）。所以每个数值旋钮都带
   min/max，越界服务端直接 400，不做静默钳制。
3. **写文件保留注释与顺序。** `imagegen.env` 里的注释记着每个值为什么这么设，
   比变量本身值钱，所以走行级替换 + 原子替换 + MD5 冲突检测，而不是读成 dict 再写回。

**7 个敏感变量**（画图/语音/视频/搜索的 API key 和音色 ID）只报「已设置 / 未设置」，
真实值一个字节都不出服务器，手机端也改不了 —— 8088 是明文 HTTP。

**模式**。七个预设，点一下改一批参数：

| 模式 | 干什么 | 什么时候用 |
|---|---|---|
| 🤫 安静 | 只在被叫到时回，关掉主动插话 | 群里嫌它吵 |
| 🙂 日常 | 插话 25%、留 40 轮、限流 8 条/60 秒 | 默认状态，调好的那套 |
| 🔥 活跃 | 插话概率翻到 50%，限流放到 16 条 | 群里冷清 |
| 💰 省钱 | 识图换智谱直连、聊天用最便宜的 flash、历史砍到 20 轮 | 想省钱 |
| 🧠 强力 | 聊天换 glm-5.3、识图走 opus-5 三档链、历史 60 轮 | 要它聪明点，慢一些 |
| 🔇 闭嘴 | 彻底不说话但 QQ 保持在线，关掉所有媒体插件 | 需要它闭嘴但别掉线 |
| 🎨 全媒体 | 出图/语音/视频/联网四个插件全开 | 想让它能发东西 |

「闭嘴」刻意不停 napcat 容器 —— 停了要重新扫码，代价比闭嘴大得多。

模式切换会同时改配置、模型、插件三样。如果其中一步失败（比如渠道方接口抖了），
App 会明确告诉你「哪一步失败、原因是什么」，而不是笼统说一句失败 ——
避免你反复点，越点越乱。

## 遇到问题

**「登录过期了」**。凭据 7 天有效，过期重新输一次密码。

**「有人同时在网页后台改了配置」**。这是保护机制：写配置前会核对文件指纹，
对不上就拒绝，防止把网页后台刚保存的改动覆盖掉。下拉刷新后重新改一次。

**「服务器上的控制台后端没起来」**。后端模块加载失败了。这时候扫码页仍然能用
（这是特意设计的：扫码页比控制台重要，掉线时它是唯一的补救入口）。
在服务器上跑 `systemctl status qqbot-qrweb` 看日志。

**「服务器返回的是网页而不是数据」**。服务端补丁没生效，需要重新部署。

**「连不上服务器」**。8088 是唯一开放的端口。检查服务器在不在跑、
手机有没有网。填地址时不要写成 `https://` —— 那个端口只有明文 HTTP。

**看门狗停摆**。看门狗每 10 秒写一次状态，超过 60 秒没动，App 就把 QQ 状态显示成
「不确定」而不是相信里面的「在线」。这不是保守 —— 之前真出过一次事：
QQ 静默掉线时 NapCat 什么日志都不打，页面绿了整整一小时。
遇到这个跑 `systemctl restart qqbot-watchdog`。

**嘴上答应却不发图**。根因是配置里 `provider[].modalities` 少了 `tool_use`，
框架会**静默**丢掉整个工具集（只打 debug 日志，线上看不见）。
状态页的「工具能力」那行专门盯这个，缺了会标红。它还会看最近一小时真的调用过没有 ——
配置对但一小时零调用，那是可疑而不是正常。

## 关于安全

**8088 是明文 HTTP，没有 TLS。** 密码在网络上不加密传输。
这是这个服务本来就有的限制（安全组只放行了 22/6099/6185/8088，加不了新端口，
也没有域名证书），不是 App 引入的。在家里或数据网络下用没什么问题，
在公共 Wi-Fi 上要意识到这一点。

**App 里不存密码。** 只存服务器地址和服务器签发的登录凭据（7 天自动失效）。
凭据丢了别人最多能看状态、改配置，拿不到密码本身。

**App 里没有任何密钥。** 不含 SSH 私钥，也不含任何模型 API key ——
所有配置改动都是 App 请求服务器、服务器自己去调 AstrBot 后台完成的。
（旧的那个 `com.release.console` 把 SSH 私钥打进了 assets，这次刻意没走那条路。）

**权限只要两个**：联网、读网络状态。不读通讯录、不读存储、不要位置。

**能改什么是白名单定死的。** 当前 104 个旋钮，每一个都在 `console_spec.py` 里显式列出。
密码、管理员列表、渠道方 API key、平台账号配置，以及 7 个敏感变量的真实值，
一律不在其中 —— 不是隐藏起来，是服务端直接拒绝，返回 403。
`platform_settings.reply_with_mention` 也故意不收录：@ 只能由 `dsh-mention` 决定，
放出这个全局开关只会制造两条互相打架的 @ 逻辑。

## 服务器上放了什么

```
/opt/qqbot/console_api.py            控制台后端逻辑
/opt/qqbot/console_spec.py           能力清单（104 旋钮 / 22 插件 / 7 模式 / 3 动作）
/opt/qqbot/envfile.py                imagegen.env 的行级安全写入器（保留注释与顺序）
/opt/qqbot/qrweb_auth.py             扫码页服务，已打补丁挂上控制台
/opt/qqbot/public/dafeiyu-console.apk  给手机下载的安装包
/opt/qqbot/qrweb_auth.py.bak.console.*  打补丁前的备份（保留最近 5 份）
```

框架配置改动**从不直接写 `cmd_config.json`**，而是走 AstrBot 后台的 API
（`127.0.0.1:6185`），和你在网页后台点保存走的是同一条路。所以改完立即生效、
不用重启容器，也不会把配置文件写坏。插件开关是另一条路：直接改
`imagegen.env`（行级替换，保留全部注释），然后由「重载环境变量」重建容器。

## 加功能要不要重装 App

**大多数时候不用。** 这个 App 不写死界面，它按 `/api/console/schema` 返回的东西渲染，
认不出的旋钮**跳过而不是崩**。所以：

| 在服务器上做什么 | 手机要做什么 |
|---|---|
| 在 `console_spec.py` 加旋钮 / 模式 / 动作 / 插件中文名 | 下拉刷新就出现 |
| 用到 App 已认得的类型（`bool` `int` `float` `enum` `str` `csv`） | 下拉刷新就出现 |
| 新增一种**渲染方式**（比如以后要画时间选择器） | 才需要更新 APK |

App 启动时会顺手问一次 `/api/console/version`（只 stat 一个文件，很便宜）。
服务器上的包 `versionCode` 比手机上这个新时，弹一次提示、点「打开下载」跳浏览器 ——
**不静默下载、不静默安装**。理由是 8088 是明文 HTTP，在这条链路上自动装包不可控。

更新 APK 必须用**同一枚签名密钥**，否则安卓会拒绝覆盖安装（只能先卸载，那样会丢
已保存的服务器地址和登录凭据）。

重新部署或回滚：

```
cd <console-repo>
bash deploy.sh              # 部署 + 18 项实测
bash deploy.sh --verify     # 只验证，不改服务器
bash deploy.sh --rollback   # 回滚到最近一个备份
```

重新出包：

```
bash build.sh               # 出签名 APK 到 build/dafeiyu-console.apk
bash test/run-tests.sh      # 391 项纯 JVM 单测，不用模拟器
python3 server/test_console.py     # 105 项后端单测（假 dashboard，不碰真服务器）
python3 server/test_qrweb_e2e.py   # 83 项端到端（真起 HTTP 服务）
```
