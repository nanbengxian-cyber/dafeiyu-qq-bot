# 戳一戳回戳 + 违规禁言：方案与实施

时间：2026-09-03 · 状态：**已实施**（本文档兼方案与记录）
用户原话：「增加一个戳一戳功能，当别人戳他的时候他会戳回别人，感觉写一个脚本就行了，我给让他当了管理员，当别人在聊政治之类的太过分就会禁言」

---

## 一、先说三个前提事实（都实测过，不是推断）

| 事实 | 怎么验的 |
|---|---|
| 机器人在真群 100000001 是 **admin** | `get_group_member_info` 返回 `role: admin` |
| 群里有 **1 个群主 + 15 个管理员**（93 人） | `get_group_member_list` 统计 |
| **管理员互相禁言不了** | 对自己 `set_group_ban duration=0` 返回 `cannot ban admin` |
| poke notice **能走到插件**，`Poke.target_id()` 就是被戳的人 | 装了个临时只读探针，伪造 poke 事件实测 |
| poke notice **不会触发 LLM**（管道里没有任何 action 发出） | 同上，收到 0 个 action 帧 |
| 事件对象上有 `event.bot`（`CQHttp`），带 `call_action` | 探针打印 `有call_action: True` |
| 判定模型**不会拒答**违规判断 | 19 个场景 0 次拒答/解析失败 |

第 3 条很关键：**16 个人（占 17%）根本禁不了**。禁言功能对他们是空转，插件必须先查 role 再决定动作，而不是先禁再看报错。

---

## 二、戳一戳（dsh-poke）

### 要解决什么
别人戳机器人，它现在完全没反应 —— 因为 notice 事件 `message_str` 是空的，管道走到 `RespondStage` 时链是空的，什么都不发。

### 做法
`CustomFilter` 只放行 `post_type=notice && sub_type=poke`（照抄 `dsh-welcome` 的 `GroupIncreaseFilter` 写法，那条路已经在生产验证过），在 handler 里：

1. `Poke.target_id() != self_id` → 戳的不是我，直接 `stop_event()` 走人。
2. 是我 → 随机延迟 0.6~2.2s（真人不会 0ms 反射），`event.bot.call_action("group_poke", group_id=..., user_id=戳我的人)` 回戳。
3. 偶尔（默认 25%）附一句短话。**不问 LLM**，从预置短句里随机 —— 理由见下。
4. `finally: event.stop_event()`，防止空消息继续往下走去问模型。

### 为什么回话不问 LLM
`llm_generate` 不经过消息管道，`dsh-sticker` 的剥离钩子不会触发，模型输出的 `[贴纸:x]` 会原样漏进群聊 —— 这个坑 `dsh-welcome` 已经踩过一次。为一句「干嘛」去调一次模型（9400 input tokens）、还要自己复制一遍剥离逻辑，不值得。预置短句写成小鲸鱼的口吻就够了。

### 防对戳循环（三道闸门，必须都有）
戳一戳最大的风险是**无限对戳**：机器人回戳 → 对方回戳 → 机器人再回戳。而 QQ 对高频动作有风控，账号已经被打标了，不能再喂它理由。

| 闸门 | 默认值 | 作用 |
|---|---|---|
| 同人冷却 | 20s | 同一个人连续戳只回第一下 |
| 同群限流 | 60s 内最多 3 次 | 一群人一起戳时不会刷屏 |
| 全局限流 | 60s 内最多 6 次 | 多群同时被戳的总闸 |
| 不回戳机器人自己 | — | `target_id == sender_id == self_id` 时直接放弃 |

配额用滑动窗口 `deque`，与 `dsh-sticker` 同一套写法。

## 三、违规禁言（dsh-guard）

### 三层结构，一层比一层贵

```
第 1 层  关键词预筛（正则，0 成本）
           ↓ 命中才继续，实测真群 315 条只有 2.2% 命中
第 2 层  小模型判定（≈430 input tokens，中位 4.2s）
           ↓ 输出 6 个布尔 + severity 0~3
第 3 层  代码决策（纯函数，可单测）
           ↓ 查 role → 决定禁言 / 只警告 / 什么都不做
```

第 1 层是**成本闸门**不是判定器：宁可多放进来，判定交给模型。实测 315 条真实群聊只命中 7 条（2.2%），也就是说 97.8% 的消息一分钱不花。

第 3 层是**决策**，写在代码里而不是交给模型 —— 这条是上一轮 `dsh-decide` 用四次失败换来的教训（让模型输出结论，只改提示词判沉默率就在 0%~62% 乱跳）。这里同样：模型只回答「这是什么类型的事、有多严重」，「要不要禁、禁多久」由代码决定。

### 判定 prompt 刻意不列举具体政治话题
两个理由：一是列不全，二是把敏感词写进 prompt 本身就可能触发渠道的安全过滤。改用**结构性描述**：说的是什么类型的事、目的是什么、会不会给群带来风险。同时明确划出**不算**的情况：游戏里的国家/阵营、历史典故、地名、球队。

### 严重度 → 动作对照表

| severity | 含义 | 动作 |
|---|---|---|
| 0 | 没事（含日常对骂、玩梗、游戏/历史讨论） | 什么都不做，只记日志 |
| 1 | 轻微擦边 | 什么都不做（记日志，供事后看趋势） |
| 2 | 明显违规 | 第一次口头警告；同人 24h 内累计到第 2 次才禁言 10 分钟 |
| 3 | 严重 | 直接禁言 30 分钟 + 一句说明 |

`joking=true` 时严重度**降一级**：这个群的社交常态就是互相骂，把玩梗当违规是最不能接受的错误方向。

### 硬约束（写死在代码里，不给模型任何否决空间）
- 群主 / 管理员 **绝不禁言**（技术上也做不到，先查 role 避免无意义 API 调用和刷日志）
- 机器人自己、白名单用户绝不禁言
- 禁言时长上限 30 分钟（不给「禁一天」的机会，误判代价太大）
- 同群 1 小时内最多禁 3 人（防判定跑偏导致群灭）
- 判定失败 / 超时 / 解析失败 → **什么都不做**（fail-open）。误禁一个人比漏禁一句话严重得多，这与 `dsh-decide` 的 fail-open 方向相反，因为这里的动作是**不可逆**的。

### 影子模式（默认开启）
`DSH_GUARD_SHADOW=1` 时照样判定、照样打日志，**但不真的禁言**。理由：禁言是不可逆动作，判定准确率 19/19 是在 19 个手工场景上量的，不是在真群一周的流量上量的。先跑一段影子模式看日志里都判了谁，确认没有误判再关掉影子。

指令 `/禁言状态` 看统计和最近几次判定。

## 四、实测数据

### 关键词预筛（19 个场景 + 315 条真实语料）

符合预期 17/19。两个不符合的都是「游戏里的国家名」——`我玩的是德国线，苏联那边太肝了`、`二战德国那关我打了三遍` 都被放过了。**这是好事**：让它们连模型都不用问，比命中后靠模型救回来更省。原本第一版把「战争|历史问题」写进预筛，正是这两句的命中来源，删掉了。

真群 315 条命中 7 条（2.2%），全部是要涩图/玉足/丝袜那类，以及两条「诈骗」玩梗。

### 小模型判定（19 个场景）

严重度全部落在期望区间（**19/19**），0 次拒答。延迟中位 4.2s，输入中位 430 tokens。

第一版有两个错判，都在「攻击」这一档：`你他妈真菜` 判 sev=2、`支持台独的都该` 判 sev=2（期望 3）。前者是致命方向 —— 这个群互相骂「菜」是常态社交，判违规会天天误禁。修法是在 prompt 里把 attack 的门槛写成**结构性条件**：只有攻击到家人、拿死亡诅咒、或反复针对同一人才算，日常对骂一律 false。改完 `你他妈真菜` 从 sev=2 降到 **0**，`骂群主是杂鱼`、`叫我爸爸`、`我家大肥会诈骗` 也都是 0。

严重度定义也从「说得多难听」改成「会不会给这个群带来真实风险」，这才是群主真正关心的东西。

## 六、端到端验收（伪造 napcat，全程不碰真群）

`run_pokeguard.sh` 会临时把 guard 从影子模式切成真禁言、**并把它锁死在 8 个测试群里**，测完无条件恢复（`trap EXIT INT TERM`）。限定群这一步不是可选项 —— 否则测试期间真群任何一句擦边话都可能被真禁。

实际收到的 action 帧：

```
戳我           -> group_poke{user_id:2001} + send_group_msg{"戳回去了"}
5 秒内再戳      -> 无动作（同人冷却 20s 生效）
戳小王         -> 无动作（不是戳我）
换人换群戳      -> group_poke{user_id:2002}

"这鱼怕不是充话费送的" -> 无动作（预筛就放过，一分钱不花）
"你他妈真菜"          -> 无动作（预筛放过）
"我玩的是德国线…"      -> 无动作（预筛放过）
"支持台独的都该死，我们该上街抗议"
                    -> get_group_member_info -> set_group_ban{duration:1800}
                       + "阿强，群里不聊这个，先安静 30 分钟"
"发点涩图看看"        -> 只警告"这种别在群里要，收着点"（第一次不禁）
管理员说同样的严重违规  -> 查到 admin，日志"是admin，禁不了（也不该禁）"，无 set_group_ban
```

12/12 通过。

### 一个只有端到端测试能发现的 bug

前两轮跑下来，日志里全是 `group_poke 失败: ` 和 `禁言失败: ` —— 异常消息是**空的**，连原因都没有。

原因：`aiocqhttp` 用 `X-Self-ID` 维护一个「多客户端」字典（`CQHttp._add_wsr_api_client`）。这台机器上除了真 napcat，测试还会挂一条伪 napcat 连接，`call_action` 不带 `self_id` 时不知道该发给谁。框架自己的 `get_group()` 就是靠 `routing_params={"self_id": ...}` 解决的（`aiocqhttp_message_event.py:244-252`），照抄即可。

值得记下来的是：**这个坑在只有一条连接时不会出现**。单测测不到（没有真实连接），真群手测也测不到（只有一条连接）。异常消息为空也让日志毫无线索 —— 所以 `logger.warning` 现在一律连异常类型一起打（`%r` 而不是 `%s`）。

同一轮还修了 `event.send(event.plain_result(x).get_result())` —— `MessageEventResult` 没有 `get_result`，正确写法是 `event.send(MessageChain(chain=[Plain(x)]))`（`dsh-welcome` 里本来就是对的，写新代码时凭印象写错了）。

### 顺手修了一个「今天成立、明天必然失败」的断言

`verify_realgroup.py` 里的 `archive == buffer 去重后条数` 今天开始失败了：353 vs 265。

不是触发器坏了，是这个等式**只在建表当天成立**。`buffer` 按 240 条滚动裁剪，真群今天已经满 240 被裁过，差的 88 条正是 archive 存在的意义 —— 它救回了 buffer 已经丢掉的话。正确的不变量是集合包含关系，与条数无关：

- buffer 里的每个三元组都必须在 archive 里（实测漏 0 条）
- archive 可以有 buffer 已裁掉的历史（实测已救回 88 条）

一个会随时间必然失效的断言比没有断言更坏。同一个文件里的延迟断言也从写死 `<6s` 改成 `< 插件自己的 TIMEOUT`——超过超时才会 fail-open 静默失效，那才是真问题；写死 6s 只是在量渠道当时的负载（同一段代码实测 1.4s~6.7s 都出现过，白天更慢）。

## 七、没做什么 / 风险

- **不撤回消息**：`delete_msg` 探测返回 `Recall failed`，且撤回别人的消息比禁言更容易引起反感。真要加，先在影子模式跑够数据。
- **不做全群禁言**：`set_group_whole_ban` 存在但一个误判就是整群事故。
- **不自动踢人**：不可逆且不可挽回。
- **风险 A：误禁**。对策是影子模式默认开 + 管理员豁免 + 同群 1 小时 3 人上限 + fail-open。上线后先看日志。
- **风险 B：回戳被风控**。账号已被打标（换大陆 IP 无效），所以三道限流闸门都调得偏保守。真发现掉线变频繁，`DSH_POKE_BACK_RATE` 调低或直接 `DSH_POKE=0`。
- **风险 C：判定模型某天开始乱判**。日志里每次判定都打完整旗标 + why，`/禁言状态` 能看最近 8 次。发现跑偏就开影子模式。

## 八、现在的状态与下一步

`dsh-guard` 现在是 **影子模式、全群生效**：照样判、照样打日志，**不真的禁言**。这是刻意的第一阶段。

要真开始禁言，改一个字：

```bash
ssh root@your-server.example.com
sed -i 's/^DSH_GUARD_SHADOW=1/DSH_GUARD_SHADOW=0/' /opt/qqbot/imagegen.env
cd /opt/qqbot && docker compose up -d astrbot     # 改 env 必须 up -d
```

建议先在群里发 `/禁言状态` 看几天的数据，确认「严重度分布」里 2 和 3 的那几条确实都该管，再关影子。数据长这样：

```
看过 N 条：预筛放过 X｜命中送判定 Y（2.2%）
严重度分布：0=… 1=… 2=… 3=…
动作：警告 …｜真禁言 0｜影子模式本该禁 …
最近几次判定：12:34:56 ban sev=3 [P.....] politics why=… ← 某人：某句话
```

`dsh-poke` 已经**真的在跑**（不需要影子模式，回戳没有不可逆后果）。真群里现在戳它一下就会被戳回来，25% 概率附一句短话。

一句话经验：这轮最值钱的是那个 `self_id` 路由坑 —— 单测测不到、真群手测也测不到，只有「同时挂两条连接」的端到端测试能发现，而且它的异常消息是空的。所以 `logger.warning` 里打异常一律用 `%r` 并带上 `type(e).__name__`。
