## 一、先纠正上一批的一个判断

上一批我把「你咋变这么乖了」记成「不成立／只是观感」，这一批**查到底了，它成立，
但原因不是"乖"**。

### 现场（群 100000001）

```
18:30:32  时髦啊: [引用消息(大肥鱼: 那地方我不去了)] [At:100000003] 摸摸
18:30:35  机器人: 摸吧摸吧
18:30:54  霓虹殊华: [引用消息(大肥鱼: 摸吧摸吧)] [At:100000003] 抱抱
18:31:01  机器人: 抱吧抱吧
18:31:45  霓虹殊华: [At:100000003] 你咋变这么乖了
```

「摸吧摸吧 / 抱吧抱吧」这一对，当天在 **12:23、17:19、18:30、18:31** 各出现一次 ——
**输入什么形状、输出就什么形状**，连着两次一字不差。破绽不是"顺从"，是**模板化**：
群友只要发「XX」，回复就一定是「X吧X吧」。这就是一眼看出是程序的地方。

### 先量一遍，别拍脑袋

统计当天 276 条机器人发言：

| 指标 | 数量 | 占比 |
|---|---|---|
| 以顺从词开头（好/行/可以/来吧…） | 8 | 2.9% |
| 含拒绝/反驳词（不行/不给/别找/滚…） | 7 | 2.5% |

**两边基本持平** —— 所以「变乖」不是全局倾向，不用去调 `dsh-agency` 的人格权重
（那才是容易改坏的地方）。真正可复现的缺陷只有那个短句模板。

## 二、修复 3：短句复读抑制（dsh-selfguard）

### 根因

`repeat_of()` 抓不到它们，两个原因叠加：

1. **`MIN_LEN = 5`**，而「摸吧摸吧」只有 4 个字 —— 第一条就被挡在检测之外；
2. **`DSH_SELFGUARD_REPEAT=0`**（群主 2026-09-12 关的）。

第 2 条要小心：**群主关掉的是「这茬刚聊完／已经聊过／刚说过」那条不耐烦话术，
不是"允许自己一句话说两遍"**。所以不能简单把开关打开。

### 改法

新增一条**独立于 `REPEAT_ON`** 的极短句通道（`SHORT_ECHO_ON`，默认开）：

* 只针对 **≤6 字**的短句，**整句完全相同**才算（不用子串/bigram —— 短句本就短，
  「行吧」和「来吧」共用一个「吧」，模糊匹配必然误伤）；
* 命中后**不说任何关于重复的话**，只把说法换掉（`_SHORT_VARIANTS` 给了
  摸吧摸吧／抱吧抱吧／行吧行吧／好啊好啊／来吧来吧／算了算了 六组变体）；
* 没有现成变体时返回空说法，表示**这条别重复**，让模型换一句；
* 换过说法的那句也要记进 `_recent`，否则下一轮又会被判成"没说过"；
* 改文本用逐段改 `Plain.text`（与 `dsh-aiflavour` 一致），不自己构造 chain，
  免得丢掉 @/图片等非文本段。

`/自制力状态` 与启动日志都加上了这个开关的状态，否则以后翻日志看不出补丁在不在。

### 真实语料回放（防误伤）

把当天**真实发出去的 276 条机器人发言**按顺序喂进这条通道：

```
276 条 -> 只有 1 条会被处理：「画好了」->（本条不重复）
```

零误伤。这也顺带说明这条通道的触发面很窄，不会把正常短回话换掉。

## 三、修复 4：语音失败时固定话术（dsh-voice）

### 现场

```
03:01:05  机器人 -> 是个口舍子: [At:3784150815] 这句先没念出来，换个说法或者稍后再试
03:03:40  是个口舍子: [引用消息(大肥鱼: …这句先没念出来，换个说法或者稍后再试)] [At:100000003] 为什么😢妈妈
03:28:47  机器人: 同上，一天里第二次发同一句
03:29:54  是个口舍子: [引用消息(大肥鱼: …同)] [At:100000003] 为什么😢
```

群友两次把这句话引用回来问「为什么😢」。它两头不讨好：既不像人话（真人不会
汇报自己发没发出去），又像是在把责任推给说话的人。

### 根因

不是模型乱说 —— `send_voice` 工具的**返回值里直接写明了「告诉用户这一句没念
出来、让他换个说法或稍后再说」**，模型逐字照搬。凡是"指定台词"的指令，
模型几乎必然照抄。

### 改法

* 失败时**不再指定台词**，只给约束：「改发文字；不要提语音、审核、超时、通道
  这类词，也不要让用户换个说法或重试 —— 直接把原本想说的那句话用普通文字短句
  发出来，就像一开始就没打算发语音。」（真人的做法就是这样：语音没成，那句
  话就用文字说了）
* 内容被审核拦下时单独一条：明确「这段内容也不要发出来」，不能诱导它照发；
* `err` 原文继续不进 prompt（以前出现过模型照抄「发不出声音：审核通道超时」）。

## 四、顺手修掉一个长期假绿

`dsh-voice/test_censor.py` 里有一条断言写死了冷却文案
`"慢点，还有 20 秒冷却"`，但实现早就改成从 `_COOL_POOL` 随机挑了（那句因为
"真人不会说冷却"、且曾是全群最高频固定句被废弃）。

后果是**这个测试长期是红的**（对着线上未改版一样红），而长期红的测试会把它后面
真正的回归一起淹掉。改成断言「属于话术池」+「不含『冷却』『秒』这类机器词」后
27 项断言 3/3 通过。

## 五、核查记录

* **各跑 3 遍全过**：`test_selfguard.py`、`test_short_echo.py`、
  `test_fail_phrasing.py`、`test_censor.py`（27 项）、
  `test_emotion_auto.py`、`test_emotion_tier.py`、`test_send_failure.py`
* **双端 md5 一致**：selfguard `db4bfa0c…`、voice `cd7a8ab0…`
* **既有测试对照**：`test_selfguard.py` 在改前（镜像 HEAD）与改后**都通过**，
  确认没有改坏；`test_censor.py` 修断言前后都是同一份实现行为
* **变异测试**（5 个，全部被抓住）：

  | 变异 | 结果 |
  |---|---|
  | 关掉短句通道（默认 `"0"`） | 失败：`短句复读抑制默认没开` |
  | `SHORT_ECHO_LEN` 降到 3 | 失败：`整句重复没被识别: '摸吧摸吧'` |
  | 改用「这茬刚聊完了」当回复 | 失败：`出现了群主讨厌的话术` |
  | 去掉"整句相同"限制、退化成模糊匹配 | 失败：`不同短句被误判成重复: '行吧' vs '来吧'` |
  | `SHORT_ECHO_LEN` 降到 2 | 失败：`整句重复没被识别: '摸吧摸吧'` |
  | 换成旧那句"指定台词"的返回 | 失败：`要求里还在提「没念出来」` |

  > 其中**变异①第一次是假绿**：把开关默认改成 `"0"` 后测试仍然全过，
  > 因为测试只调纯函数、没检查开关本身。补上 `assert SHORT_ECHO_ON is True`
  > 之后才真正变红。这是这一轮"反复核查"抓到的第二个假绿。

* **重启后健康**：60 插件加载、0 Traceback、0 ERROR、机器人正常回话；
  启动日志已显示 `短句复读抑制=开(≤6字整句相同就换说法)`
