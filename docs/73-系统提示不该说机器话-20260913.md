## 一、先摆正方向：重复不在"聊天"里，在"系统提示"里

量「套路话术」时先量了整体重复度：

| | 条数 | 唯一率（整条） | 2 字组唯一率 | 3 字组唯一率 |
|---|---|---|---|---|
| 大肥鱼 | 10149 | 75.1% | 32.2% | 56.0% |
| 真人 | 11483 | 87.0% | 27.7% | 55.2% |

**整条唯一率它低（75% vs 87%），但 n-gram 唯一率两边持平甚至它更高。**
说明它的**聊天内容并不比真人单调**，重复集中在少数几条固定长句上。去看高频榜：

```
大肥鱼： [引用消息] 133× / 慢点，还有 N 秒冷却 114× / 秒冷却 103× / [At:…]
         发不出声音：这句话不太适合念出来，换一句嘛 60× / 你是群主（QQ …），可以用：32×
真人：   ？174× / 神了 89× / 😋 64× / 🤔 51× / 来个妹妹 45× / 6 / 666 / 对
```

**真人的高频全是聊天反应；机器人的高频全是系统提示。** 所以"更不像人"的地方不在
人设 prompt，在这些机器话术上。本轮治其中最突出的一条。

## 二、动手的那一条：`慢点，还有 N 秒冷却`

- **114 次**，是机器人重复次数最多的**真文本**（不含泄漏）；
- **2026-09-12 一天 34 次**，09-13 00:48 还在发 —— 完全活跃；
- 触发者多为群友敲 `/说话`（少部分 `/画图`）；
- 它是一句**冷冰冰的限流公告**："冷却"是游戏/软件词，真人不会说"冷却"。

**最讽刺的一次**（2026-09-13 00:48:00）：

```
怪企鹅(下线版): /说话 有这么难吗？唉，你，真的是      ← 他在抱怨语音难用
大肥鱼        : 慢点，还有 6 秒冷却                 ← 机器人回了句机器公告
```

### 改法：换成人话 + 必须有变体

```python
_COOL_POOL = ("急啥，一个一个来", "别催，让我缓口气", "刚念完，等一下嘛",
              "马上，这就好", "来了来了", "稍等会儿")   # dsh-imagegen 用画图版
```

四个设计决定：
1. **去掉"冷却"和秒数倒计时**。"再等 6 秒"是机器给的精度，人只会说"等会儿"。
2. **保留"现在不行、等会儿"的意思** —— 删掉提示的话群友会一直敲，反而更糟。
3. **必须有变体，且不连着重复**。只换成另一句固定的话，过两天它自己就成了**新的
   口头禅** —— 那等于把问题挪个位置。这条是本轮最重要的一条经验。
4. **两个插件的池子不共用**（只重 3 句）—— 否则全群只听到同一套话。

机制一行没动（还是 `_notice_allowed` 90s 去重 + `COOLDOWN` 限流），只换文案。

### 池子不是编的：这些话它本来就在聊天里说

选完池子后回查全量日志，机器人在**正常对话**里早就在用这套调子（7 条实证）：

```
来了来了，刚才在画图…        这尾巴得排队 急啥        凌晨省电呢 别催
别催，人家乐意再发           这会儿真出不了图 别催嘛   别催，服务器正喘气呢
```

所以这个改动的实质是：**把它在对话里已经会说的调子，拿回到系统提示上用** ——
而不是给模型灌一套新口吻。同一句"别催"，聊天里说得出，限流公告里却说
"还有 6 秒冷却"，这个落差本身就是机器味的来源。

### 测试

`plugins/dsh-voice/test_cool.py`：**真跑命令处理器**（不是比字符串），把冷却拉满、
绕过 90s 去重闸门，连调 12 次：

```
dsh-voice（/说话）：12 次冷却 → 6 种说法，无连着重复
dsh-imagegen（/画图）：12 次冷却 → 6 种说法，无连着重复
COOL_LINE_TEST_OK
```

它同时断言"不含『冷却』『秒』"——防止日后有人把机器词加回去。

## 三、四个差点让我改错东西的度量陷阱（本轮主要教训）

本轮一共**否掉了四个改动方向**，全都是"指标本身错了，不是机器人错了"：

### 陷阱 1：时区——宿主是 UTC，日志是 UTC+8

排查时发现第一轮修掉的 dsh-memory 长括号「（每 10 条消息、间隔 15 分钟才整理一次）」
**在日志 `09-13 00:12:30` 还在发**。但：生产 `main.py` 已是新文本、pyc 是新版编译的、
两边 md5 一致、容器内路径只有一份。所有证据都说"修好了"，只有日志说"没修好"。

真相：宿主 `date` 是 UTC，日志是 UTC+8。我部署的时刻是**宿主 Sep 12 16:59 = 日志
09-13 00:59**，而那句长括号是**日志 00:12:30**——**比部署早 46 分钟**。修复没问题，
是我的时间轴整体错了 8 小时。

> **判据**：任何"宿主文件 mtime vs 日志时间"的比对，先算时钟偏移。
> `stat` 给的是 UTC，日志写的是 UTC+8。

### 陷阱 2：拆组件——`Prepare to send` 是每条 result 一行，多段 `Plain` 用空格连接

一度量出"机器人 11.75‰ 的消息有多余右括号（`）`）而真人只有 0.38‰，31 倍"。
但那些样本长这样：`我记住的你（9/12` 和 `条）：` —— **本来是同一条消息**，
被我按空格拆成了两条。**按整条重算：机器人 0 条，真人 7 条，倍率 0×。**

> **判据**：跨段才能配对的量（括号、引号、成对标记）**必须用整条原文**；
> 只有单段口径的量（长度、句式、词频）才拆空格。我此前为了词频口径统一拆空格，
> 直接把这条误用到括号上。

### 陷阱 3：说话人集中度——"群文化"可能只是一个人的癖好

同一次重算发现真人**大量用孤零零的左括号 `（` 收尾**（`可你自己不就是AI吗（`、
`你一天多少伙食费（`）：真人 18.36‰ vs 机器人 2.03‰，**真人 9 倍**。看着像"群友的
书写习惯，机器人不该缺"。

按说话人拆开：**306 人里只有 9 人（3%）用过**，而 **CKpad 一个人占 306/338 = 90%**
（他自己 51.9% 的消息都这么写）。**那是一个人的个人癖好，不是群文化。**
学它等于在模仿某个具体群友，比不学更怪。

> **判据**：任何"全群语料统计出的风格差异"，先按说话人拆一遍。
> 集中在一两个人身上 = 个人习惯，不要当成群体规范往模型里灌。

### 陷阱 4：条件化——"它老反问『谁』"其实是它真的不认识人

从今天的回复里肉眼看到一串「谁…」式反问（`谁问你了`/`砍谁 我？`/`亲谁啊`/`教谁啊`/
`谁说我睡了`/`谁睡了`/`给谁查？`），60 条里 13 条。整条统计：机器人 13.99‰
vs 真人 1.62‰，**8.6 倍**。看着是个很硬的句式套路。

但**先看实例**：`院长是谁`、`大红是谁`、`要看谁的档案`、`我连她是谁都没认出来` ——
全是**内容上该问的**。机器人看不见脸、对不上号，**它真的不知道"谁"是谁**；
真人不需要问。压掉这个句式只会让它**更不准**，不是更像人。
（另外 136 种说法 / 139 次 —— 几乎没有重复，本来就不算"套路话术"。）

> **判据**：句式类指标要**先看实例再下结论**。"高频"和"错"是两件事；
> 有些高频正是能力差距造成的**正确**反应。

## 四、顺带修掉的：测试往生产日志灌东西

docs/71 结论 7 记录过这个坑（插件测试 `import astrbot.core` 会把 AstrBot 的文件
sink 挂到生产日志上），当时的办法是"测完用 `logger.remove()`"——**但那是事后补救**：
本轮的测试实测在生产日志留下了两条 `Added llm tool: send_voice`（行 34490/34492），
因为污染发生在 import 期，`remove()` 已经太晚。

**真正的堵法：在 import 之前把 `loguru` 的 `Logger.add` 换成空操作。**

```python
from loguru import logger as _lg
_LGR = type(_lg); _ADD = _LGR.add
_LGR.add = lambda self, *a, **k: 0     # 挡住 AstrBot 挂文件 sink
try:
    import dsh_voice_main as V
finally:
    _LGR.add = _ADD
```

验证：测试运行前后生产日志行数 **34493 → 34493（差 0）**。
以后所有插件测试都该用这个写法，`logger.remove()` 那套可以退休了。

## 五、查清但**不需要改**的一处：`发不出声音：审核通道超时`（93 次）

全量日志里 `发不出声音：…` 出现 93 次，形态是：

```
Prepare to send - CKpad/778933351: [At:778933351]  发不出声音：这句话不太适合念出来，换一句嘛
Prepare to send - 怪企鹅/3864614070: [At:3864614070]  发不出声音：审核通道超时
```

带着 `[At:…]`，是对**点名它的人**的直接回答，内容是"审核通道超时"这种内部机制 ——
和 docs/72 的报错泄漏是同一类，而且更频繁。

**但它在当前源码里已经不存在了**（只剩注释）：这是模型**照抄工具返回里的内部原因**
造成的，第一轮改动已经把 `err` 原文从口播素材里摘掉，改成只给模型一句"用自然口语说
这一句没念出来，不要提审核/超时/通道/provider"：

- 最后一次出现：**2026-09-12 22:06**；部署（09-13 00:46）之后 **0 次**；
- 新文案「这次声音没送出去，等一下再试试」历史上 **0 次**（那条路径还没触发过）。

**残留风险已记录为待办**：现在的写法仍然把 `（内部原因：{err}）` 交给模型，只是
叮嘱它别说。约束模型不做某事，可靠性天然低于不给它这个信息。属"未触发、无法证伪"，
本轮不动。

## 六、可复用的结论

1. **"机器人重复"要分层看**：聊天内容（几乎正常）vs 系统提示（明显机器）。
   治之前先用 n-gram 唯一率证明是哪一层，别直接改人设。
2. **换掉一句话术时，必须同时给变体。** 否则新句子过两天长成新的口头禅，
   问题只是换了个字符串。
3. **指标不可信的概率，比机器人出错高。** 本轮四个方向全是口径错：
   时区、拆组件、说话人集中度、未条件化。**先证明"这个口径量的是我以为的东西"。**
4. **跨段量必须用整条，单段量才拆空格。** 别把一种口径无脑推广到另一种。
5. **风格差异先按说话人拆一遍**，一个人 90% 就说明是个人癖好。
6. **句式类指标先看实例**，高频可能是"能力差距导致的正确反应"。
7. **测试的日志污染要在 import 前堵**，不是事后 `remove()`。
8. **改措辞前先查它自己怎么说话。** 本轮池子的 6 句全都能在它**已有对话**里找到
   同调子的实例（见第二节）——"把它已经会说的调子搬回系统提示"，比"给它一套新口吻"
   可靠得多，也不会造成人设漂移。

  改成只给"失败了、请用一句自然口语告诉用户"（见第五节）。当前 0 触发，改不改都不
  影响现状，属于加固。
- **还有两条高频机器话术没治**：
  * `你是群主（QQ …），可以用：…` 32 次 + `条）：` 41 次 —— 这是权限/能力说明，
    机器味最重的形态（把参数摊给群友看）。
  * `在画了，稍等十几秒…` 9 次 —— 措辞已经算人话，但**固定**且带预估秒数，
    可并入本次的变体写法。
- **验证新文案真的出现在生产**：需要群友敲 `/说话` 或 `/画图` 触发冷却。
  日志里 grep `急啥|别催|刚念完|刚画完|笔还没干|来了来了|稍等会儿|这就好` 即可。
- **`[At:…]  + 两条空格 + 正文`** 这个形态本轮出现多次（`[At:778933351]  发不出声音：…`）
