# 74 · 群事件感知（含撤回）与「谁戳的我」

日期：2026-09-13
插件：`dsh-awareness` 1.1.0（生产 `/opt/qqbot/astrbot/data/plugins/dsh-awareness`，镜像 `plugins/dsh-awareness/`）

## 1. 需求

> 「他现在的认知还不够仔细，比如说群友发了什么撤回了什么等，但是认知太多又不行，做一个类懒加载的认知。」
> 「你看群里，他现在连谁戳的他都不知道，需要修」

两件事同一层：**机器人要记得住群里的细碎事实，但不能为此每轮塞一大坨上下文。**

## 2. 类懒加载怎么分层的

| 层 | 内容 | 成本 | 触发条件 |
| --- | --- | --- | --- |
| 索引 | 「最近30分钟：消息N条/M人，图片X、撤回Y、戳一戳Z」 | 174 字/轮（实测） | 每轮 |
| 明细 | 逐条「谁在几点说了什么」，撤回条目带原文 | +269 字，硬顶 700 字 | 被@、群主发问、或话里出现 刚才/撤回/谁说的/还记得 |
| 戳一戳 | 「谁（昵称+QQ）戳了你；你已经回戳过对方」 | ~130 字 | 被戳后 10 分钟内每轮 |

对比：`dsh-selfaware` 每轮 1844 字，本插件常驻增量约 +174 字（≈ +9%）。闲聊不展开正文，这正是「认知太多又不行」的解法。

## 3. 撤回是怎么记住的

OneBot 的 `group_recall` 通知**只给 message_id，不给正文**。所以每条消息入库时缓存 `message_id`，收到撤回时回查还原：

```
实测（2026-09-13 00:58）
00:58:13 怪企鹅：你讲话风格比较一版一眼     ← 打错字
00:58:16 怪企鹅：[撤回]
00:58:20 怪企鹅：你讲话风格比较一板一眼     ← 重发
→ 插件记录 原文='你讲话风格比较一版一眼'（含撤回者/原发送者/原种类）
```

本地没留存到的（超出保留窗或机器人当时不在），照实记「原文没留存下来」，**不编内容**。

## 4. 事故：连谁戳的他都不知道

### 现场

```
01:30:53  我叫萌新地狱(2187671056) 戳了机器人
01:30:55  机器人回戳 +「有事说事」
01:31:10  我叫萌新地狱：[引用(大肥鱼:有事说事)] [At:机器人] 没事就想戳戳
01:31:14  机器人：戳谁呀？                        ← 完全对不上话
```

### 根因（两层，缺一不可）

1. **平台侧**：poke 通知的正文是空的，`message_str = ""`；而 AstrBot 的
   `_convert_handle_notice_event` 把 sender 昵称**硬编码成 QQ 号**
   （`nickname=str(event.user_id)`）。所以 LLM 拿不到任何可读身份。
2. **插件侧**：`dsh-poke` 的 `build_probe_feedback_prompt(kind, target_id)`
   **收了 `target_id` 却从未使用**，正文只有「对方回戳了你」——一个没有指代的「对方」。

于是被戳时既不触发 LLM 轮次（只有回戳动作），十几秒后群友 @ 它时，那一轮上下文里**完全没有「谁戳了我」**，只能反问。

### 修法（在 dsh-awareness 里做，不动 dsh-poke）

- 采集 poke 通知：`user_id`=戳的人、`target_id`=被戳的人、`self_id`=机器人；
  被戳的是机器人时标 `to_me`。
- **昵称补全**：poke 通知只带 QQ 号，用该人**历史发言的昵称**回填
  （实测补成「我叫萌新地狱」而不是 `2187671056`）。
- 注入 `<poke_awareness>`：明确写「谁（昵称+QQ）戳了你一下」，并标注
  「你已经回戳过对方」（靠机器人自己的 poke 上报判断），省得它答「那我也戳回去」。
- 别人互戳、与我无关时不注入（零开销）。

## 5. 热重载踩坑（运维必读）

新插件和改 `imagegen.env` 都必须重建容器（`docker restart` **不重读 env_file**）：

```bash
cd /opt/qqbot && sudo docker compose up -d astrbot
```

但**重新部署插件代码本身不必重启**，可用 dashboard 的官方重载接口：

```bash
# dashboard 密码在 cmd_config.json 里是 pbkdf2/sha256 哈希，
# /opt/qqbot/observe/reload_plugin.py 的明文登录会 401。
# 替代：用服务自己的 jwt_secret 签一个临时 token（不改任何配置）
sudo docker exec -i astrbot python - <<'PY'
import json, time, urllib.request
import jwt
d = json.load(open('/AstrBot/data/cmd_config.json', encoding='utf-8'))['dashboard']
t = jwt.encode({'username': d['username'], 'exp': int(time.time()) + 600},
               d['jwt_secret'], algorithm='HS256')
r = urllib.request.Request('http://127.0.0.1:%d/api/plugin/reload' % int(d.get('port') or 6185),
                           data=json.dumps({'name': 'dsh-awareness'}).encode(), method='POST')
r.add_header('Content-Type', 'application/json')
r.add_header('Authorization', 'Bearer ' + (t.decode() if isinstance(t, bytes) else t))
print(urllib.request.urlopen(r, timeout=90).read().decode()[:200])
PY
```

**陷阱**：AstrBot 重载只清 `data.plugins.*` 命名空间。插件里用**顶层模块名**
导入的辅助模块（本插件的 `event_ring`）会留在 `sys.modules`，于是新版 `main.py`
导入到旧模块，报 `cannot import name 'render_poke_note'` **并把插件搞掉线**。
修法是在导入前 `sys.modules.pop("event_ring", None)`（已落在 `main.py`）。


备份：`/opt/qqbot/backups/dsh-awareness-pre-20260912-165703/imagegen.env.bak`、
`/opt/qqbot/backups/dsh-awareness-v1.0-20260912-173721/`。

## 7. 验证

- 纯逻辑单测 8 组（`test_event_ring.py`）+ 容器内假事件集成测试 5 组（`test_awareness_integration.py`）全过，
  含「重复 message_id 不入库」「别群不注入」「敏感不落库」「别人互戳不注入」「未留存照实说」。
- 生产实测：撤回捕获 12 条；索引 174 字/轮、明细 443 字/次（被@时）。

## 8. 遗留

- `dsh-poke` 的 `build_probe_feedback_prompt` 仍未使用 `target_id`，主动试探场景下
  仍只说「对方」。该场景有对话上下文兜底（能推断是谁），优先级低于已修的「被戳」场景。
- `dsh-initiate`（主动话题）尚未消费本事件环，可让主动话题引用「群里刚发生的事」。
