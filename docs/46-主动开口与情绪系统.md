# 46-主动开口与情绪系统

> 2026-09-04 上线。三个新插件：`dsh-initiate`（冷场主动开口）、`dsh-emotion`（单一主情绪）、
> `dsh-quote`（引用消息改写），外加一个已存在半天的真实崩溃修复。
> 本文按「症状 → 量化测量 → 真因 → 修复 → 验证」记录，包括走错的路。

## 一、冷场主动开口（dsh-initiate）

### 症状

群里安静下来它就一直安静，除非有人先说话。人类群友会自己起话头，它不会。

### 两条可选路线

| 路线 | 做法 | 问题 |
|---|---|---|
| A：直接调 LLM 再 `event.send` | 绕过消息管道 | 贴纸标记不剥离、@ 策略不生效、分段发送不生效 —— `dsh-welcome` 已经为此重复过一份剥离逻辑 |
| **B：造合成事件丢进完整管道** | 构造 `AstrBotMessage` → `platform.create_event` → `commit_event` | 需要摸清框架内部构造，但所有既有钩子自动生效 |

选 B。代价是要核对框架内部 API，收益是不用为每个新入口重复一遍剥离/限流/@ 逻辑。

核对过的调用链（全部在容器里实际验证）：

```python
message = AstrBotMessage()          # 普通类，不是 dataclass
message.raw_message = Event.from_payload({...})   # aiocqhttp
event = platform.create_event(message)
event.set_extra("dsh_initiate", True)
platform.commit_event(event)        # 同步方法，不是协程
```

`AiocqhttpAdapter.handle_msg` 就是 `commit_event(create_event(message))`，照它的形状抄最安全。

### 五道闸门，全过才开口

| 闸门 | 值 | 为什么 |
|---|---|---|
| 冷场时长 | ≥ **15 分钟** | 低于这个还在正常对话节奏里 |
| 冷场上限 | ≤ **6 小时** | 超过就是话题彻底凉了，硬接会很怪 |
| 活跃时段 | **10:00–02:59**（上海） | 见下方直方图 |
| 同群冷却 | **1 小时** | 防止连续自言自语 |
| 每日上限 | **3 次** | 主动发言的边际收益递减很快 |

时段不是拍脑袋定的。本群 1276 条历史消息按小时分布：

```
21:00  235   ████████████████████
15:00  180   ███████████████
22:00  157   █████████████
20:00  138   ███████████
00:00   90   ███████
01:00   70   █████
23:00   64   █████
...
07:00    1
08:00    2
03:00–09:00 几乎空白
```

在 03:00–09:59 开口等于把消息发给空气，所以整段排除。

### 判断只做感知，决策留给代码

小模型只回答「有没有值得接的话头」这类**事实**，`should_initiate(facts)` 这个纯函数负责否决。
这是 `dsh-decide` 用四次失败换来的教训：让模型直接输出结论，只改提示词判沉默率就在 0%~62% 乱跳。

**任何判断失败、超时、解析不出来，一律沉默。** fail-closed 而不是 fail-open ——
主动开口说错话的代价远大于不说话。

### 兼容补丁

合成事件会被三个既有插件误处理，各打一处补丁：

| 插件 | 问题 | 补丁 |
|---|---|---|
| `dsh-decide` | 会对合成事件再判一次「要不要插话」，但那是「插进正在进行的对话」的判断，此刻没有对话 | 见到 `dsh_initiate` 直接 return |
| `dsh-ctxclean` | 两档 `<reply_context>` 都在描述「有一句话」，而这一档根本没有那句话，落到「自己插话」会让模型去找一句不存在的话 | 新增第三档 `_INITIATED` |
| `dsh-mention` | 会把合成事件记进「谁在跟我说话」，并可能插 At | 两处都跳过 |

合成消息的 `message` 列表是**空的**，这带来两个额外好处：框架的 `has_context_content`
（只认 `Plain | Image | Json`）为假，所以不会污染群聊上下文记录、也不会触发内置主动回复；
图片处理钩子同样不触发，避免了「没要求生图却生图」那类误触发。

## 二、情绪系统（dsh-emotion）

### 需求原话

> 情绪系统会受到记忆、言语等影响，每次受到外部条件只触发一种情绪，触发完受到某种条件就会清零。

三个硬约束：**受记忆和言语影响**、**一次只有一种**、**有清零条件**。

### 状态模型

六种情绪，同一时刻只有一种：`calm` `happy` `sad` `angry` `curious` `awkward`。

```python
{
  "emotion": "angry", "intensity": 3, "source": "message",
  "started_at": ..., "expires_at": ...,
  "evidence": "触发它的原话", "reset_conditions": [...],
  "neutral_run": 0, "directed": True,
}
```

模型不能写入任意情绪，只能从固定集合里选；脏数据一律经 `normalize_state` 收敛成合法状态。

### 一条消息只触发一种：固定优先级仲裁

```
清零 > 生气 > 低落 > 好奇 > 开心 > 尴尬
```

「你好厉害，但也真让我失望」这种既夸又贬的话只取一个结果（低落）。
「牛逼，你谁都想对着干呗，有病」这种夹阴阳判生气而不是开心 —— 攻击优先于赞美。

### 清零四条路

| 方式 | 条件 |
|---|---|
| `explicit_reset` | 道歉/澄清（「对不起」「我说错了」「误会了」），优先于一切新情绪 |
| `neutral_run` | 连续 **2 条**无情绪信号的真人消息 |
| `answered` | 好奇状态下收到强度 ≥2 的非提问消息 |
| `ttl_expired` | 生气/低落 1800s，开心 900s，好奇/尴尬 600s |

清零**不能只靠 TTL**：真人生气被道歉了会立刻消气，不会硬撑半小时。

### 影子模式回放揪出的两个真误判

第一版跑真群 1618 条历史（`archive` + `buffer`），触发 38 次。逐条看样本发现两处硬伤：

**误判一：把「余额」当尴尬。** 9 次尴尬命中里 8 次是子串误伤：

```
我的余额还有120多
担心这个，还不如担心我的额度够不够
作者要饿似了，所以暂时不给我额外额度了
```

词表里有「额」，于是「余额」「额度」「额外」全中。修法：语气词类信号只在
**整条消息就是它本身**时才算（`^[额呃啊哦]{1,4}[。.!！~]?$`），
并给每种情绪配排除词表（`_EXCLUDE`）。这是「结构判断优于枚举词表」的又一次验证。

**误判二：没有「针对谁」的判断。** 38 次命中里 25 次整句既没有「你」也没喊名字：

```
为什么我这么菜          ← 自嘲，不是在问机器人
为什么不发语音          ← 在问别人
他昨天特别难过          ← 讲第三方
```

修法：攻击类**必须**有指向证据（有「你」/喊名字/@ 它）；提问必须同时有疑问结构和指向；
没有指向的只当环境氛围，强度压到 1，且不覆盖更强的既有情绪（`kept_stronger`）。

### 修完之后的回放对比

| 指标 | v1 | v1.1 |
|---|---|---|
| 触发次数 | 38 | 23 |
| 尴尬误判 | 9（8 个是余额/额度） | 0 |
| 生气 | 2（含无指向裸「闭嘴」） | 1（「你倒是先闭嘴」） |
| 平静占比 | — | 1580 / 1618 |
| 最长连续同一情绪 | — | 开心 5、好奇 3、生气 2、低落 2 |

**没有任何情绪卡住下不来** —— 这是上线前最需要确认的一条。

### 走错的一步

第一次修「提问」时把疑问正则收成 `^(?:为什么|怎么|真的吗)`，只锚定句首。
结果 `curious` 从 14 次直接掉到 **0** 次 —— 群里最常见的追问是「那你为什么没有」，
疑问词在句中。这是漏判不是修好。改回句中匹配，但仍要求配合指向证据。

**教训：命中数归零不等于误判修好了，必须逐样本看。**

## 三、引用消息改写（dsh-quote）

### 症状（用户原话）

> 大肥鱼好像看不懂别人引用的聊天，错以为是自己修复

### 真因

框架 `astr_main_agent._process_quote_message` 拼给模型的块只有这么多：

```
<Quoted Message>
(大肥鱼): 30块确实不贵
</Quoted Message>
```

三处致命缺失：

1. **没说这句是不是它自己说的。** 它的群名片就是「大肥鱼」，而群里还有一个**真人**
   也把昵称改成了「大肥鱼」。凭昵称在这个群里本来就认不了人。
2. **没说现在是谁在引用。** 只有被引用者，没有引用者，于是
   「A 引用 B 的话说了句什么」被压平成「有人说了 B 的话」，主谓宾就错了。
3. **没说这次 @ 的是谁。** @ 了别人时它照样当成在对自己说话。

### 修法

在 `on_llm_request` 里把那块整块换掉（顺序已核对：`_process_quote_message` 在 build 阶段，
`OnLLMRequestEvent` 在其后触发），改成用 QQ 号说清关系：

```
<quoted_message>
这条消息引用了之前的一句话。引用的内容是**旧的**，不是刚刚发生的新消息。
· 现在说话的人是 「安」（QQ 385909xxxx）。
· 他引用的那句话是 「大肥鱼」（QQ 149320xxxx） 说的，【不是你说的】：「教官真是太逊了」
· 也就是说，这是他们之间的对话，你只是看见了。别把它当成你做过的事或你说过的话。
· 这次他 @ 的是 「群主」（QQ 277400xxxx），不是你。
</quoted_message>
```

拿不到被引用者 QQ 号时**不猜**，只说「分不清是谁说的，别假设是你自己」。

标签用小写 `<quoted_message>` 与 `dsh-ctxclean` 的结构判断对齐，
并加进它的 `_NEVER_DROP` —— 语义和框架原块一致（描述这条消息本身，不是一轮性注入）。

### 顺带修的一个坑

清理引用原文开头的 `@昵称(QQ号)` 时，贪婪正则会吃掉正文。真实样本：

```
@群主对        ← At 和正文之间没有空格，正文只有「对」一个字
```

贪婪切之后正文为空，退化成「（空消息）」，比不切更糟。
改成：正则只在 @ 后跟 `(QQ号)` 或空白时才切；优先从消息**组件链**里精确剥离 At
（`At` 组件自带 `qq` 字段，不用猜昵称边界）。

## 四、顺带修掉的真实崩溃

`dsh-decide` 合并「机器人自己说过的话」时按两元组解包三元组：

```python
_rows: list[tuple[str, float, str]] = []       # (显示名, ts, 文本)
...
newest_ts = max(ts for _n, ts in _rows)        # ✗ ValueError
newest_ts = max(r[1] for r in _rows)           # ✓
```

只要机器人最近说过话（`_own` 非空）就必抛 `too many values to unpack (expected 2)`，
整个判断落到 fail-open「照旧说话」。

**当天实测：崩 12 次，成功判定 9 次。** 也就是说超过一半的发言，
模型根本没收到 `to`（这句是谁对谁说的）这条判断 —— 这正是「主谓宾弄错」的直接原因。

这个 bug 一直被 fail-open 掩盖着：功能看起来正常（机器人照样说话），
只是说得不对。**fail-open 让崩溃变成了静默的质量下降。**

## 五、验证

### 单元测试

```bash
python3 plugins/dsh-emotion/test_emotion.py    # 36 项
python3 plugins/dsh-quote/test_quote.py        # 25 项
```

`test_emotion.py` 分三组：A 组 17 项抽取规则（**把上面所有真实误判样本锁成断言，防回退**）、
B 组 12 项状态机与清零、C 组 7 项脏数据收敛与注入块形状。

`test_quote.py` 分四组：A 组 6 项 @ 剥离与组件链、B 组 8 项只认 QQ 号的身份判定
（含同名真人场景）、C 组 4 项 @ 指向、D 组 7 项块形状与边界。

两份测试都用 AST 摘纯函数执行，不导入 `astrbot`，所以能在任何机器上跑。

### 真实语料回放

```bash
python3 plugins/dsh-emotion/replay_emotion.py [插件路径]
```

在容器里读 `dsh_memory.db` 的 `archive` + `buffer`，统计触发分布、清零原因分布、
情绪占比、最长连续同一情绪、可疑样本。**这个脚本是发现上面两个误判的唯一手段** ——
单元测试只能验证你已经想到的情况。

### 上线过程

1. 影子模式部署，`DSH_EMOTION_SHADOW=1` / `DSH_INITIATE_SHADOW=1`；
2. 观察真实群消息的审计日志（`dsh_emotion_events.jsonl`），确认状态文件**没有**被写入；
3. 回放历史，逐样本看误判；
4. 修完再回放对比；
5. 单元测试锁死所有已知误判样本；
6. 改 env 切到真生效，用 `docker compose up -d`（`restart` 不重读 `env_file`）。

## 六、可复用的教训

1. **fail-open 会把崩溃伪装成质量下降。** `dsh-decide` 崩了半天没人发现，因为机器人照样说话。
   凡是 fail-open 的兜底，**必须**在兜底路径上打 WARN 级日志并计数。
2. **命中数归零不等于误判修好了。** 收紧规则后 `curious` 掉到 0，看着像「不再误判」，
   实际是全漏了。任何规则改动都要逐样本对比，不能只看总数。
3. **影子模式的价值在于回放，不在于等。** 光挂着跑一晚只能看到当晚那几条；
   拿历史语料回放 1618 条，两个误判 20 分钟就暴露了。
4. **凭昵称认人在群聊里永远是错的。** 昵称可以随时改，也可以重名 ——
   这个群里就有真人把名字改成和机器人一样。身份判定只能用 QQ 号。
5. **状态机的清零条件要和触发条件一起设计。** 只给 TTL 的情绪系统不像人：
   真人被道歉了会立刻消气。每种情绪都得有自己的清零事件。
