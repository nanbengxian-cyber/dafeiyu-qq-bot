# 74 · 机器人口癖：把「大半夜的」从一个口头禅变成学会不说的词

**日期**：2026-09-13
**改动**：`dsh-aiflavour` 1.0.0 → 1.1.0（新增"口癖层 TIC"）
**结论先说**：这是我在第 2 轮**判错**的一个方向——当时我把它归为"习惯用词、聚簇很弱"，
数据后来推翻了它。口癖不在系统提示里，在**它自己的聊天内容**里，所以第 3 轮
"重复全在系统提示"那个结论要补一句限定。

---

## 一、怎么发现的：一句没被回答的请求

翻机器人最近的回复、逐条配上前文，最有代表性的一对：

```
01:22:02  邓仕杰: 你给我说一句晚安吗？我要睡了，睡前想听你说
01:22:14  大肥鱼: 大半夜的
```

两个毛病同时在：**① 没回答那个明确的请求；② 回复是个没有谓语的碎片**
（"大半夜的"单独成句，读起来像一句抱怨/敷衍）。而这个碎片，正是它当晚的第 N 次。

---

## 二、量化：71 倍，而且一小时内 8 次

| | 次数 | 占比 | 备注 |
|---|---|---|---|
| 大肥鱼 | **21** | 3.54‰ | |
| 真人 | **1** | 0.05‰ | 且是「大半夜刷到有福了」—— 另一种句式 |

**71 倍**。分布（按小时）：

```
09-04 16:1  09-05 15:1  09-06 03:1  09-07 00:3  09-07 01:3  09-07 02:1
09-12 23:1  09-13 00:8  09-13 01:2
```

`09-13 00` 点**一个小时 8 次**，而且 15 分钟内同一句式四连：

```
00:32  妈什么妈，大半夜的
00:33  大半夜的，谁是你宝宝
00:34  谁是你宝宝啊 大半夜的
00:36  亲什么亲 大半夜的
```

**这就是"复读机"的样子。** 第 2 轮我看到的最密集是"一小时 7 次"，当时判断
"聚簇很弱、属习惯用词"—— **那个门槛定错了**。一小时 8 次、15 分钟四连，
群里任何一个真人都能听出来。

---

## 三、根因：不是人格示范，是模型习惯 + 自我强化

**先排除了人格提示词**。翻出生产人格（`personas.system_prompt`，6987 字）查"半夜"，
只有 1 处：

```
- 你没有身体，但「自己是跑在服务器里的 DeepSeek 娘」这件事本身就能玩：
  吃 token、烧钱、余额见底、半夜被群主拽起来改代码、被换模型。
```

**这是描述它自己的处境，不是叫它说"大半夜的"。** 所以不是人格教出来的。

真正的机制更可能是一个**自我强化回路**：`req.contexts`（会话历史，`dsh-ctxclean`
保留最近 30 轮）里装着它自己刚说过的话。它一旦说了两三次「大半夜的」，
历史里就堆着这几次，**模型把"自己最近的样子"当成自己的口吻，继续照着说**。
这解释了为什么它是**成簇**的而不是均匀的：一开口就停不下来。

（顺带印证：`dsh-ctxclean` 的文件头记录过一次严重的历史形状问题——每个请求曾
把 138 份"这是最新群聊"注入块一起发出去。历史越是被自己的话填满，
这种自我模仿越强。这条是猜想，本轮没有单独验证。）

---

## 四、为什么没有去重开自我重复闸门

最省事的做法是重开 `dsh-selfguard` 的自我重复闸门——但它：

1. **是用户明确关掉的**（`DSH_SELFGUARD_REPEAT=0`），用户不喜欢它那种
   「这茬刚聊完／已经聊过」的不耐烦话术；
2. **判据不可靠**：它的自我重复 = 与近 3 条比「公共子串 ≥ 4 字」或「共享 bigram」。
   第 2 轮离线回放 8987 条历史机器人消息（6577 条可比）出了 **168 次命中 = 2.55%**，
   多为误判 —— `公共子串≥4字` 分不清"内容真的重了"和"只是复用了常见短语"。

**所以换一个判据**：不看"两条像不像"，看**同一个短语在多条里反复出现**。
「大半夜的」出现在最近 5 条里的 4 条 —— 这种事没有误判空间。

---

## 五、改在哪：`dsh-aiflavour` 的新一层

选它是因为**机制已经现成**：按群计频的词根热度表 + 到阈值升级进剥除名单 +
连续 7 天没命中自动降级 + JSON 持久化。缺的只是"口癖"这一类词。

于是加第 4 层 **TIC（口癖）**，与 AI 腔词根共用同一套动学，但有一处关键区别：

| | 命中后 | 为什么 |
|---|---|---|
| AI 腔词根 | 剥；180s 内再中 → **整条拦** | "解释/总结"说教一而再再而三，整条不发是对的 |
| **口癖 TIC** | **只剥，不进会话刹车** | 口癖只是个赘词/语气垫，**整条拦是过重的惩罚** |

数据也支持这个区分：`大半夜的不睡觉 刷这些` 剥成 `不睡觉 刷这些` 是好结果；
但一小时内说了 8 次就把整条回复吞掉，会让机器人**该说话时突然哑掉**，那是更重的病。

### 剥除的三个边界情况（也是这次唯一需要改判据的地方）

原来的剥除是一行：

```python
re.sub(r"\s*" + pat + r"\s*[,，。；!！?？]?", "", cur)   # 只吃**右邻**标点
```

口癖落在句尾时会剥出**尾逗号**：`妈什么妈，大半夜的` → `妈什么妈，`。
真人不会发一条以逗号结尾的话 —— 那是把 "机器味" 换成了 "打错字味"。

新的 `_strip_all` 规则（三种情况都实测过）：

| 情况 | 例子 | 结果 |
|---|---|---|
| 右邻是分隔符 → 吃右邻 | `大半夜的，谁是你宝宝` | `谁是你宝宝` |
| 右邻是空白/没有（命中在句尾）→ 改吃**左邻**分隔符 | `妈什么妈，大半夜的` | `妈什么妈` |
| 右邻是正常文字 → 两侧都不动 | `活着呢，大半夜的测试呢` | `活着呢，测试呢` |

**第三条是关键**：如果不加这条限制，"左邻逗号"规则会把
`活着呢，大半夜的测试呢` 剥成 `活着呢测试呢`，把两个短句粘成一句。

**还有一个看起来是问题、其实不是的**：一开始担心 `大半夜的表白` 会剥成悬空的
`的表白`。**不会** —— 因为 `strip_strong` 把模式**按长度降序**排，
`大半夜的`（4 字）永远先于 `大半夜`（3 字）匹配，所以 `的` 一定跟着被吃掉。
而"把 `的` 留下、只去掉 `大半夜`"反而才是不合法的中文（`的表白`）。
**两种写法里，吃掉的 `的` 才是对的**，所以这个"边界情况"根本不存在。

## 六、验证

`plugins/dsh-aiflavour/test_tic.py`，数据全部来自**生产日志的真实文本**
（`/tmp/tic_cases.json`：21 条真发过的含"大半夜"的回复 + 5913 条不含它的普通回复）：

1. **21/21 全部剥干净**，且断言"结果里不含『大半夜』"、"结果首尾没有悬空标点/空白"；
   其中 1 条（原文只有 `大半夜的`）剥成空 → 走 `clear_result` 整条不发，**不会发空消息**。
2. **对照 5913 条普通回复，口癖层改动 0 条**。
   这里有个测试自身的设计要点：不能直接断言"输出 == 原文"，因为 `STRONG_BASE`
   里本来就有 `说白了`/`讲白了`，历史上真被剥过 2 条 —— 那是既有行为，不是这次的
   误伤。正确口径是**拿"开着口癖层"和"关掉口癖层"的同一份代码逐条比**。
3. **口癖连击 2 次 `brake=False`，AI 腔词根连击 2 次 `brake=True`** —— 证明"只剥不刹"
   生效，且原有的整条拦行为**没被改坏**。
4. **学习门槛还在**：第 1、2 次是观察，第 3 次才 `upgraded`。
5. **生产版代码回放**：把容器里 `/AstrBot/data/plugins/dsh-aiflavour` 整份拷出来
   跑同一套测试（测的是**部署出去的那份**，不是镜像）→ `TIC_TEST_OK`。

生产日志零污染（`Logger.add` 在 import 前置空，见 docs/73 第四节）。

## 七、两个"看着像问题、查了不是"的（本轮否掉的方向）

1. **真人连发 11.7% vs 机器人 2.6%（4.5 倍）** —— 一开始像是"节奏不像人"的硬证据
   （真人把一句话拆成三条短消息发）。但**口径不对等**：`dsh-merge` 会把群友的
   连续几条**合并成一个事件**再让机器人回一条，人的"连发"大部分已经在入口被并掉了。
   拿人的 3 条 vs 机器人的 1 条做除法没有意义。**不动。**
2. **`你是群主（QQ 2774067216），可以用：` 32 次 + `我这边和你的互动档位：陌生…`
   8 次** —— 是重复榜上仅次于已修项的两条，看着是"把自己的参数讲给群友听"的
   重度机器味。查触发条件：分别是 `/权限` 和 `/我和鱼` **两条命令的正常回答**。
   用户敲命令要的就是这些信息，**不是缺陷**。**不动。**

第 2 条是"先看触发条件再下结论"这条纪律救回来的 —— 只看输出、不看输入，
我会去改一段设计上正确的行为。

## 八、上线时的一个决定：把已知事实直接播进动态名单

机制是**学出来**的（同群累计 ≥3 次才开剥）。但上线后 `动态名单0个`，
意味着要等它自己再犯 3 次才开始治 —— 而它已经被实测过 21 次了。

所以把 `{"大半夜的": count=3, active, "大半夜": count=3, active}` 直接写进
`data/aiflavour_dyn.json`，让改动**立刻生效**：
- 学习门槛对**未知**词是保护（防止我刚判错就永久拉黑一个正常词）；
- 对这个词没有保护意义 —— 71 倍、一小时 8 次是已经量出来的事实；
- 自愈还在：连续 7 天没再命中会自动降级回观察。

重启后加载行 `动态名单2个` ✓。备份：`/opt/qqbot/backups/dsh-aiflavour-pre-口癖层-20260912-174724/`。
