# 64-联网出口审核：先审后发，防炸群

> `dsh-web` 抓到什么就往群里发什么。这份文档记录为什么「关键词正则」不够，以及怎么加一道
> **先审后发、失败即不发**的出口闸 —— 目标只有一个：**不让机器人自己把违禁内容贴进群**。

---

## 一、要解决的问题

机器人的联网功能有三条会**直接进群**的路径：

- `/看网页 <url>`、`/搜 <词>`、`/b站 <链接>` 的结果直接 `yield` 进群，**不经过 LLM**，也不经过
  `dsh-guard` 的判定；
- `on_llm_request` 钩子抓到的网页正文会被塞进上下文，模型可能原样复述；
- 模型自己调用的联网工具，返回的内容同样会进上下文。

原有的 `SENSITIVE_RE` 是一张**纯正则关键词表**，只能拦「命中关键词」的内容。而最危险的一类恰好
不命中：**维基百科那种通篇在讲一个敏感人物、但正文里未必出现词表里那几个词**的页面。正则漏一条
就炸一条 —— 一旦机器人在群里发了违禁内容，**群秒炸、号必封**。

## 二、方案：出口审核（先审后发，fail-closed）

新增 `_moderate(context, umo, content, url, timeout)`，三层：

| 层 | 内容 | 失败时 |
|---|---|---|
| 1. 正则快筛 | `_MOD_BLOCK_RE` 命中直接拦，省一次模型调用。词表刻意**不收**「核心」「领导」这类泛词（「团队的核心领导能力」会误伤），只收几乎必然踩线的完整词，并补了英文词（给维基/外媒摘要） | 直接不发 |
| 2. 小模型 JSON 判定 | `politics / sensitive_figure / nsfw / illegal / hate` 五个布尔 + `reason` + `can_send`。**任一布尔为 true 强制拦**，不依赖模型给的 `can_send` | 超时/异常/解析失败/无 provider → 一律不发 |
| 3. 结论缓存 | 确定性结论缓存 30 分钟（按 URL 或文本指纹）；**超时/异常不缓存**（下次可能就好了） | — |

prompt 只做**结构性描述**，不列举具体政治话题 —— 与 `dsh-guard` 同一套经验：列出来的词本身就是
渠道过滤的靶子。判定口径写「宁可误拦，不可漏放」，并明确列出放行类（游戏剧情里的国家/阵营、
纯历史科普、球队地名、技术文档、日常百科）。

> **为什么是 fail-closed**：这是要进群的内容。漏判一条就炸一条，宁可发一句「这个我不聊」，
> 也不能把可疑正文贴出来。这条与 `dsh-guard` 的禁言判定一致。

## 三、五条出口全覆盖

| 出口 | 路径 | 处理 |
|---|---|---|
| 链接自动注入 | `on_llm_request` → `_attach` | 正文先正则+小模型审；不过 → 换成拒答短话注入，**原文绝不进上下文** |
| 自动搜索注入 | `attach_search` | 先 `_drop_sensitive` 再整体送审 |
| LLM 工具 | `web_search` / `read_webpage` / `bilibili_video` | 审不过 → 返回「不予展示」指示，模型只能说不看 |
| 显式指令 | `/看网页` `/搜` `/b站` | 直接进群的高危路径，`yield` 前先审 |
| **回复出口闸** | `on_llm_response`（`strip_leaks`） | 回复**带网址才触发**送审，平时零开销 |

### 回复出口闸的降级策略（防审核卡住聊天）

| 情形 | 处理 |
|---|---|
| 确定拦截 | 整条换成拒答短话（「这个我不聊。」等，**不提「审核/安全」这类机制词**） |
| 没审成（超时/无模型） | 摘掉全部网址 + 正则复查正文；正文干净就发无网址版，脏才整条拦 |

网址识别用 `_REPLY_URL_RE`，比原来的 `URL_RE` 更宽：额外认**不带协议的裸域名**（`b23.tv` 也命中）
—— 贴网址不总是带 `http://` 前缀，这是防御纵深。

## 四、配置

全部有默认值，不配也能跑：

| env | 默认 | 说明 |
|---|---|---|
| `DSH_WEB_MOD` | `1` | 总开关 |
| `DSH_WEB_MOD_PROVIDER` | 空 | 空＝用当前会话模型；可指到便宜模型，不抢主对话额度 |
| `DSH_WEB_MOD_TIMEOUT` | `12` | 审核超时 |
| `DSH_WEB_MOD_RESPONSE_TIMEOUT` | `8` | 回复出口闸单独用更短的超时：模型话都说完了，不能让群友干等 |
| `DSH_WEB_MOD_TTL` | `1800` | 结论缓存秒数 |

## 五、验证

容器内 py3.12 跑 stub 单测 **19 项断言全过**：

- 正则命中 / 不误伤泛词；
- JSON 解析容错（```json 围栏、前后杂字、垃圾输入）；
- `politics=true` 强制拦（即使 `can_send=true`）；
- 超时 → fail-closed；
- 拿不到 provider → 拦；
- 总开关关闭 → 直通；
- 缓存命中生效、**超时结论不缓存**；
- 出口闸五种情形（确定拦 / 没审成+正文干净 / 没审成+正文脏 / 无网址零开销 / 正常放行）。

部署后：`astrbot` 容器重启日志里 `[web] 已加载：开关=True` 正常，群消息正常流动、无新增报错。

## 六、残留风险（明确写下来）

- **B 站路径只走正则闸**：高频低风险，为了控制成本没上模型。简介里若出现词表外的敏感内容可能漏。
- **回复闸只对「带网址的回复」触发**：模型复述敏感**文字**（无网址）时，靠上游的 content_filter 拒
  completion —— 表现为群里一行报错，不炸群但难看。
- **审核调用共享当前会话模型的额度与速率**：上游 429 高峰时审核超时，按 fail-closed 拦（宁可少说，
  不可说错）。
