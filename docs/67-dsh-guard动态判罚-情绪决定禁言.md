# dsh-guard 动态判罚：让情绪决定禁不禁

2026-09-12。dsh-guard 1.1.0 → **1.2.0**，已上线主群 100000001。

## 一、要解决的问题

原来的 dsh-guard 是一张固定表：判出类型和严重度 → 查表 → 警告/禁 300s/禁 600s。
问题是它**不看场合**：机器人刚被骂到炸毛，和它正跟人玩得开心，对同一句话的
反应完全一样。群里已经装了一堆状态插件（情绪、欲望、社交关系、逆反、疲劳），
用户要求：**让这些来决定要不要禁言**；同时明确划一条线 —— 「违法、刷屏等行为」
不属于态度问题，不受心情影响。

1.2.0 就是加一层「动态判罚层」：把上面的状态压成**一个宽容度数字**，
再让它去调判罚的档位、警告门槛和禁言时长。

## 二、核心设计：一个数字，不是一堆权重

```
宽容度 len ∈ [-3, +3]     正数 = 更宽容，负数 = 更严格
  = 情绪 + 欲望 + 关系 + 逆反 + 疲劳     （五次封顶，见下）
```

为什么是一个可加的数字，而不是「给每种情况配权重」：

* **可解释**。日志里一行就能交代清楚：
  `len=-1.2 angry3(指向我) [angry3·指向我] 来源=情绪、欲望、关系`，
  出问题能回查「这次为什么禁了他」。
* **可单测**。纯函数，不依赖框架：113 项断言覆盖五路来源、档位、边界、封顶。
* **可关**。`DSH_GUARD_MOOD=0` 整层失效，行为退回 1.1.0；不是把权重调零。

五路各自的贡献（都在 `mood_logic.py` 顶部常量表里）：

| 来源 | 强信号（能单独推动一档） | 弱信号（只改门槛） |
| --- | --- | --- |
| 情绪 | 强度 3 生气 −1.0；**指向机器人再 −0.2**（对号入座比泛泛而谈更严重） | 强度 1 −0.5、强度 2 −0.75 |
| 关系 | 「避让」−1.0；「亲近」+1.0（+ 高信任再 +0.3） | 「熟人」+0.5、「疏离」−0.5、低信任 −0.3 |
| 欲望 | ——（**刻意不给强信号**，见第四次校准） | 玩心/想搭话/想潜水/戒备/类痛觉，合计封顶 ±0.5 |
| 逆反 | —— | 高出基线 8~22 → −0.35；≥22 → −0.7 |
| 疲劳 | —— | 同一人追问同级话题 2 次 −0.35、3 次 −0.7 |

## 三、五条硬边界（写进代码，不是写在注释里）

1. **行为类不看心情**。`illegal`（违法）、`ad`（广告）、`nsfw`（色情索要）、
   `pileon`（围攻）以及**代码兜底**（诅咒家人、群体仇恨 → 直接抬到 sev3）走的是
   `classify()` 判定的硬类，`_mood_for()` 连状态都不读（集成测试断言
   `mood_read` 计数不增加）。刷屏闸、直接辱骂闸同理 —— 这两条路上「心情好也不打折」，
   刷屏那 1 天（86400s）刻意 `bypass_cap`，不被时长系数砍半。
2. **心情最多推一档**（`max_step=1`，可配到 2）。不会出现「生气就把 5 分钟变 1 小时」。
3. **心情只能把「放过」抬成「警告」，绝不能抬成「禁言」**。
   这条最关键：sev2 的判定依赖 24 小时内累犯记录，如果生气状态能把它推到
   sev3，就会**拿旧账去禁一句本来没事的话** —— 最不能接受的误禁方向。
   代码里由 `raised_only()` 强制：抬高出来的动作固定是 warn、门槛强制 ≥2。
4. **时长系数只有 ×0.5 ~ ×1.5**（斜率 0.15，满值约 ×0.55~×1.45），
   且最终仍受 `MAX_BAN_SEC=1800` 与时长下限 60s 约束。
5. **心情加重出的警告有同群冷却**（默认 300s）。生气时 borderline 消息会变多，
   不冷却就会一串「收着点」刷屏；冷却期内不警告、也**不记累犯**
   （不能出现「没警告过却因为累犯被禁」）。

## 四、四次校准（这层是拿生产数据反复打脸打出来的）

1. **阈值画在 ±1.5 太宽**。第一版「非常生气」只有 −1.0，够不到严格线，
   等于情绪白读了。改成一个强信号（生气 3 / 避让 / 亲近+高信任）就能推动一档的 ±1.0。
2. **分两档，让弱信号不白读**：严重度只在 |len|≥1.0 时动；警告门槛 |len|≥0.5 就动。
   弱信号表达成「多给一次机会」，而不是直接改变动不动手。
3. **集成测试揪出一个真 bug**：`mood_logic` 纯函数全绿，但插件里
   `severity_step()` 的结果被算出来又丢掉（元组解包把「规则严重度」和
   「心情严重度」接反了），只有警告门槛那一路真正生效。日志照打、
   单测照过 —— 只有把真实 `check()` 跑起来才现形。现已改名
   `sev` / `mood_sev` 并加注释。
4. **欲望封顶 1.0 会让整层退化成常数**。上线前拿生产状态实跑：
   机器人长期是「玩心 64 + 想搭话 100」（基线都是 16，connection 基本钉在上限），
   于是**对所有人**恒定 +1.0 —— 态度类严重度永久降一档，骂战从「警告」
   变成「放过」且不留记录。这不是动态，这是给整张表乘了个常数。
   改成封顶 ±0.5（**只够改门槛、不够改严重度**），并留下校准数据做注释。
   校准后生产实测：`len=+0.50 玩心64,想搭话100,类痛觉28 → 严重度不变，门槛 2→3`。

## 七、怎么看出它真的在工作

群主在群里发 `/禁言状态`，会多出这几行（照实际代码输出抄的）：

```
动态判罚：开｜读状态 12 次（失败 0）
  偏向：更宽容 7 次｜更严格 2 次｜加重出的警告 1（冷却挡下 1）｜心情带来的禁言 1 次
  只作用于态度类（骂战/时政），行为类与围攻、代码兜底一律不看心情；最多推一档，且只会把放过变成警告、不会变成禁言
最近几次心情：
  100000001：len=-1.2 angry3(指向我) [angry3·指向我] 来源=情绪、欲望、关系（类型=attack）
```

`读状态 N 次（失败 M）` 是这一层的健康指标：长期 `N=0` 说明态插件没装/路径不对，
`M` 一直涨说明状态读坏了（此时判罚退回固定规则，等于没上线，必须能看出来）。
判罚日志里每条都带 `｜len=... 因子` 尾巴，能直接回答「这次为什么判这么重」。

**群里不会出现任何解释心情机制的话** —— 态度变化只体现在判罚本身，
刻意没做「今天心情不好所以凶一点」这种台词（会破坏机器人在群里的形象）。

## 八、未做（有意识的取舍）

* 不写回状态插件。`dsh-desire` 的 `signal_events` / `bridge_cursor` 是它自己的
  自我感知桥，不是通用写接口；让 guard 往里塞事件会把两个插件的职责搅在一起。
  所有跨插件读取一律只读（`mode=ro`、timeout=1）且失败即中性。
* 疲劳用的是「同一人同话题追问次数」这个现成分级，是一个**刻意的粗代理**
  （真正的话题匹配要 import 另一个插件，代价大于收益），已在代码里注明。
* 不做语气变化。理由同上：禁言层只负责判罚，不负责表演情绪。
